# `_calculate_metrics_v1`、C 系列、单品与多品统一方案

> 审计日期：2026-09-01  
> 审计范围：`_calculate_metrics_v1`、`get_return_analysis_v1`、C3/C4/C5/C7、`backtest_training`、多产品预览/Word/导出，以及 `Task` / `TaskResult` / `TaskResultReturn` / `TaskLog`。  
> 本文是代码修改前的目标设计和验收依据，不代表本次已经修改了生产代码。

> **2026-09-02 决策修订：**
> 1. `metrics.py` 允许修改，但仅限字段输出重命名（`sortino_ratio`、`excess_sharpe`、`excess_sortino`、`excess_cumulative_return`、`excess_nav`），指标公式不动，回撤公式不动。
> 2. 新数据链路只输出新字段，不做旧字段双写；读取数据库历史载荷时通过 `historical_metrics.upgrade_historical_metrics` 兼容升级，相关入口均带 TODO，待历史数据迁移后删除。
> 3. 旧版累计收益直接加权（legacy_cumulative）已停用并注释保留，组合算法仅保留“日收益加权后复利”一种；多品任务配置主字段切换为 `weighting_mode`，前端开关已注释。
> 4. 暂缓项（保留入口、不接入）：`metric_registry` 全局展示消费、Word 日/月收益重复计算消除、P2 指标缓存与跨请求组合缓存。

## 1. 结论

**应该统一，但统一的对象不是“所有页面都返回同一种字段”，而是统一以下三件事：**

1. **统一指标计算入口**：所有双收益序列都只通过一个 V1 facade 调用 `_calculate_metrics_v1`。
2. **统一完整指标结果**：计算层返回完整、可序列化、有版本的 canonical metrics；C 系列的旧扁平字段只作为兼容投影。
3. **统一收益与组合口径**：单品原始收益、按比例后的单品收益、多品组合收益都使用同一套收益转换和指标计算规则。

仍然需要保留的差异只有“业务对象”差异：

- **单品原始指标**：一条产品/策略收益序列的指标。
- **比例后单品指标**：一条产品收益按自身比例缩放后重新计算的指标；它不是组合指标。
- **多品组合指标**：多条产品先按统一组合算法生成组合收益，再对组合收益计算指标。

因此不应继续用模糊的 `calculate_metrics`、`weighted_calculate_metrics` 混合表达这三种结果，而应明确命名为：

```text
product_metrics
weighted_product_metrics
portfolio_metrics
```

## 2. 当前真实链路

### 2.1 `_calculate_metrics_v1` 是完整计算层

定义：

- `app/services/performance_analysis/metrics.py:1113`
- 最终结果字典：`app/services/performance_analysis/metrics.py:1583-1736`

当前 V1 已包含大量新增指标，主要包括：

- 年度收益、年化收益、累计收益
- 年度/总区间最大回撤和回撤修复天数
- Sharpe、Sortino、Kama 等风险调整指标
- 3/6/12 月滚动收益
- 月度收益、月度波动率、偏度、峰度、盈亏统计
- 日度收益、日度波动率、偏度、峰度、盈亏比、收益分布
- 超额收益、超额分布、超额滚动收益
- 极端上涨/下跌行情统计
- 资金曲线、连续上涨/下跌、回撤频率等

这个层应该是所有下游的唯一公式来源。不要在 C 系列、回测训练、多品服务、Word 或导出器中重新实现同名指标。

### 2.3 `backtest_training` 单品目前走另一条入口

调用位置：

- `app/services/backtest_training_service.py:729-747`

当前关系：

```text
backtest_training 单品输入
  -> get_calculate_metrics_v1
  -> _calculate_metrics_v1
  -> 完整 metrics
  -> TaskResult.result["calculate_metrics"]
```

因此当前存在两个“单品”入口：

| 业务 | 当前入口 | 保存键 | 结果形态 |
|---|---|---|---|
| C3/C4/C5/C7 单品任务 | `get_return_analysis_v1` | `analyze_result` + `flat_result` | 完整结果与旧摘要并存 |
| `backtest_training` 单品 | `get_calculate_metrics_v1` | `calculate_metrics` | 更接近完整 V1 字典 |

这不是指标公式的合理差异，而是历史接口演进造成的适配分叉。应统一计算入口和 canonical 结果，保留旧键只为兼容历史读取。

### 2.4 V2 不是独立指标算法

`/xpl/v2` 是页面/输入协议名称，不是 `metrics_v2`：

- `templates/xpl/v2.html:1320-1329` 的 Google 来源走 `/xpl/v1/analyze`
- `templates/xpl/v2.html:1344-1359` 的粘贴来源走 `/xpl/analyze`
- 这些路径最终仍调用 `_calculate_metrics_v1` 或其适配器
- Word 明确调用 `get_calculate_metrics_v1_with_dataframes`：`app/services/strategy_backtest_report_service.py:35-45`

需要在文档和代码中把“V2 页面”和“V1 指标计算”区分开，避免误以为 V2 已经有另一套指标口径。

## 3. 当前新增指标到底丢在哪里

应区分三种情况，不能笼统说“多品没有新增指标”。

### 3.1 计算层

`_calculate_metrics_v1` 已计算并返回大量新增字段，前提是输入有效且计算没有异常。

当前有一个必须先修复的缺陷：

- `metrics.py:1577-1579` 读取 `index_df['return_range']` 和 `start_df['return_range']`
- 但这两列并没有在主收益 DataFrame 中创建
- `return_range` 实际只在 `calculate_distribution()` 生成的月度 DataFrame 中出现
- 宽泛异常处理会使非空输入最终返回空结果

因此应先修复日度分布来源，并补充非空 V1 全字段回归测试，否则后续“统一新增指标”没有可靠基础。

另外，`metrics.py:1185-1186` 计算了 `index_annual_rate_of_return`、`start_annual_rate_of_return`，但没有放入最终结果字典。应删除无效计算，或正式纳入 canonical 结果并补测试。

### 3.2 TaskResult / detail API

`backtest_training` 和多品原始 `TaskResult` 通常保存完整 V1 指标：

- `backtest_training_service.py:744-747`
- 多品每个产品的结果在 `backtest_multi_product_service.py:906-1028`

多品 detail 路由也能直接展开完整 `calculate_metrics`：

- `app/routes/backtest_multi_product.py:299-338`

所以新增指标不一定在存储层丢失。

### 3.3 页面预览、Excel 和 Word 展示层

#### C 系列旧摘要

`get_return_analysis_v1` 的 `flat_result` 只保留旧字段，新增字段不会自动进入旧接口。

#### 单品全局预览

`backtest_training_api_service.py:940-998` 的 fallback rows 是固定摘要，只展示有限字段；这不是 V1 没算，而是展示投影没有注册新增指标。

#### 多品全局预览

多品 `_derive_metrics`：

- `app/services/backtest_multi_product_service.py:646-682`

多品 `SUMMARY_ROW_DEFS`：

- `app/services/backtest_multi_product_service.py:39-60`
- 结果行生成：`app/services/backtest_multi_product_service.py:1370-1412`

目前只输出约 20 个摘要行。大量新增指标即使已经在 `portfolio_metrics` 中算出，也会在预览/Excel 投影阶段被过滤掉。

#### Word

Word 通过：

- `get_calculate_metrics_v1_with_dataframes`
- `MetricsV1ResponseDTO`
- `app/services/strategy_backtest_report_service.py:35-45`

能够取得完整 V1 结果和三张 DataFrame，但当前报告章节仍只显式使用一部分指标，且日/月收益在报告服务中重新派生。因此“Word 能计算到”不等于“Word 已展示全部新增指标”。

## 4. 统一目标模式

推荐建立一个统一 facade，例如：

```python
calculate_v1_metrics(
    returns,
    *,
    runtime_params=None,
    return_dataframes=False,
) -> MetricsV1Result
```

它内部唯一调用 `_calculate_metrics_v1`，并返回统一结果对象。

### 4.1 统一内部结果对象

保留当前报告层的 `MetricsV1ResponseDTO` 作为 DataFrame 运行时对象，但扩展或新增纯 JSON canonical DTO：

```python
@dataclass(frozen=True, slots=True)
class MetricsV1Result:
    schema_version: str
    metrics: dict[str, Any]
    index_df: pd.DataFrame
    start_df: pd.DataFrame
    excess_df: pd.DataFrame
    index_monthly_df: pd.DataFrame | None
    start_monthly_df: pd.DataFrame | None
    excess_monthly_df: pd.DataFrame | None
```

纯 JSON 投影至少要包含：

```json
{
  "schema_version": "metrics.v1",
  "period": {},
  "benchmark": {},
  "strategy": {},
  "relative": {},
  "distributions": {},
  "series_metadata": {}
}
```

建议内部 canonical 命名：

| 当前/历史名 | canonical 名 | 说明 |
|---|---|---|
| `index_*` | `benchmark.*` | index 实际是基准/指数 |
| `start_*` | `strategy.*` | start 实际是策略/模型 |
| `*_sotino_ratio` | `*_sortino_ratio` | 新结果只写正确拼写 |
| `excess_sharp` | `excess_sharpe` | 修正拼写 |
| `excess_of_promissory_note` | `excess_sortino` | 明确指标含义 |
| `*_annualized_rates` | `*_annualized_return_by_year` | 避免与单值混淆 |
| `monthly_excess_return_percentage_last_return` | `monthly_excess_win_rate` | 当前值实际是 all-period 胜率 |
| `index_return_dist` | `benchmark_daily_distribution` | 明确周期和对象 |
| `start_return_dist` | `strategy_daily_distribution` | 明确周期和对象 |
| `net_value` | `benchmark_nav` / `strategy_nav` | 明确对象 |
| `excess_net` | `excess_nav` | 本项目确认是超额净值 |

旧字段不应立即删除。建议：

- 新生成结果只写 canonical 字段。
- 读取历史结果时兼容旧字段。
- C 系列 StockParamResult 需要旧字段时，由统一 `LegacyMetricsAdapter` 从 canonical DTO 生成。
- 不再让每个 C 服务各自复制一套字段映射。

### 4.2 空值语义

不要把所有 `None`、NaN、无数据都转成 0：

- `result_mapper.py:84-90` 当前 `safe_value()` 会将缺失值转成 0
- 这会把“没有足够数据”误认为“指标真实为零”

canonical DTO 建议：

- 有效数值使用数字
- 不可计算使用 `null`
- 只有旧接口兼容投影时，才按历史约定转成 0

### 4.3 分布数据必须带 bucket

不要把 Pandas Series 直接 `tolist()` 后丢失索引。分布应转换为：

```json
[
  {"bucket": "<-5%", "count": 2, "percentage": 3.33},
  {"bucket": "-5%~-2%", "count": 4, "percentage": 6.67}
]
```

这样 Word、预览、CSV/XLSX 和前端都能复用同一份分布数据。

## 5. 单品、多品应该如何统一

### 5.1 单品统一

C 系列单品和 `backtest_training` 单品的输入适配可以不同：

- C3/C4/C5/C7 需要处理 Google Sheet 单元格、版本偏移、百分比单位和 K 线差异。
- `backtest_training` 需要处理回测训练结果区。

但进入指标层后必须统一成同一输入协议：

```python
[
  {
    "date": "2026-01-02",
    "index_return": 0.0123,
    "start_return": 0.0156
  }
]
```

其中两个 return 明确为累计收益率。

目标链路：

```text
C3/C4/C5/C7 输入适配器 ┐
backtest_training 输入适配器 ├─> canonical return series
历史/V2 输入适配器       ┘          ↓
                              calculate_v1_metrics
                                      ↓
                              MetricsV1Result
```

C 系列不应继续直接依赖一个只返回旧摘要的 `get_return_analysis_v1` 作为内部标准入口。可以保留该函数作为兼容 API，但其内部应改为：

```text
统一 facade
  -> 完整 canonical result
  -> LegacyMetricsAdapter
  -> (flat_result, analyze_result)
```

`backtest_training_service` 也应调用同一 facade，而不是单独调用 `get_calculate_metrics_v1`。

### 5.2 多品统一

多品要统一的是“每个产品进入组合前后的计算协议”，不是把多品结果伪装成单品结果。

三类结果必须显式区分：

```text
product_metrics
    每个产品原始累计收益序列的完整 V1 指标

weighted_product_metrics
    单个产品按自身比例缩放后重新复利得到的指标
    不能当作组合风险指标

portfolio_metrics
    所有产品先还原日收益、按比例合成、再复利得到组合累计收益后的完整 V1 指标
```

默认组合算法必须为：

```text
累计收益
  -> 单品每日收益率
  -> 每日按比例加权
  -> 每日组合收益求和
  -> 复利为组合累计收益
  -> 对组合收益调用统一 V1 facade
```

公共组合器应由预览、Word、Excel/XLSX、详情和缓存共同调用，例如：

```python
combine_product_returns(
    products,
    weights,
    weighting_mode="daily_compound",
)
```

支持显式的：

```text
daily_compound       默认
legacy_cumulative    仅历史任务显式开启时使用
```

Word payload 必须包含 `weighting_mode`，否则 legacy 多品的全局预览和 Word 可能不一致。

比例和日期规则也必须统一：

- `30` 和 `30%` 统一解释为 30%，`0.3` 也统一转换为 0.30；禁止混合单位产生歧义。
- 默认不因总比例小于 100% 而强制归一化，保留未投资现金语义。
- 组合只使用所有产品共同日期交集。
- 无共同日期时返回空组合并明确显示无数据。

## 6. Task、TaskResult、TaskResultReturn 与统一结果的关系

推荐保持现有存储职责：

```text
Task
 ├── config / status / progress
 ├── TaskLog                     运行日志
 └── TaskResult                  参数步骤或产品结果
       ├── canonical metrics      摘要/指标 JSON
       └── return_series_id ───┐
                              ↓
                       TaskResultReturn
                       原始累计收益序列
```

### `Task`

保存一次任务整体状态，不保存大收益数组。

### `TaskResult`

保存某个步骤、参数组合或产品的结果。目标是保存：

- `schema_version`
- canonical metrics JSON
- 结果元数据
- `return_series_id`

不建议继续同时写完整 `analyze_result`、完整 `calculate_metrics`、`flat_result` 三份重复结构。旧结构可在读取/迁移适配层兼容。

### `TaskResultReturn`

继续作为原始收益序列的主存储，保存累计收益：

```text
stock_date
index_return
start_return
```

不要把原始序列重新塞入 `TaskResult.result` 或 `TaskLog`。

当前 `TaskResultReturn` 没有数据库级 `task_result_id` 外键，只通过 `TaskResult.return_series_id` 关联。数据库关联增强可以放到后续 P2，先不要破坏历史数据。

### `TaskLog`

只保存运行日志。当前基类已经排除 `_return_date`、`return_date`、`returns_json` 等大字段，应该继续保持。

## 7. P0/P1/P2 修改边界

### P0：先保证正确性和统一入口

1. 修复 `_calculate_metrics_v1` 非空数据的 `return_range` 错误。
2. 统一新输出为 `sortino_ratio`，读取历史时兼容 `sotino_ratio`。
3. 按标准负值回撤统一指标内部、TaskResult、API 和导出层，展示时不再重复取负。
4. 统一多品默认 `daily_compound`，并抽取公共组合器。
5. Word payload 传递并消费 `weighting_mode`，保证预览与 Word 一致。
6. 明确 `excess_nav` 是超额净值：`1 + (strategy_cumulative_return - benchmark_cumulative_return)`。

### P1：统一服务和展示投影

1. 增加统一 V1 facade 和 canonical DTO。
2. C 系列和 `backtest_training` 都调用同一 facade。
3. `get_return_analysis_v1` 降级为 legacy adapter，不再是新的内部契约。
4. 多品明确区分 `product_metrics`、`weighted_product_metrics`、`portfolio_metrics`。
5. 预览、Word、Excel/XLSX 使用共享指标注册表，不再各自维护固定字段列表。
6. Word 直接消费 V1 DataFrame 和月/日派生结果，不再自行实现 `_daily_returns`、`_monthly_returns`。
7. 统一年度回撤优势公式和字段名。
8. 修复多品详情页面 weighted/portfolio 指标取值混淆。
9. 修复多品运行时图表把某个产品序列误标成组合序列的问题。
10. 删除或正式返回 `index_annual_rate_of_return`、`start_annual_rate_of_return`。

### P2：减少重复计算并增强跨请求复用

1. Word 单次请求建立 `ReportContext`，缓存 normalized returns、NAV、日/月收益、指标和图表数据。
2. 同一次报告中 V1 facade 和组合器各只执行一次。
3. 为 `TaskResultReturn` 增加 return-series hash/fingerprint，为指标增加 `metrics_version`。
4. 当收益序列指纹、指标版本、组合比例和 weighting mode 未变时复用指标。
5. 如需跨 worker/重启复用，再增加带完整 fingerprint 的组合结果缓存。
6. 最后再考虑 TaskResult 与 TaskResultReturn 的数据库级外键、索引和孤儿清理。

## 8. 必须补充的验收测试

### V1 完整结果

- 非空双收益输入不会因 `return_range` 错误返回 `{}`。
- 新增指标能在 canonical result 中找到。
- 无法计算的指标为 `null`，不是无条件变成 0。
- 分布结果保留 bucket 标签。

### 单品统一

- C3/C4/C5/C7 和 `backtest_training` 对相同 canonical return series 得到相同 V1 核心指标。
- C 系列旧接口仍返回兼容的 flat 字段。
- `TaskResult.result` 不包含大收益数组，`TaskResultReturn` 能完整恢复序列。

### 多品统一

- `product_metrics`、`weighted_product_metrics`、`portfolio_metrics` 三者来源和名称不同。
- 默认组合使用“累计收益转日收益 -> 比例加权 -> 复利累计”。
- 比例总和小于 100% 时不被自动归一化。
- 共同日期交集规则一致。
- legacy 模式只有显式开启时使用。

### 预览与 Word

- 相同产品、比例、日期和 weighting mode 下，全局预览组合收益与 Word 组合收益一致。
- daily_compound 和 legacy_cumulative 均有一致性测试。
- Word 同一次请求只运行一次完整 V1 计算和一次组合器。
- Word 使用 `excess_nav`，不误标为 `relative_nav`。

### 兼容字段

- 新数据只生成 `sortino_ratio`。
- 历史 `sotino_ratio` 能读取。
