## 1. 背景与现状分析

### 1.1 随机价任务的数据形态

- C1.1 / C7.0.3 支持 `price_mode=random_price`：执行时按
  `random_group_count` 展开组合（`base._expand_random_price_groups`），
  每个组合的 `kline_key = "{窗口}:random-{N}"`，并带 `random_group` 字段。
- 随机行结构（`KlineService.build_price_rows`，include_ohlc=True）：
  `stock_val` = 随机价（uniform 在 high/low 或 open/close 区间，task_id 播种
  确定性可复现），**open/high/low/close/vwap 仍是真实价**。随机价写入 Sheet
  的 ext 列。
- 执行侧去重不受随机组影响：C1.1/C7 均重写 `_dedupe_extra_signature`
  （`c1_1.py` / `c7.py`），把 `random_group + kline_key` 拼进签名，N 个随机组
  都会真实执行，**不存在"参数相同被去重掉"的问题**。
- 每条 `TaskResult.parameters` 落库的是整个组合 dict：A1/B1、kline_key、
  random_group 全都在，**存量数据无需回填**。

### 1.2 全局预览现状（为什么看起来像被去重）

- 链路：`backtest_report_query_service._build_global_preview_initial_payload`
  （首屏分组索引）→ `/preview-group` 按 result_ids 取
  `_build_global_preview_payload_from_results`（每条结果一列，**本身不去重**）。
- 问题 1：首屏年份分组 key = 整个 `kline_key`（含 `:random-N`），200 个随机组
  变成 200 个年份分组，下拉爆炸。
- 问题 2：列头 `_build_parameter_header` 只认 `parameter` 列表 / A1 / xm。
  C1.1 无参数（组合里 A1/B1 被 pop），每列都落到"未命名参数"；C7 的 200 组
  参数相同则 200 列表头完全一样，无法区分是哪个随机组。
- 问题 3（既有登记缺口）：`_build_global_preview_payload` 的类型白名单没有
  `google_sheet_c1_1`，C1.1 走导出报"任务不存在"。

### 1.3 指数侧与超额的口径（已核实）

- 指数侧指标来自 `calculate_index_returns_from_closes(kline)`
  （`base.py:100`，C7.0.3/C1.1 共用）：**用真实收盘价（close 列）相对首日
  累计**。随机价只作用于策略侧（ext → start_return），所以同窗口所有随机组
  的 `index_*` 指标逐项相同（已在测试库实测确认）。
- 用户确认的口径：成对列里的"指数"就用真实K线算（现状即是），**不需要改**。
- 曾讨论过"超额基准改用随机价（stock_val/ext）累计"的方案（见 §3.4），已
  回退，实施与否需产品再确认。

## 2. 需求（用户已确认）

1. 年份分组只按窗口（`2026-2018`），不再按 `窗口:random-N` 拆分。
2. 组内全部随机组一次性铺开成列。
3. 每个随机组一对列：**指数 | 结果**（指数列 = 真实K线基准，同窗口内取值
   相同，为对照阅读重复展示）。
4. 不保留旧布局左侧的总览"指数"列（与成对列里的指数重复）。

## 3. 实现方案（四块，均已验证可跑通）

### 3.1 后端分组与列（`app/services/backtest_report_query_service.py`）

- `_build_global_preview_payload_from_results`：
  - `is_random_group = bool(parameters.get("random_group"))`；
    `year_key = kline_key.split(":random-")[0]`（随机组才切，非随机不动）。
  - group dict 增加 `"random_price": False`，命中随机组时置 True；
    序列化时输出 `"random_price"`。
  - column dict 增加 `"random_group": parameters.get("random_group")`。
- `_build_global_preview_initial_payload`：year 模式分组 key 同样按窗口切。
- **白名单**：`_build_global_preview_payload` 的类型集合加
  `"google_sheet_c1_1"`（同时修复 §1.2 问题 3）。
- 列头：`_build_parameter_header` 末尾对 `parameters.get("random_group")`
  追加 `（{kline_key}）`；C1.1 无参数时 kline_key 兜底当主标识。

### 3.2 前端（`static/js/pages/global_preview_index.js` renderTable）

`group.random_price` 时走成对渲染：

- 表头两行：第一行每列 `colspan=2`（组名 + 结果 ID 小字），第二行固定
  `指数|结果`；左侧"指标类型/指标"用 `rowspan=2`；**没有第三列**。
- 数据行：每列输出 `row.index_value`（指数）+ `row.values[column_key]`（结果）。

### 3.3 Excel（同文件 `_build_global_preview_workbook` 单品分支）

- `is_random_price = bool(group.get("random_price"))` 走成对写法：
  row_1 每列两格 `[header, ""]` 并逐对 `merge_cells(1, 3+2i, 1, 4+2i)`；
  row_2 固定 `指数|结果`；数据行 `[index_value, value]` 成对。
- **坑**：函数结尾原有的 `merge_cells(start_row=1, start_column=1, end_column=3)`
  是给旧布局前三列的，随机分支必须收窄成 `end_column=2`，否则会把 C1 表头
  吞进合并区（MergedCell.value 变 None，测试抓到过）。
- 测试断言写法：openpyxl 对合并区非锚点格返回 MergedCell（value=None），
  断言要打在锚点格上。

### 3.4 执行侧超额基准（可选，需产品确认，已回退未保留）

- 现状：超额 = 真实指数 vs 策略 start_return。
- 备选方案：随机组用随机价（`stock_val`，即 ext 列）累计作基准，与策略侧
  同源（随机市场的"买入持有" vs 策略）。
- 改法（已验证可编译可跑）：`calculate_index_returns_from_closes` 加
  `value_field="close"` 参数；C1.1（必为随机）固定传 `"stock_val"`；
  C7.0.3 在 `_execute_parameter_combination` 按 `combination.get("random_group")`
  条件传。**影响新跑任务的结果口径，存量结果不回填**——上线前必须确认口径。
