> 范围：`app/` 生产代码中的模块级静态常量（业务事实表、枚举、映射、样式、种子数据）。
> 方法：脚本提取全部模块级 `UPPER_CASE` 定义（264 处，含 tests/scripts），统计跨文件真实引用数
> （排除定义行），叠加人工读码分类。`tests/archive`、`tests/scripts`、`ding_stream_service`
> 为独立域，不在本报告收编范围。

## 0. 结论速览

- 全仓模块级常量约 264 处，其中 `app/` 生产代码约 130 处。绝大多数是**单模块私有、单源声明**，
  属合理写法，不动。
- 真正的问题是**同一业务事实被多个模块各自硬编码**，本次已将最严重的一类（C 系模板单元格语义，
  散落 4 处、三套键名）收敛至新常量包 `app/constants/`，详见 §1。
- 审计判定：**5 个死常量**（§3）、**3 组重复/双轨**（§4）、**7 项历史遗留风险**（§5）。
- 全量回归 25 个失败经 HEAD 干净树对比确认**全部为存量失败**（在途重构/网络抖动），收敛改动 0 新增。

## 1. 本次已完成的收敛：app/constants/c_template_layout.py

### 1.1 问题原状

"C5/C7 模板 D2~D20 格 = 哪个指标"这一事实曾写在 4 个文件、三套键名：

| 文件 | 常量 | 键名风格 |
|---|---|---|
| `google_sheet_tasks/result_payload.py` | `STOCK_PARAM_METRIC_SPECS` | 出库键（maxdd / index_rate / max_index_dd） |
| `model_summary/extractor.py` | `C3_METRIC_CELLS` / `C4_C5_METRIC_CELLS` | 概念键（max_drawdown / index_return） |
| `backtest_report_query_service.py` | `SUMMARY_METRIC_CELL_MAP` | 报表键（return / index_return） |
| `export_workbook_service.py` | `C3_PARAM_CELL_MAP`、`C5_EXPORT_METRIC_KEYS`、内联 I16/I17… 字面量 | 导出键（maxdd / year_rate） |

另外 `utils/c7_result_normalizer.py` 的 C7 平移布局百分数单元格、`backtest_parameter_utils.py`
的参数行顺序契约，也与上述文件存在隐含耦合。改模板单元格需要同步 4~6 处，漏一处即静默错位，
且 `maxdd` vs `max_drawdown` 的键名漂移已经实际发生。

### 1.2 收敛设计

单一规格表 + 派生视图，**逐值等价于历史常量**（不改任何键名、不改任何行为）：

- 规范词汇 = extractor 概念键（`return_rate` / `max_drawdown` / …），一个概念一行单元格事实；
- `C3_PARAM_SLOTS`：8 参数槽位（单元格 B5~B12、契约字段名、导出列名、展示标签）四 vocabulary 合一，
  由此派生 `C3_PARAMETER_KEYS` / `C3_PARAMETER_FIELDS` / `C3_PARAM_CELL_MAP` / `C3_PARAM_NAMES`；
- `C7_ROW_SHIFT = 6`：C7.0.2 结果区 = C4/C5 布局整体下移 6 行，`c7_shifted_cell()` 派生全部 C7 视图
  （`SUMMARY_METRIC_CELL_MAP["C7"]`、`C7_RAW_PERCENT_CELLS`、`C7_PERCENT_LEVERAGE_CELLS`）；
- 报表键别名（`return_rate`→`return`）显式登记在 `_REPORT_SUMMARY_ALIASES`，不再靠注释口口相传；
- 原两处同名异义的 `SUMMARY_ROW_LABELS` 之一更名为 `SINGLE_PRODUCT_SUMMARY_ROW_LABELS`
  （6 行单品摘要），消除与 `summary_contract.SUMMARY_ROW_LABELS`（20 项契约）的撞名。

消费方改造：`extractor` / `export_workbook_service` / `backtest_report_query_service` /
`backtest_parameter_utils` / `c7_result_normalizer` / `routes/backtest_api` 删除本地定义改为 import；
三处内联 I 列字面量（report_query `_build_c3_summary_rows`、export_workbook `c3_result_row` /
`_return_beats_value`）改为查 `C3_METRIC_CELLS`。

### 1.3 边界（刻意不收编）

- `result_payload.STOCK_PARAM_METRIC_SPECS` 保持原样：AGENTS.md 指定其为透传规格表，且出库键
  已持久化在 `TaskResult.result`，属对外契约。其 D2~D20 与常量包的重复在 §4 登记，不做机械合并。
- `summary_contract.py`（20 项汇总行契约）保持原样：前后端共享契约的单一来源，行序即展示序。
- 常量包纪律：纯数据、零逻辑（派生推导除外）、零 IO、零 Flask 依赖；任何层可 import；
  禁止反向依赖业务模块。单模块私有常量不进包。

### 1.4 顺带修复的真实缺陷

`backtest_report_query_service.py` 使用 `re.fullmatch`（`_extract_display_year`）却**漏写
`import re`**——C3 摘要行构建（`build_c3_summary_rows`）一旦走到年份区间解析即抛 `NameError`。
本次补上。这也是"静态内容散落"审计过程中顺带发现的存量 bug。

### 1.5 验证

- 派生值与历史字面量**逐值断言等价**（含 `SUMMARY_METRIC_CELL_MAP` 四键、C5 导出键序列、
  C7 平移单元格集合、参数槽位四表）；
- 触达模块全部可导入；
- `python -m pytest tests/unit tests/integration`：25 失败 / 609 通过；与 HEAD 干净树（git worktree）
  同套件对比，**工作区独有失败 = 0**，25 个失败全部为存量。

## 4. 重复/过度（建议合并，非必须）

### 4.1 并发上限双轨（建议优先处理）

- `runtime.py:447` 读 SystemConfig `max_concurrent_tasks`（种子默认 20，管理端可见可调）；
- `facade.py` + `registry.py` 读 `task_max_workers`（`GLOBAL_MAX_KEY`，默认 8，**未播种**，
  管理端配置页看不到该键）。

两把旋钮同时约束全局并发、默认值不一致（20 vs 8）、一个在管理端可见一个不可见，实际生效值
难以推断。建议二选一：要么播种 `task_max_workers` 让管理端可见，要么废弃其一。

### 4.2 MIME 常量双定义

`EXCEL_MIMETYPE` / `ZIP_MIMETYPE` 在 `export_service.py` 与 `export_workbook_service.py` 各定义
一份。小事，合并到其一即可。

### 4.3 代码默认值与 DB 种子双源（可接受模式，需同步纪律）

- `base.py DEFAULT_EXECUTION_DELAY_MIN/MAX`（20/30）↔ SystemConfig 种子 `execution_delay_min/max`（20/30）；
- `registry.GLOBAL_MAX_DEFAULT`（8）↔ 无对应种子（即 §4.1 问题）。

"代码默认值 + DB 运行时可调"本身是合理分层，但两处数字需人工保持一致，改动时必须成对检查。

### 4.4 任务类型展示名两套

`extractor.TASK_TYPE_LABELS`（"C3"/"回测"）与 `models.TaskType.choices()`（"Google Sheet C3"/"单品回测"）
是同一事实的两套展示名，消费场景不同（CSV 导出 vs 管理端下拉）。可接受，但改名时两处都要动。

### 4.5 已登记的可接受重复

- `result_payload.STOCK_PARAM_METRIC_SPECS` 的 D2~D20 ↔ 常量包（§1.3，AGENTS 指定不并）；
- `PROJECT_ROOT` 在 12 个文件各自 `Path(__file__)…`——Python 样板，不值得抽象；
- 报表词汇别名（`return` vs `return_rate`、`year_rate` vs `turnover_rate`）——业务词汇的历史
  分歧，已显式登记在常量包别名表，比散落注释强。

## 5. 历史遗留（风险登记）

### 5.1 任务类型大小写疣（建议择机归一）

DB 与 `TaskType` 枚举值为**大写后缀**（`google_sheet_C4`/`google_sheet_C5`/`google_sheet_C7`），
而 `TASK_TYPE_REGISTRY` 键、`normalize_task_type` 返回值为小写，`extractor.SUPPORTED_TASK_TYPES`
又用大写。全靠边界处 `.lower()` / `normalize_task_type` 兜底，新增比较点极易踩坑。
建议：统一以 `normalize_task_type` 为唯一归一口，`SUPPORTED_TASK_TYPES` / `TASK_TYPE_LABELS`
的键改从枚举值派生（改值不改语义需回归 `model_summary` 相关用例）。

### 5.2 枚举与裸字面量并存

`TaskType` 枚举已存在，但 `creation.py`、`export_workbook_service.py`、`runtime.py`、
`schemas/task.py`、`backtest_report_query_service.py` 等 20+ 处仍写 `"google_sheet*"` 裸字面量。
因 §5.1 大小写不一致，**机械替换为 `TaskType.X.value` 反而会引入 bug**（枚举值大写、比较侧小写），
须先做 §5.1 归一。

### 5.3 两个"任务超时"并存

- Flask 配置 `TASK_TIMEOUT`（env 注入，默认 3600 秒）；
- SystemConfig `task_timeout`（种子 36000 秒）。

同名异义异值，消费方不同。建议至少在描述中互相注明，长期合并为一个来源。

### 5.4 config.py 混装三类内容

`app/config.py` 同时承载：Flask 静态配置镜像（env → 类属性）、SystemConfig 默认种子
（约 280 行 `default_configs`，含大量 C 系模板运营参数）、RBAC/SSO 种子（`PERMISSIONS`、
`SSO_ROLE`）。三类生命周期不同（进程启动 / 首次建库 / 手动 init-rbac），建议拆分为
`config.py` + `app/seeds/`（或等价结构），降低"改种子误触配置"的_review 风险。

### 5.5 模板参数格双源（代码 ↔ DB 配置）

参数输入格同时存在于：常量包 `C3_PARAM_SLOTS`（B5~B12，代码消费）与 SystemConfig 种子
`c3_parameter_positions` / `C3_commission_cell`（运营可调）。本次审计确认两者一致
（B5=commission、B6=xm、B7=dbbh1/tp1、B8=dbbh2、B9=zlxc/nl、B10=zsgz/if、B11=ywf1/ywfs、
B12=ywf2/ywb），但无机制保证未来同步。改模板时必须两处一起改。

### 5.6 前后端跨栈镜像（后端收敛不解决，需前端同步批次）

| 契约 | 后端 | 前端 |
|---|---|---|

## 6. 判定合理、明确不动

- **任务域协议前缀**：`task_error_utils` 的 `NETWORK_ERROR_PREFIX`（`[NETWORK_RETRYABLE]`）、
  `WATCHDOG_RESTART_PREFIX` 与看门狗 `REASON_*`——跨进程协议，AGENTS.md 红线要求独立于
  HTTP 语义体系，已在各自文件单源；
- **市场域**：`utils/market.py` 8 个常量即市场知识集中地（正面范本）；
- **K线域**：`kline_service.DATA_SOURCE_*`、`KLINE_PRICE_FIELD_BY_MODE`（注释即契约：
  "整个项目只允许这一份映射"）；
- **wire 字段**（`stock_open`↔`open`）：翻译仅存在于 `KlineService.read/write_internal_kline_data`
  两侧 + `stock_sdk` 模型，符合 AGENTS 约定；
- **charts 配色/字体、`WORD_STYLE`**：渲染实现细节，改它的场景只有改渲染本身；
- **`extractor.SUMMARY_COLUMNS` 两段式组合**（首段 + 追加 `RETURN_ANALYSIS_COLUMNS`）：刻意写法，
  非重复定义；
- **auth.py 常量**（`DEFAULT_JWT_SECRET` 有启动期 fail-fast 校验守护、`ACCESS_TOKEN_COOKIE`
  带项目前缀防跨服务 cookie 污染）：语义自洽。
