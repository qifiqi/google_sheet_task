# Admin Web UI 视觉与交互规范

本文档是 Vue 3 + Element Plus 2.10+ 管理后台的设计基准。后续新增或调整 admin web 页面时，默认依赖本规范，不再按单页临时发挥。

参考设计图：

- `docs/design/admin-web-style-proposals/option-a-clean-blue.png`

## 1. 设计目标

| 项目 | 规范 |
| --- | --- |
| 产品定位 | Google Sheet 参数批量校验、任务执行、资源占用、日志监控后台 |
| 视觉关键词 | 清爽、克制、可信、数据密集、低干扰 |
| 技术基准 | Vue 3、TypeScript、Element Plus 2.10+、Vue Router |
| 页面基调 | 浅色后台，左侧固定侧边栏，顶部工具栏，内容区卡片化 |
| 优先级 | 信息可读性 > 操作效率 > 视觉装饰 |

禁止把后台做成营销落地页、深色监控台、强装饰插画页或大面积渐变页。

默认主题保持浅色。允许用户从顶部栏主动切换暗色主题，但暗色主题必须保持相同的信息层级、密度和克制风格，不能改造成另一套高饱和监控台视觉。

## 2. 全局设计原则

| 原则 | 要求 |
| --- | --- |
| 数据优先 | 首屏展示任务状态、运行任务、Token 占用、日志、最近任务等核心信息 |
| 密度适中 | 参考图 A 的卡片间距和表格行高，避免过松或过度堆叠 |
| 统一组件 | 按 Element Plus 组件语义使用，不手写重复控件 |
| 状态明确 | 成功、运行、失败、警告、空闲必须用一致颜色和标签 |
| 低干扰动效 | 只允许 150-300ms 的 hover、展开、加载过渡 |
| 可维护 | 样式通过全局 token 和局部 BEM/语义 class 管理，不在页面里散落魔法值 |

| 危险 | `--admin-danger` | `#EF4444` | 失败任务、异常日志、删除操作 |

| 常规文本 | `--admin-text-regular` | `#334155` |

| 滚动条拖动 | `--admin-scrollbar-thumb-active` | `#5B8DEF` |

### 3.3 使用规则

- 页面背景使用 `#F8FAFC`，卡片和表格容器使用白色。
- 主色只用于“当前、主操作、链接、关键数据强调”，不要整页大面积铺蓝。
- 危险色仅用于失败、异常、删除，不用于普通提示。
- 图表最多同时出现蓝、绿、黄、红四类状态色，避免彩虹化。

### 3.4 暗色主题

| 用途 | Token | 暗色色值 |
| --- | --- | --- |
| 页面背景 | `--admin-bg` | `#14161A` |
| 面板背景 | `--admin-surface` | `#1C1F24` |
| 侧栏背景 | `--admin-sidebar-bg` | `#191C21` |
| 主文本 | `--admin-text` | `#F3F4F6` |
| 常规文本 | `--admin-text-regular` | `#D1D5DB` |
| 次级文本 | `--admin-text-muted` | `#9CA3AF` |
| 边框 | `--admin-border` | `#30343B` |

- 暗色切换只能通过全局 token 实现，禁止在单个页面或表格内维护第二套颜色。
- 必须同步覆盖 Element Plus 的 `--el-color-*-light-8`、`light-9`、`dark-2` 语义色阶，保证 `ElTag`、`ElAlert`、`ElProgress` 等组件随主题切换。
- 暗色状态标签使用深色语义底、同色系描边和亮色文字，不得保留浅色主题的白底。
- 新组件只引用 `--admin-*` 或 `--el-*` token，不在局部样式中判断主题。

## 4. 字体与排版

| 层级 | 字号 | 字重 | 行高 | 使用场景 |
| --- | --- | --- | --- | --- |
| 页面标题 | 20px | 600 | 28px | 顶部当前页面名 |
| 区块标题 | 16px | 600 | 24px | 卡片标题、表格标题 |
| KPI 数字 | 28px | 600 | 36px | 指标卡主数值 |
| 正文 | 14px | 400 | 22px | 表格、描述、表单 |
| 辅助文字 | 13px | 400 | 20px | 卡片副标题、时间、说明 |
| 标签文字 | 12px | 500 | 18px | 状态标签、徽标 |

字体栈：

```css
font-family: "Plus Jakarta Sans", "Inter", "Segoe UI", "PingFang SC",
  "Microsoft YaHei", Arial, sans-serif;
```

不按视口宽度动态缩放字体；后台界面不使用负字距。

## 5. 整体布局

### 5.1 框架尺寸

| 区域 | 桌面规范 |
| --- | --- |
| 侧边栏宽度 | 展开 `240px`，折叠 `64px` |
| 顶部栏高度 | `56px` |
| 标签栏高度 | `40px`，没有多页标签时可隐藏 |
| 内容区内边距 | `24px` |
| 卡片间距 | `16px` |
| 卡片圆角 | `8px` |
| 卡片边框 | `1px solid #E2E8F0` |
| 卡片阴影 | 默认不使用重阴影，可用极轻阴影 `0 1px 2px rgba(15, 23, 42, 0.04)` |

### 5.2 页面结构

```text
AdminLayout
├─ AdminSidebar    240px / 64px
├─ MainShell
│  ├─ AdminTopbar  56px
│  ├─ TabBar       40px
│  └─ PageContent  padding 24px
```

### 5.3 内容网格

| 场景 | 规范 |
| --- | --- |
| 桌面大屏 `>= 1440px` | 使用 12 栅格，核心表格 8 栅格，右侧状态面板 4 栅格 |
| 中屏 `1024-1439px` | KPI 保持 2-4 列，表格和日志上下排列 |
| 平板 `768-1023px` | 侧栏可折叠，内容 1-2 列 |
| 移动 `<768px` | 侧栏抽屉化，卡片单列，表格横向滚动 |

### 5.4 滚动条

| 项目 | 规范 |
| --- | --- |
| 优先组件 | 页面壳、侧边栏、抽屉和长列表优先使用 `ElScrollbar` |
| 宽度 | 垂直与水平滚动条均为 `8px`，实际可见滑块约 `4-6px` |
| 轨道 | 默认透明，不增加额外边框或厚重底色 |
| 默认滑块 | 浅色 `#DBE7F8`，暗色 `#3B4657` |
| hover | 浅色 `#93B4E8`，暗色 `#536987` |
| 拖动 | 使用主题主蓝，浅色 `#5B8DEF`，暗色 `#60A5FA` |
| 圆角 | `8px`，不使用方形滑块 |
| 最小长度 | 滚动条滑块最小 `36px`，避免难以拖动 |

- `ElScrollbar` 的 `.el-scrollbar__thumb` 必须读取全局滚动条 token，不允许页面局部定义颜色。
- 页面主内容区、侧边栏使用 `always` 与 `:min-size="36"`，保证滚动位置持续可见且便于拖动。
- 表格、弹窗等内部原生滚动容器使用相同 token 作为 fallback。
- 标签栏允许隐藏滚动条但必须保留横向滚动能力；其他长内容区域不应隐藏滚动条。
- 不使用永久高亮的纯蓝滚动条，只有 hover 和拖动时提高对比度。

不要在卡片里面再嵌套一层视觉卡片。需要分组时使用标题、分割线或表格分组。

## 6. 侧边栏规范

| 元素 | 规范 |
| --- | --- |
| Logo 区 | 高度 `56px`，左侧 24px 图标，右侧产品名 |
| 菜单图标 | Element Plus Icons，尺寸 `18px` |
| 图标语义 | 按导航 `key` 集中映射功能图标，父级模块与直属功能项不得使用同一图标 |
| 菜单项高度 | `44px` |
| 菜单项圆角 | `6px` |
| 菜单左右间距 | `12px` |
| 当前菜单 | 蓝色文字 + `#EFF6FF` 背景 + 左侧可选 3px 蓝色指示 |
| 普通菜单 | `#334155`，hover 背景 `#F8FAFC` |
| 分组展开 | 使用 Element Plus 子菜单箭头，禁止自定义复杂动画 |
| 展开规则 | 同一层级只展开一个分组，当前页面所属分组自动保持展开 |
| 底部用户区 | 显示角色/用户，固定在底部；折叠时只显示头像/图标 |

菜单来源必须继续依赖当前鉴权与 `/api/meta/nav` 返回结果，不在前端硬编码权限菜单。

## 7. 顶部栏与标签栏

### 7.1 顶部栏

| 元素 | 规范 |
| --- | --- |
| 左侧 | 折叠菜单按钮、当前页面标题或面包屑 |
| 中间 | 默认留白，不放营销文案 |
| 右侧 | 搜索、刷新、全屏、主题、用户下拉、退出；不放九宫格、通知、设置入口 |
| 高度 | `56px` |
| 分隔 | 底部 `1px solid #E2E8F0` |

图标按钮使用 `ElButton text` 或圆形轻量按钮，尺寸 `32px`。

### 7.2 标签栏

| 状态 | 规范 |
| --- | --- |
| 当前标签 | 蓝色文字、浅蓝背景、可关闭图标 |
| 普通标签 | 灰色文字、白色背景 |
| 高度 | `40px` |
| 超出 | 横向滚动，不换行 |

## 8. 卡片规范

| 类型 | 尺寸与内容 |
| --- | --- |
| KPI 卡片 | 高度 `120-140px`，标题、主数值、趋势、小图表/图标 |
| 图表卡片 | 最小高度 `280px`，标题区 + 图表区 |
| 表格卡片 | 标题区 + 操作区 + 表格 + 分页 |
| 日志卡片 | 标题区 + 筛选区 + 日志列表 |

卡片结构：

```text
Card
├─ Header: 标题 / 次级操作
├─ Body: 数据内容
└─ Footer: 分页 / 查看全部 / 次级说明，可选
```

卡片标题 16px/600；卡片正文 14px。卡片内边距默认 `20px`，表格卡片可缩小为 `16px 20px`。

## 9. 表格规范

### 9.1 基础样式

| 项 | 规范 |
| --- | --- |
| 组件 | `ElTable` |
| 表头高度 | `44px` |
| 表格行高 | `48px` |
| 字号 | `14px` |
| 表头背景 | `#F8FAFC` |
| 表头文字 | `#334155`，字重 600 |
| 单元格边框 | `#EEF2F7` |
| hover 行 | `#F8FAFC` |
| 空状态 | 使用 `ElEmpty`，文案不超过 12 字 |

### 9.2 列设计

| 列类型 | 规范 |
| --- | --- |
| ID / 编号 | 等宽字体或普通 13px，允许蓝色链接 |
| 名称 | 左对齐，单行省略，hover tooltip 显示完整值 |
| 状态 | 使用 `ElTag`，颜色遵循状态规范 |
| 进度 | `ElProgress` line，宽度 `90-120px` |
| 时间 | `YYYY-MM-DD HH:mm:ss`，次要时间可用 `HH:mm:ss` |
| 回测数值 | 正值使用成功绿 `--admin-success`，负值使用危险红 `--admin-danger`，零值与非数值使用常规文本色 |
| 操作 | 放在最右侧，优先文字按钮，最多 3 个直接展示 |

- 回测数值通过统一的 `is-positive` / `is-negative` 类着色，禁止在单元格内使用内联样式。
- 正负色仅辅助快速扫描，列名、数值符号和百分号必须完整保留，不能只依赖颜色表达含义。

### 9.3 操作列

| 操作级别 | 按钮形式 |
| --- | --- |
| 查看 / 详情 | `ElButton link type="primary"` |
| 编辑 / 重试 | `ElButton link type="primary"` |
| 取消 / 停止 | `ElButton link type="warning"` |
| 删除 | `ElButton link type="danger"`，必须二次确认 |
| 更多 | `ElDropdown` |

操作列不要使用大面积实心按钮，避免表格视觉噪声。

### 9.4 分页

| 项 | 规范 |
| --- | --- |
| 组件 | `ElPagination` |
| 位置 | 表格底部右侧 |
| 默认页大小 | `10` 或 `20` |
| 展示 | `total, sizes, prev, pager, next, jumper` |

### 9.5 日志查看器

系统日志、任务运行日志等高密度、长文本场景不使用 `ElTable` 截断展示，统一使用 `SystemLogViewer` 终端组件：

| 项目 | 规范 |
| --- | --- |
| 外层结构 | 保留系统页面的浅色表格容器、筛选区和操作区，终端只作为日志内容区域 |
| 标题 | `Document` 图标、`日志输出` 与结果数量；高度 `44px` |
| 日志正文 | 等宽字体 `Consolas, Cascadia Mono, SFMono-Regular, monospace`，`13px / 22px` |
| 终端背景 | 固定 `#07111F`，不随明暗主题改为浅色，保证运行日志连续可读 |
| 字段顺序 | 时间、级别、来源、消息；保持单行，长文本通过容器横向滚动查看 |
| 级别 | `INFO` 蓝、`WARNING` 黄、`ERROR/CRITICAL` 红、`DEBUG` 灰；颜色只作为辅助，级别文本必须完整保留 |
| 滚动 | 使用 `ElScrollbar`，垂直与水平滑块常驻、最小长度 `36px`；页面本身不得出现横向滚动 |
| 高度 | 桌面 `420-680px`，移动端 `460px`；结果数量变化不引发容器跳动 |

- 日志页面保留服务端筛选、自动刷新、手动刷新与当前结果下载；专用组件只负责渲染和滚动。
- 自动刷新数据按接口最新记录顺序展示，组件加载新数据后定位到最新记录，不能打断页面其他区域的滚动。

## 10. 按钮规范

### 10.1 层级

| 层级 | Element Plus | 使用场景 |
| --- | --- | --- |
| 主按钮 | `type="primary"` | 新建任务、保存、确认提交 |
| 次按钮 | 默认按钮 | 取消、返回、普通筛选 |
| 文本按钮 | `link` / `text` | 表格行操作、卡片右上角操作 |
| 危险按钮 | `type="danger"` | 删除、强制停止、清理资源 |
| 警告按钮 | `type="warning"` | 取消任务、暂停、风险操作 |

### 10.2 尺寸

| 场景 | 尺寸 |
| --- | --- |
| 页面主操作 | `default`，高度约 `32px` |
| 表格行操作 | `small` 或 `link` |
| 图标按钮 | `32px x 32px` |
| 表单提交 | `default`，必要时宽度 `96-120px` |

### 10.3 交互

- hover 只改变背景、边框、文字颜色，不使用会导致布局位移的缩放。
- loading 状态必须禁用重复提交。
- 危险操作必须用 `ElPopconfirm` 或 `ElMessageBox.confirm`。
- 同一区块主按钮最多一个。

## 11. 表单与筛选区

| 元素 | 规范 |
| --- | --- |
| 筛选区布局 | 单行横排，空间不足时换行 |
| 输入框宽度 | 常规 `220px`，短字段 `160px` |
| 日期范围 | `ElDatePicker`，宽度 `260-320px` |
| Select | 常规 `180-220px` |
| 表单标签 | 左对齐或顶部对齐，按页面复杂度统一 |
| 提交区 | 右对齐，主按钮在最右 |

筛选区不放在厚重卡片中；可以作为表格卡片 Header 的一部分。

## 12. 状态标签规范

| 状态 | 文案示例 | 颜色 |
| --- | --- | --- |
| 运行中 | `运行中` | success 绿，圆点 + 浅绿底 |
| 排队中 | `排队中` | primary 蓝 |
| 成功 | `成功` | success 绿 |
| 失败 | `失败` | danger 红 |
| 警告 | `警告` | warning 黄 |
| 已取消 | `已取消` | info 灰 |
| 已过期 | `已过期` | danger 红 |
| 即将耗尽 | `即将耗尽` | warning 黄 |

同一状态在卡片、表格、日志中必须使用相同文案和颜色。

## 13. 图表规范

| 图表 | 使用场景 | 规范 |
| --- | --- | --- |
| 折线图 | 吞吐趋势、成功率趋势、耗时趋势 | 蓝色主线，绿色成功线，红色失败线 |
| 环形图 | Token 占用、模板健康 | 中心显示主数值，右侧图例 |
| 迷你趋势图 | KPI 卡右侧 | 无坐标轴，弱网格或无网格 |
| 进度条 | 任务进度、资源占用 | 使用 Element Plus `ElProgress` |

图表优先表达状态和趋势，不追求复杂视觉效果。坐标轴、图例、tooltip 要简洁。

## 14. 登录页规范

| 区域 | 规范 |
| --- | --- |
| 背景 | 使用浅色数据网格/Sheet 纹理背景图，透明度低 |
| 登录卡片 | 宽度 `400-440px`，圆角 `8px`，白底 |
| 品牌区 | Logo + 产品名 + 一句短副标题 |
| 表单 | 用户名、密码、登录按钮 |
| 插图 | 可使用生成的登录图，但不遮挡表单 |

登录页仍走当前 `/api/auth/login` 鉴权，不改变 token 存储和刷新逻辑。

## 15. 图片与品牌资产规范

| 资产 | 用途 | 要求 |
| --- | --- | --- |
| Logo | 侧边栏、登录页 | 简洁几何标识，和 Sheet/任务/校验有关 |
| 背景图 | 登录页、内容区极弱纹理 | 浅色、低对比、不得影响文字 |
| 登录图 | 登录页辅助视觉 | 不使用人物大插画，优先数据流、表格、任务节点 |
| 动图/动效源图 | 仪表盘顶部或状态区域 | 表现任务流转、校验、资源占用，不做炫技动画 |

项目内使用的最终图片必须复制到 `frontend/src/assets` 或其他项目目录中，不能只引用生成工具默认目录。

## 17. 前端开源能力基线

以下依赖是本后台前端的固定技术基线。新增页面优先使用对应能力，不重复手写同类基础设施。

| 能力 | 依赖 | 强制使用场景 | 使用边界 |
| --- | --- | --- | --- |
| 图表 | `echarts` | 业务分析、仪表盘趋势、任务与资源统计 | 图表卡必须具备坐标轴、单位、图例和 tooltip；仅 KPI 内的微趋势可隐藏坐标轴。禁止手写 SVG/polyline 模拟业务图表。 |
| 浏览器交互 | `@vueuse/core` | 主题、全屏、持久化、剪贴板、尺寸监听、节流防抖 | 使用 `useStorage`、`useDark`、`useFullscreen`、`useClipboard`、`useResizeObserver` 等组合式能力；禁止为这些通用行为重复维护事件监听和 localStorage 包装。 |
| 日期时间 | `dayjs` | 表格时间、日志时间、日期范围、图表时间轴 | 所有用户可见日期统一由 `dayjs` 格式化；业务接口的原始时间值不得在模板内拼接。 |
| 跨页状态 | `pinia` | 登录身份、权限菜单、主题、页签等全局状态 | 只存跨页面共享状态；页面私有表单、筛选和一次性弹窗状态仍留在组件或 composable。 |
| 服务端状态 | `@tanstack/vue-query` | 仪表盘、任务、结果、资源等高频接口 | 查询通过 `useQuery` 管理 loading/error/cache；写操作通过 `useMutation` 后失效相关 query，禁止组件内散落重复刷新逻辑。 |
| JSON 浏览 | `vue-json-pretty` | 原始接口结果、配置预览、调试数据 | 仅用于只读结构化展示；业务分析必须转换为明确的指标表格，不能把 JSON 浏览器当作数据明细页。 |

- Element Plus 已覆盖表格、表单、弹窗、抽屉、分页、滚动条、上传和日期选择；不得额外引入平行 UI 或表格框架。
- 导出继续调用后端接口，前端只保留统一下载工具；不引入浏览器端 Excel 处理库。
- `axios`、`lodash`、`Chart.js`、`vxe-table`、`ag-grid` 不在默认依赖清单内，新增前必须说明现有能力无法满足的具体原因。

## 18. 响应式规范

| 断点 | 行为 |
| --- | --- |
| `>=1440px` | 标准桌面布局，4 个 KPI 卡横排 |
| `1200-1439px` | KPI 可 2x2，右侧日志保持独立列 |
| `768-1199px` | 侧栏折叠，主内容双列或单列 |
| `<768px` | 侧栏抽屉化，卡片单列，表格横向滚动 |

任何页面都不能出现横向页面滚动；只有表格容器可以局部横向滚动。

## 19. 可访问性与交互验收

- 所有可点击元素有 hover 和 focus-visible 状态。
- 表单控件必须有 label 或可访问名称。
- 颜色不能作为唯一状态表达，状态必须同时有文字。
- loading、empty、error 三种状态必须齐全。
- 动效遵守 `prefers-reduced-motion`。
- 文本不能与按钮、图标、图表重叠。

## 20. 后续开发执行规则

1. 新增 admin 页面前，先确认本规范是否已有对应模块。
2. 若页面需要新增组件形态，先补充本规范，再写页面。
3. 允许页面有局部差异，但必须记录在页面设计说明或代码注释中。
4. 不允许在单个页面里私自引入新主色、新圆角、新表格行高。
5. 与当前鉴权、侧边栏、后端接口相关的行为，以现有系统为准；本规范只约束视觉和交互。

### 通用硬性规范（无论选哪种都必须遵守）

| 规范类别 | 强制要求 |
| :--- | :--- |
| **选择器权重** | 禁止使用 `#id` 选择器，类选择器嵌套不超过3层，避免极高权重导致覆写困难。 |
| **颜色值** | 必须使用RGB/HEX（如 `#1890ff`），**严禁**使用中文颜色名（如 `red`、`blue`）。 |
| **数值单位** | 布局尺寸（width/margin/padding）使用 `rem` 或 `px`（配合postcss-pxtorem）；`border`、`box-shadow` 使用 `px`；字体大小使用 `px`（配合缩放）。 |
| **代码检查** | 必须配置 `stylelint` 并集成到 pre-commit 钩子，自动排序属性（推荐按 **定位 → 盒模型 → 文本 → 视觉** 的顺序）。 |
