# C7.0.3 模型适配方案

状态：待实施

## 目标

C7 创建页按每个已选 Google Sheet 的标题识别模型版本，并让 C7.0.2 与 C7.0.3 使用各自的 K 线输入布局。

- `C7.0.2.v20260703-回测-sharable-manual-test-2【使用中】`：保留现有两列写入方式。
- `C7.0.3.v20260729-回测-sharable-manual`：从第 3 行开始写入 OHLC K 线。

## 配置表

现有 C7.0.2 配置保持不变：

```text
c7_input_column_a = A
c7_input_column_b = B
```

新增以下系统配置项：

```text
c7_0_3_kline_date_column = CC
c7_0_3_kline_open_column = CD
c7_0_3_kline_high_column = CE
c7_0_3_kline_low_column = CF
c7_0_3_kline_close_column = CG
```

含义如下：

| 字段 | C7.0.3 列 | 行情字段 |
| --- | --- | --- |
| 时间 | CC | `stock_date` |
| O | CD | `stock_kp` |
| H | CE | `stock_zg` |
| L | CF | `stock_zd` |
| C | CG | `stock_sp` |

默认值应加入 `app/config.py` 的 `default_configs`，由 `init_config()` 幂等写入 `SystemConfig`。列号和起始行不可硬编码在业务逻辑中，以便后续通过管理后台调整。

## 前端方案

修改 `templates/google_sheet_c7/create.html`。

### 控件位置

版本选择属于单个 Google Sheet，而不是整个任务。每个任务可以包含多张表，它们可能是不同的 C7 版本。

在每个 `.sheet-config-item` 的第一行中，紧跟“选择 Google Sheet”添加“C7 模型版本”下拉框。建议布局：

```text
选择 Google Sheet（6 列） | C7 模型版本（2 列） | 表标题（2 列） | 工作表名称（2 列）
```

下拉值：

```text
c7_0_2：C7.0.2（两列 K 线）
c7_0_3：C7.0.3（OHLC K 线）
```

### 自动识别

`loadWorksheetsForItem()` 已从 `/api/google-sheet/worksheets` 响应获得真实表标题 `data.title`。在标题写入“表标题”输入框后，按前缀设置版本：

```javascript
const title = (data.title || '').trim();
if (title.startsWith('C7.0.3')) {
    versionSelect.value = 'c7_0_3';
} else {
    versionSelect.value = 'c7_0_2';
}
```

无法识别时回退到 `c7_0_2`，保证旧任务兼容；用户可以手动改为正确版本。

### 配置保存与回填

在每个 `sheets` 项中保存 `c7_model_version`：

```json
{
  "spreadsheet_id": "...",
  "title": "C7.0.3.v20260729-回测-sharable-manual",
  "sheet_name": "data",
  "c7_model_version": "c7_0_3"
}
```

以下逻辑必须同步支持该字段：

- `submitTask()`
- `getCurrentConfig()`，用于保存模板
- `applyConfigToForm()` 和 `normalizeC4Config()`，用于模板及任务重启回填
- `saveFormData()` 与 `loadSavedFormData()`
- 动态新增表格配置的克隆和事件绑定逻辑

## 后端方案

主要修改 `app/services/google_sheet_service_C7.py`。

### 按表解析布局

在 `execute_task()` 合并系统配置和任务配置后，根据 `config_data['sheets']` 建立 `spreadsheet_id -> c7_model_version` 映射。执行时按当前 `google_sheet.spreadsheet_id` 读取版本及配置表字段，避免把同一份 A/B 写入数据发给不同版本的表。

布局规则：

```text
c7_0_2：起始行 2，日期 c7_input_column_a，单价 c7_input_column_b
c7_0_3：起始行 2，CC/CD/CE/CF/CG 由配置表读取
```

### 保留 OHLC 数据

现有 `_get_all_parameters()` 的 K 线映射只保留 `stock_date` 和 `stock_val`，无法供 C7.0.3 写入 OHLC。构造 K 线行时还必须保留：

```python
{
    "stock_date": row["stock_date"],
    "stock_val": row[price_field],
    "stock_kp": row["stock_kp"],
    "stock_zg": row["stock_zg"],
    "stock_zd": row["stock_zd"],
    "stock_sp": row["stock_sp"],
}
```

`stock_val` 继续服务 C7.0.2 的价格类型逻辑；C7.0.3 写入时使用 OHLC 原始字段。

### 写入与清理

重构 `_execute_parameter_combination()`，按每张表单独构建 `cell_updates`：

```python
# C7.0.3，row 从 3 开始
updates[f"{date_column}2"] = item["stock_date"]
updates[f"{open_column}2"] = item["stock_kp"]
updates[f"{high_column}2"] = item["stock_zg"]
updates[f"{low_column}2"] = item["stock_zd"]
updates[f"{close_column}{row}"] = item["stock_sp"]
```

清理旧数据也要按版本执行：

```text
C7.0.2：A2:B{last_row}
C7.0.3：CC2:CG{last_row}
```

不得清理 C7.0.3 的第 1行，以免删除标题、公式或参数区域。

### 多字母列支持

`app/services/google_sheet_client.py` 的 `get_last_row()` 当前通过 `ord()` 转换列号，只能处理单字母列。传入 `CC` 会失败。

改为使用 `gspread.utils.a1_to_rowcol(f"{col_letter}1")` 获取列号，之后再调用 `worksheet.col_values(column_number)`。该修复也适用于其它未来使用 AA 之后列的任务。

### 自定义 K 线模式

若 C7.0.3 支持 `kline_source=custom`，读取逻辑也应按版本分支：

```text
C7.0.2：从 A/B、第 2 行读取日期和单价
C7.0.3：从 CC:CG、第 2 行读取日期和 OHLC
```

C7.0.3 的自定义数据需校验日期、O、H、L、C 均非空。

## 前提

本文仅获知 C7.0.3 的 K 线输入位置。默认假设参数输入单元格、触发检测单元格、结果读取范围和 J/L 收益列与 C7.0.2 相同。

若这些位置也发生变化，应将它们同样做成 `c7_0_3_*` 配置项，并在按表解析布局时一起读取，不能继续共享 C7.0.2 的配置。

## 验收用例

1. 选择标题以 `C7.0.2` 开头的表，版本自动为 `c7_0_2`，仍从 A2/B2 写入。
2. 选择标题以 `C7.0.3` 开头的表，版本自动为 `c7_0_3`，从 CC2:CG2 写入第一条 OHLC。
3. C7.0.3 清理仅覆盖 CC2:CG 的旧数据，不修改第 1 行。
4. `get_last_row('CC')` 返回正确结果。
5. C7.0.3 缺少任一 OHLC 值时，任务失败并记录可读错误摘要。
6. 模板、localStorage 恢复和任务重启后，`c7_model_version` 保持不变。
7. 同一任务含 C7.0.2 与 C7.0.3 两张表时，各自写入正确位置。
