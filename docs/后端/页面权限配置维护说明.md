# 页面、权限、配置维护说明

本文记录当前项目里新增后台页面、权限、导航菜单和默认配置时的固定入口，避免在路由、模板、启动脚本、数据库种子逻辑之间反复查找。

## 当前结构问题

当前系统同时存在四类入口：

- 页面路由：`app/routes/*.py`，例如后台页面集中在 `app/routes/admin.py`
- 蓝图注册：`app/routes/__init__.py`
- 侧边栏菜单：`app/navigation.py` 的 `DEFAULT_NAVIGATION_MENU`
- 权限种子：`app/config.py` 的 `PERMISSIONS`

过去 `run.py` 启动时还会调用默认配置、RBAC、导航菜单和默认定时任务的写库逻辑，导致应用启动同时承担“运行恢复”和“数据初始化”两类职责。现在已拆分：

- 启动恢复：`app/startup.py`
- 默认数据写库：`app/seed_data.py`
- 显式初始化脚本：`scripts/seed_default_data.py`

## 启动不再做的事

`python run.py` 不再写入以下种子数据：

- `SystemConfig` 默认配置
- `Permission` 权限字典
- `Role` / 默认管理员
- `NavigationMenuItem` 侧边栏菜单
- 默认 `ScheduledTask`

需要初始化或同步这些数据时，显式执行：

```powershell
python scripts/seed_default_data.py
```

如果只想写种子数据，不做 schema 修补：

```powershell
python scripts/seed_default_data.py --skip-schema
```

如果不想创建默认定时任务：

```powershell
python scripts/seed_default_data.py --skip-scheduler
```

## 新增后台页面流程

以新增 `/admin/example` 页面为例：

1. 在 `app/routes/admin.py` 添加页面路由，返回模板。

```python
@admin_bp.route('/example')
def example():
    return render_template('admin/example.html')
```

2. 新增模板文件。

```text
templates/admin/example.html
```

3. 在 `app/config.py` 的 `PERMISSIONS` 添加页面访问权限。

```python
('page', 'page:admin:example', '访问示例页面', '/admin/example')
```

4. 在 `app/navigation.py` 的 `DEFAULT_NAVIGATION_MENU` 添加侧边栏菜单项。

```python
{"key": "example", "label": "示例页面", "path": "/admin/example", "permission": "page:admin:example"}
```

`app/navigation.py` 同时维护：

- 默认侧边栏菜单
- 旧路径到新路径的兼容映射 `NAV_LEGACY_PATH_MAP`
- 路径到页面权限的映射 `build_nav_permission_map()`

5. 执行种子脚本，把新权限和菜单同步到数据库。

```powershell
python scripts/seed_default_data.py --skip-schema
```

6. 到角色管理页给对应角色分配新权限。

管理员角色会在种子脚本中自动获得全部权限；普通角色需要在页面上手动勾选。

## 新增 API 权限流程

1. 在对应 `app/routes/*_api.py` 或业务蓝图中给接口加装饰器。

```python
@login_required
@permission_required('example:manage')
```

2. 在 `app/config.py` 的 `PERMISSIONS` 添加接口权限。

```python
('example', 'example:manage', '管理示例资源', None)
```

3. 执行：

```powershell
python scripts/seed_default_data.py --skip-schema
```

4. 在角色管理页给角色分配权限。

## 新增默认系统配置流程

默认配置只维护在 `app/config.py` 的 `init_config()` 中。新增配置后执行：

```powershell
python scripts/seed_default_data.py --skip-schema --skip-scheduler
```

注意：默认配置脚本只补缺失项，或补空的说明字段；运行时不再通过应用启动自动覆盖数据库配置。

## 推荐后续优化

当前已经把启动写库迁出，但页面新增仍需维护 `admin.py`、模板、`PERMISSIONS`、`DEFAULT_NAVIGATION_MENU` 四处。下一步建议把后台页面声明继续抽成统一 registry，例如：

```python
AdminPage(
    key='example',
    label='示例页面',
    path='/admin/example',
    template='admin/example.html',
    permission='page:admin:example',
)
```

然后由 registry 生成页面权限、默认导航菜单，甚至自动注册简单模板路由。这样才能把新增后台页面压缩成“改一处声明 + 写模板”。
