# 页面、权限、配置维护说明

本文记录当前项目里新增后台页面、权限、导航菜单和默认配置时的固定入口，避免在路由、模板、启动脚本、数据库种子逻辑之间反复查找。

## 当前结构

当前系统把普通后台页面声明集中在：

- 页面 registry：`app/page_registry.py`
- 页面路由：`app/routes/admin.py`
- 默认侧边栏菜单：`app/navigation.py` 从 registry 生成 `DEFAULT_NAVIGATION_MENU`
- 权限种子：`app/config.py` 用 `BASE_PERMISSIONS + page_permissions()` 生成 `PERMISSIONS`
- 前端页面权限映射：`/api/meta/page-permissions`

过去 `run.py` 启动时还会调用默认配置、RBAC、导航菜单和默认定时任务的写库逻辑，导致应用启动同时承担“运行恢复”和“数据初始化”两类职责。现在已拆分：

- 启动恢复：`app/startup.py`
- 默认数据写库：`app/seed_data.py`
- 显式初始化脚本：`scripts/seed_default_data.py`

## 启动不再做的事

`python run.py` 不再写入以下种子数据：

- `SystemConfig` 默认配置
- `Permission` 权限字典
- `Role` / 默认管理员
- `NavigationMenuItem` 侧边栏菜单
- 默认 `ScheduledTask`

需要初始化或同步这些数据时，显式执行：

```powershell
python scripts/seed_default_data.py
```

如果只想写种子数据，不做 schema 修补：

```powershell
python scripts/seed_default_data.py --skip-schema
```

如果不想创建默认定时任务：

```powershell
python scripts/seed_default_data.py --skip-scheduler
```

## 新增后台页面流程

以新增 `/admin/example` 页面为例：

1. 在 `app/page_registry.py` 添加页面声明。

```python
PageDef(
    key="example",
    label="示例页面",
    path="/admin/example",
    template="admin/example.html",
    permission="page:admin:example",
    parent_key="system",
    sort_order=70,
)
```

`parent_key` 对应默认分组：

- `task`：任务模块
- `data`：数据模块
- `scheduler_group`：调度模块
- `system`：系统模块
- `business`：业务模块

如果页面需要权限但不显示在菜单中，设置 `visible=False`。

2. 新增模板文件。

```text
templates/admin/example.html
```

普通后台模板页无需再手动添加路由，`app/routes/admin.py` 的 registry fallback 会按 `PageDef.path` 渲染 `PageDef.template`。

如果页面需要特殊模板上下文，再在 `app/routes/admin.py` 添加显式页面路由。显式路由会继续优先生效。

```python
@admin_bp.route('/example')
def example():
    return render_template('admin/example.html', options=build_options())
```

3. 执行种子脚本，把新权限和菜单同步到数据库。

```powershell
python scripts/seed_default_data.py --skip-schema
```

4. 到角色管理页给对应角色分配新权限。

管理员角色会在种子脚本中自动获得全部权限；普通角色需要在页面上手动勾选。

普通后台页面不需要再手动修改：

- `app/config.py` 的页面权限
- `app/navigation.py` 的默认菜单
- `static/js/template-auth.js` 的后台页面 matcher

## 页面权限边界

当前页面 GET 请求不会自动携带 `Authorization` header，因此服务端页面路由仍不做强权限拦截。现阶段：

- API 是强权限边界，必须使用 `login_required` / `permission_required`
- 页面权限用于默认菜单过滤和前端页面守卫
- 前端通过 `/api/meta/page-permissions` 获取 registry 派生的路径权限映射

后续如要加强页面路由服务端校验，可把 JWT 改为 HttpOnly Cookie 或引入等价的服务端登录态。

## 新增 API 权限流程

1. 在对应 `app/routes/*_api.py` 或业务蓝图中给接口加装饰器。

```python
@login_required
@permission_required('example:manage')
```

2. 在 `app/config.py` 的 `PERMISSIONS` 添加接口权限。

```python
('example', 'example:manage', '管理示例资源', None)
```

3. 执行：

```powershell
python scripts/seed_default_data.py --skip-schema
```

4. 在角色管理页给角色分配权限。

## 新增默认系统配置流程

默认配置只维护在 `app/config.py` 的 `init_config()` 中。新增配置后执行：

```powershell
python scripts/seed_default_data.py --skip-schema --skip-scheduler
```

注意：默认配置脚本只补缺失项，或补空的说明字段；运行时不再通过应用启动自动覆盖数据库配置。

## 页面 registry 维护建议

`app/page_registry.py` 是页面权限和默认菜单的单一声明来源。新增普通后台页面时优先只补 `PageDef` 和模板；只有存在旧 URL 时才补 `aliases`，只有详情页这类动态路径才补 `path_prefixes`。
