# 部署运维

## 部署形态总览

```
Nginx (80)
  ├── /            → frontend/dist（Vue 静态资源，try_files 回退 index.html）
  └── /api/        → proxy_pass http://127.0.0.1:5000（read timeout 300s）
Docker 容器 google_task:1.0.4（宿主 8081 → 容器 5000，gunicorn 单 worker）
PostgreSQL（部署机 .env.production 指向内网库）
```

Jinja 旧前端页面仍由 Flask:5000 直接渲染，经 `/api/` 之外的路径访问时需 Nginx 一并反代（当前 nginx.conf 只反代 `/api/`）。

## Docker

- Dockerfile：`python:3.11.10-slim-bookworm`，只复制 `app/ static/ templates/ stock_sdk/ run.py 环境文件 run.sh`（**不含 frontend/**），非 root 用户 appuser(1000)，`/app/logs`、`/app/data` 777。
- CMD：`/bin/bash ./run.sh`；ENV `FLASK_APP=run.py`、`PORT=5000`。
- **构建前需准备 `.env.development/.env.production/.env.testing`**（Dockerfile 会 COPY，缺文件构建失败；这些文件不入库）。
- docker-compose.yml：project `google-sheet-validator`，服务 app，端口 **8081:5000**，挂载 `./data`、`./logs`，`APP_ENV=production`，`stop_grace_period: 45s`，restart unless-stopped。

```bash
docker compose up -d
```

## Gunicorn：必须单 worker

`dockers/gunicorn.conf.py`（容器内 /app/docker-gunicorn.conf.py）：

- **workers=1、max_requests=0、preload_app=False** —— 任务线程、APScheduler、看门狗都是进程内单例，多 worker 会重复调度、互抢 Google Sheet Token；`max_requests>0` 会在长任务运行中回收 worker。
- `timeout=120`；`post_worker_init` 钩子调用 `app.startup.bootstrap_app(worker.app.callable)` 完成启动期编排。
- 根目录 `config/gunicorn.conf.py`（workers=CPU×2+1、preload）与单 worker 约束冲突，是过时备用配置，勿用于本项目的容器部署。

## Nginx（nginx.conf）

```nginx
root /path/to/frontend/dist;          # Vue 构建产物
location /api/ { proxy_pass http://127.0.0.1:5000; proxy_read_timeout 300s; }
location /     { try_files $uri $uri/ /index.html; }   # history 路由回退
```

部署新前端：`cd frontend && npm run build`，将 dist 同步到 Nginx root。

## 配置体系

三层配置源，后者覆盖前者：

1. **环境变量 / .env / .env.{APP_ENV}**（app/__init__.py::load_app_environment，后加载不覆盖先加载）
2. **Config 类**（app/config.py，按 APP_ENV 选择）
3. **SystemConfig 数据库表**（运行时经 `config_manager` 读取，管理后台可改）

常用 SystemConfig 键（默认值见 `app/config.py::init_config`）：

| 键 | 默认 | 说明 |
|---|---|---|
| proxy_url | — | Google 访问代理 |
| dfcf_kline_proxy_enabled | False | 东方财富 K 线是否走代理（SmartProxyManager） |
| max_concurrent_tasks | 20 | 最大并发任务 |
| task_timeout | 36000 | 任务超时秒 |
| task_status_check_timeout | 600 | 日志静默判死阈值 |
| watchdog_enabled / interval_seconds / log_timeout_minutes | True / 1800 / 30 | 看门狗 |
| watchdog_force_restart_wait_seconds / max_restart_attempts | 45 / 3 | 强制重启 |
| execution_delay_min/max | 20/30 | Sheet 轮询延迟 |
| api_retry_max_attempts / api_retry_delay | 10 / 30 | Sheet 读写重试 |
| token_file | data/token.json | Google OAuth token |
| google_sheet_token_global_max_usage | 0(不限) | Token 全局占用上限 |
| C3/C4/C5/C7 单元格位置 | — | c3_parameter_positions、c3_check_positions、c3_output_range_*、c7_0_3_kline_* 等 |

配置访问统一走 `get_config_manager()`，不要散落读环境变量。

## 日志体系

- 应用日志：`logs/app.log`（ConcurrentRotatingFileHandler，多进程安全）。
- 看门狗专属：`logs/task_watchdog.log`（RotatingFileHandler 10MB×10）。
- 任务日志：DB `TaskLog`（message 截断 4000 字符）+ 任务级 logger（`get_task_logger`）；`/api/system-logs` 与管理后台可查。
- 运行时目录：`data/`、`logs/` 由 bootstrap 自动创建，Docker 挂载持久化。

## 外部集成

- **钉钉通知**：`app.notifier = DingTalkNotifier`，服务级 `error_dd` / `task_ok_to_dd`；环境变量 `DING_TALK_ACCESS_TOKEN/SECRET`。
- **钉钉 Stream 微服务**：独立进程 `python run_ding.py`（ding_stream_service/，dingtalk-stream SDK），凭据 `DING_STREAM_CLIENT_ID/SECRET`。
- **代理源**：SmartProxyManager 从 `stockapi.stplan.cn` 拉取代理（30s TTL / 单代理复用 50 次）。

## 运维检查单

1. 重启容器即自动恢复：Token/Sheet 占用清零、死任务回 pending（bootstrap_app）。
2. 任务卡死先看 `/api/tasks/<id>/runtime-detail` 与运行态快照 `get_runtime_snapshot()`。
3. `[NETWORK_RETRYABLE]` 错误由看门狗自动重启；`attempt=N/M` 超 3 次放弃。
4. 数据库体积增长靠默认"每日数据清理"任务与 `/api/database/vacuum`。
5. 生产安全：改默认 admin 密码、强随机 JWT_SECRET_KEY（否则启动 fail fast）、勿在代码/文档中留存代理账号密码。
