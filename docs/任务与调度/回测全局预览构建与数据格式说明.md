# 回测全局预览构建与数据格式说明

本文说明单产品与多产品回测全局预览的后端构建流程、数据契约和修改注意事项。
预览页面只负责展示，指标计算和数据格式整理均在后端完成。

## 代码入口

| 场景 | 构建函数 | API | 页面 |
| --- | --- | --- | --- |
| 单产品 | `app.services.backtest_training_api_service._build_global_preview_payload_from_results()` | `GET /backtest-training/api/global-preview/<task_id>` | `templates/backtest_training/global_preview.html` |
| 多产品 | `app.services.backtest_multi_product_service.build_multi_product_global_preview_payload()` | `GET /backtest-multi-product/api/global-preview/<task_id>` | `templates/backtest_multi_product/global_preview.html` |

单产品的 `_build_global_preview_payload()` 是全量调用封装；首屏和分组切换接口会先查询结果索引，再调用同一套构建逻辑。多产品的比例修改和导出接口都复用 `build_multi_product_global_preview_payload()`，因此不能在页面端另行实现一套比例算法。

## 单产品数据格式处理

### 输入格式

每条 `TaskResult` 至少包含：

```json
{
  "id": 101,
  "step_index": 0,
  "success": true,
  "parameters": "{\"stock_code\": \"AAPL\", \"year\": 2024, \"parameter\": [1, 2]}",
  "result": "{\"calculate_metrics\": {}}"
}
```

`parameters` 和 `result` 在数据库中是 JSON 字符串，构建时分别解析。`result` 可能直接包含 `calculate_metrics`，也可能把它放在 `analyze_result` 中，后端统一提取后再格式化。

### 分组和列

1. 分组键为 `stock_code::year`，股票代码优先取结果参数，缺失时回退到任务配置。
2. 每条结果生成一列 `result_<result_id>`，即使结果失败也保留列，方便定位失败步骤。
3. 成功结果通过 `_extract_summary_rows()` 转成指标行；严格格式化失败时使用 fallback 行，尽量保留可计算指标。
4. 相同 `category + metric` 的行合并，列值写入 `values[column_key]`；缺少某列指标使用空字符串，不把缺失误认为数值 0。

最终单产品 payload 的核心结构：

```json
{
  "task": {"id": "...", "name": "...", "status": "completed"},
  "summary": {"total_results": 2, "success_results": 2, "failed_results": 0},
  "groups": [
    {
      "group_key": "AAPL::2024",
      "columns": [{"column_key": "result_101", "result_id": 101}],
      "rows": [
        {"category": "收益", "metric": "年化收益", "index_value": "...", "values": {"result_101": "..."}}
      ]
    }
  ]
}
```

## 多产品全局预览构建

### 构建阶段

`build_multi_product_global_preview_payload()` 按以下顺序处理：

1. 读取任务并通过 `normalize_multi_product_config()` 统一产品字段和比例格式。
2. 应用 `ratios_override`（如果是比例试算或保存请求），不直接修改数据库任务配置。
3. 按 `step_index` 查询全部 `TaskResult`，以 `parameter_group_index` 分组。
4. 在每组内按 `product_index` 保存单产品结果，分别提取原始指标和已有的比例后指标。
5. 比例后指标缓存缺失、比例变化或算法开关变化时，从 `TaskResultReturn` 收益序列重新计算。
6. 使用所有产品共同日期收益序列计算组合指标，再按 `SUMMARY_ROW_DEFS` 生成统一指标行。
7. 写入内存缓存；缓存键包含任务结果、产品比例和加权算法开关，避免读取旧预览。

### 输出格式

多产品 payload 的 `groups` 按参数方案组织：

```json
{
  "group_key": "0",
  "group_label": "参数方案 1",
  "parameter_group_index": 0,
  "products": [{"product_index": 0, "product_name": "AAPL", "ratio": "50"}],
  "rows": [
    {
      "category": "收益",
      "metric": "年化收益",
      "value_type": "percent",
      "product_values": [
        {
          "product_index": 0,
          "index_value": "...",
          "result_value": "...",
          "weighted_result_value": "...",
          "raw_result_value": 0.12,
          "raw_weighted_result_value": 0.06
        }
      ],
      "weighted_index_value": "...",
      "weighted_result_value": "..."
    }
  ]
}
```

页面使用 `product_values` 展示每个产品的三类值：原始指数、原始模型结果、比例后模型结果；使用 `weighted_index_value` 和 `weighted_result_value` 展示组合结果。`raw_*` 字段仅用于前端重算/导出等需要数值的场景，展示文本必须经过 `_fmt_value()`。

## 修改注意事项

- 不要改变单产品的 `group_key`、`column_key` 和 `rows[].values` 结构，否则首屏索引和分组切换会失配。
- 不要把多产品结果按执行步骤直接平铺；`parameter_group_index` 才是页面参数方案维度。
- 比例后模型结果必须基于收益序列重新计算，不能简单把已格式化的百分数字符串相乘。
- 指标没有指数来源时应输出 `-`；缺少模型列值时使用空字符串，保持“无值”和“零值”可区分。
- 新增指标时同步更新 `SUMMARY_ROW_DEFS`、`_derive_metrics()`、页面表头和相关导出逻辑。
- 修改后至少运行：

```powershell
pytest tests/test_backtest_multi_product.py -q
pytest tests/test_backtest_training_export_preview.py -q
```
