# 独立爬虫定时任务接入方案

## 目标

让爬虫保持为可独立开发、可本地运行和可随时替换的 Python 文件；平台只负责任务配置、定时触发、运行记录和失败告警。

选用现有 APScheduler 作为触发器，复用 `ScheduledTask` 的 Cron 和启停配置。爬虫执行发生在现有 `app/services/scheduled_task_worker.py` 独立进程中：worker 通过文件路径动态导入脚本，并调用其 `run(config, context)` 入口。

不要在 Flask Web 主进程中直接导入和运行爬虫。爬虫卡死、内存泄漏或未预期异常不得影响 Web 服务和其他调度任务。

## 执行流程

```text
管理页面新增 / 更新爬虫任务
  -> ScheduledTask 持久化 Cron、参数、启用状态
  -> APScheduler 注册或更新 job
  -> 到点触发 scheduled_task_worker.py 独立进程
  -> worker 校验相对路径，并动态导入 crawler.py
  -> crawler.run(config, context)
  -> 写入 CrawlerRun 运行记录
  -> 成功完成；失败则写错误摘要、完整 traceback 并发送钉钉告警
```

平台重启后，`init_scheduler()` 会启动调度器，调度器从数据库重新加载所有 `is_active=true` 的 `ScheduledTask`。因此，已启用的爬虫任务会按原 Cron 继续执行；脚本不需要重新注册。

## 文件和数据约定

建议将每个已部署爬虫存储在受控目录中：

```text
data/crawlers/
  stock_price/
    crawler.py
  news_collector/
    crawler.py
```

数据库中只保存相对于 `data/crawlers/` 的脚本路径，例如 `stock_price/crawler.py`。禁止前端提交绝对路径、`..` 路径或任意 shell 命令。

定时任务使用现有 `ScheduledTask`，推荐字段取值：

```json
{
  "name": "每日股票价格爬取",
  "cron_expression": "0 18 * * 1-5",
  "task_type": "crawler",
  "task_function": "run_crawler",
  "task_params": {
    "script_path": "stock_price/crawler.py",
    "config": {
      "symbols": ["000001", "600519"]
    },
    "timeout_seconds": 600
  },
  "is_active": true
}
```

新增 `CrawlerRun`（或命名为 `ScheduledTaskRun`）记录每次运行。至少保存：

| 字段 | 用途 |
| --- | --- |
| `id` | 本次运行唯一标识 |
| `scheduled_task_id` | 关联的定时任务 |
| `status` | `running`、`completed`、`failed`、`timed_out`、`interrupted` |
| `trigger_type` | `scheduled` 或 `manual` |
| `started_at` / `ended_at` | 运行耗时与排障依据 |
| `script_path` / `script_sha256` | 确认本次实际使用的脚本版本 |
| `result_summary` | 成功时的结构化摘要 |
| `error_code` / `error_message` | 面向页面和告警的短错误信息 |
| `traceback_text` | 仅供详情页和日志查看的完整调用栈 |

## 爬虫接口

每个脚本必须提供：

```python
def run(config: dict, context) -> dict:
    """执行爬虫；成功返回 JSON 可序列化的字典，失败抛出异常。"""
```

`context` 由平台提供，至少包含：

- `run_id`：本次运行 ID；
- `logger`：已绑定任务和运行 ID 的 logger；
- `info(message, *args)`：可选的简化日志方法。

业务预期错误使用带错误码的异常；网络类错误可以标记为可重试：

```python
class CrawlerError(Exception):
    def __init__(self, code: str, message: str, *, retryable: bool = False):
        super().__init__(message)
        self.code = code
        self.retryable = retryable


raise CrawlerError("UPSTREAM_TIMEOUT", "行情服务请求超时", retryable=True)
```

未处理的 Python 异常同样必须上抛，worker 会将异常类名作为错误码，并保存完整 traceback。不要在爬虫中吞掉异常后返回成功。

可复制的最小模板位于：[templates/crawler_template.py](templates/crawler_template.py)。

## Worker 核心代码

动态导入必须使用唯一模块名，以避免不同任务或脚本更新后复用旧模块：

```python
import importlib.util
from pathlib import Path


def load_crawler(script_path: Path, run_id: str):
    module_name = f"crawler_{run_id.replace('-', '_')}"
    spec = importlib.util.spec_from_file_location(module_name, script_path)
    if spec is None or spec.loader is None:
        raise RuntimeError(f"无法加载爬虫脚本: {script_path}")

    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    runner = getattr(module, "run", None)
    if not callable(runner):
        raise RuntimeError("爬虫脚本必须提供 run(config, context) 函数")
    return runner
```

路径校验应在加载前完成：

```python
CRAWLER_ROOT = Path("data/crawlers").resolve()
script_path = (CRAWLER_ROOT / relative_path).resolve()
if CRAWLER_ROOT not in script_path.parents or script_path.suffix != ".py":
    raise ValueError("爬虫脚本路径不合法")
if not script_path.is_file():
    raise FileNotFoundError(f"爬虫脚本不存在: {relative_path}")
```

在 `scheduled_task_worker.py` 中新增 `task_function == "run_crawler"` 分支。分支负责创建 `CrawlerRun`、加载脚本、调用 `run()`、更新运行结果、无论成功或失败都释放 `ScheduledTask.is_running` 锁。

## 调度配置

继续使用 APScheduler；当前项目不需要为爬虫引入 Celery Beat。创建 crawler job 时应统一设置：

```python
scheduler.add_job(
    func=self._execute_task,
    trigger=trigger,
    id=job_id,
    args=[task_id],
    replace_existing=True,
    max_instances=1,
    coalesce=True,
    misfire_grace_time=300,
)
```

- `max_instances=1`：同一任务未结束时不重复执行；
- `coalesce=True`：平台停机错过多次触发时，只补一次；
- `misfire_grace_time=300`：五分钟以内的错过触发允许补跑；超过则跳过；
- 调度器时区应固定为 `Asia/Shanghai`。

“立即执行一次”仅创建一次 `manual` 运行，不修改既有 Cron。

## 重启与锁恢复

平台启动时，除加载启用任务外，还必须处理异常退出遗留状态：

1. 查询状态为 `running` 的 `CrawlerRun`；
2. 将其改为 `interrupted`，写入“平台重启导致执行中断”；
3. 清理对应 `ScheduledTask.is_running` 和 `running_instance_id`；
4. 发送一次中断告警，或按任务参数控制是否告警；
5. 再由调度器继续后续 Cron。

不能仅依赖内存中的 `running_tasks`；进程重启后该数据会丢失。

## 告警规则

钉钉告警应由 worker 在已获得真实异常的地方发送。为定时任务新增 `send_scheduled_task_notification()`，不要复用只面向 Google Sheet `Task` 的详情链接。

| 场景 | 建议错误码 | 是否告警 |
| --- | --- | --- |
| 脚本路径不合法或脚本不存在 | `SCRIPT_NOT_FOUND` | 是 |
| 脚本导入、语法或依赖失败 | `SCRIPT_LOAD_ERROR` | 是 |
| 缺失 `run()` 入口 | `INVALID_CRAWLER_INTERFACE` | 是 |
| 爬虫主动抛出的业务错误 | 自定义 `CrawlerError.code` | 是 |
| 未预期 Python 异常 | 异常类名 | 是 |
| 超过 `timeout_seconds` | `CRAWLER_TIMEOUT` | 是 |
| worker 启动失败 | `WORKER_START_ERROR` | 是 |
| 平台重启中断运行 | `RUN_INTERRUPTED` | 建议是 |
| 正常成功 | - | 默认不告警，可按任务配置发送成功通知 |

告警中应包含任务名、运行 ID、脚本路径和 SHA-256、错误码、错误摘要、开始时间、耗时和运行详情链接。不得发送 Cookie、Token、账号密码、完整请求头或完整任务配置。

## 更新脚本和使用流程

1. 本地复制模板并实现 `run()`，先命令行运行验证。
2. 上传到 `data/crawlers/<crawler_key>/crawler.py` 的临时文件。
3. 通过平台的“校验脚本”动作动态导入并确认存在 `run()`。
4. 使用原子替换更新正式文件。
5. 创建或更新 `ScheduledTask`，设置 `task_function=run_crawler`、Cron、参数、超时和启用状态。
6. 点击“立即执行”验证结果、运行记录和失败告警。
7. 后续替换脚本后，无须重启应用；下一次执行自动加载新版本。

脚本运行期间更新文件不会影响已加载的模块；正在执行的任务继续使用旧版本，下次运行使用新版本。运行记录中的 SHA-256 用于回溯版本。

## 验收清单

- 本地执行模板可返回成功结果。
- 新增并启用 crawler 定时任务后，到点只启动一次。
- 修改 Cron、参数或启停状态后，调度器立即生效。
- 应用重启后，启用任务仍按 Cron 运行。
- 脚本语法错误、导入错误、业务错误、超时和 worker 启动失败均写入 `CrawlerRun` 并触发钉钉告警。
- 应用在爬虫运行期间重启后，遗留运行记录标记为 `interrupted`，任务锁被释放。
- 不允许通过 API 执行 `data/crawlers/` 以外的任意 Python 文件。
