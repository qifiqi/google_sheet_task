# 架构总览

> 本文描述当前代码的真实架构。所有路径和函数名均以仓库现状为准。

## 一句话定位

基于 Flask 的**长时间运行任务平台**：以 Google Sheet 为参数与结果载体，在线程中执行 C 系列（C3/C4/C5/C7/C31）参数批量校验任务和回测训练任务，配套调度器、看门狗自动恢复、Token/Sheet 占用管理、管理后台和 Vue 前端。

## 技术栈

| 层 | 技术 |
|---|---|
| 后端框架 | Flask + Flask-SQLAlchemy + Flask-Migrate（Alembic） |
| 任务并发 | threading（进程内线程），非 Celery |
| 调度 | APScheduler BackgroundScheduler + croniter |
| Google Sheet IO | gspread + google.oauth2.credentials.Credentials |
| K线数据源 | 东方财富（dfcf_api）、腾讯（qq_api）、Yahoo（yf_api） |
| 数据处理 | pandas / numpy |
| 数据库 | 默认 SQLite（`instance/app.db`），生产 PostgreSQL（psycopg2-binary），兼容 MySQL（PyMySQL） |
| 文档/导出 | openpyxl / xlsxwriter（Excel）、python-docx + Matplotlib（Word 报告） |
| 认证 | PyJWT（access 2h / refresh 7d） |
| 前端（新） | Vue 3 + Vite + Element Plus + Naive UI（见 [前端Vue工程.md](前端Vue工程.md)） |
| 前端（旧） | Jinja2 模板 + 内联 JS + static/ 资源，与新前端并存 |
| 部署 | Docker + gunicorn（强制单 worker）+ Nginx |

## 启动流程

### create_app()（app/__init__.py）

1. `load_app_environment()`：先加载 `.env`（不覆盖已有环境变量），再按 `APP_ENV` 加载 `.env.{development|production|testing}`（同样不覆盖）。
2. `validate_auth_runtime_settings()`（app/utils/auth.py）：非 development 环境下若 `JWT_SECRET_KEY` 是默认值或 `AUTH_ENABLED=false` 直接抛错（fail fast）。
3. 按 `APP_ENV` 选择 Config 类并 `init_app()`。
4. `db.init_app` / `migrate.init_app`；`get_config_manager().init_app(app)`。
5. `register_blueprints(app)`（app/routes/__init__.py）。
6. 注入模板上下文 `auth_enabled`；挂 `app.notifier = DingTalkNotifier(...)`。

### bootstrap_app(app)（app/startup.py）

`python run.py`（`__main__` 分支）和 Docker 下 gunicorn 的 `post_worker_init` 钩子都会调用它：

1. `_prepare_runtime_directories()`：创建 `data/`、`logs/`。
2. `initialize_logging()`：ConcurrentRotatingFileHandler 多进程安全日志。
3. `_recover_runtime_resources()`：
   - `reset_google_sheet_token_occupancy()`：清零 Token 占用计数
   - `reset_google_sheet_occupancy()`：清零 Sheet `is_in_use`/`current_task_id`
   - `cleanup_stale_backtest_sheet_run_locks()`：清理非 running 任务的 `BacktestSheetRunLock`
4. `check_and_cleanup_dead_tasks(app)`：DB 中 `running` 但本进程无线程的任务重置为 `pending` 并写日志。
5. `_start_background_components(app)`：
   - `init_scheduler(app)`：`scheduler_service.start(delay_seconds=30)` + `create_default_tasks()`（默认"每日数据清理" cron `0 0 * * *`）
   - `init_task_watchdog(app)`：看门狗独立 daemon 线程

> **注意**：`bootstrap_app` 中 `_initialize_database_schema()`（db.create_all + 13 个 ensure_* schema 修补）保持注释状态——常规启动**不建表**，新环境需先 `flask init_db` / `flask db upgrade` 或 `python run.py init-db`。`_initialize_system_metadata()`（init_config 默认配置 + init_rbac 含默认管理员 admin/admin123 + 导航菜单）**每次启动幂等执行**，并顺带清理历史遗留的接口级权限行。修改启动逻辑前先读 `app/startup.py` 确认实际状态。

### 运行模型与扩容约束

任务线程、APScheduler、看门狗都是**进程内单例**，因此 `dockers/gunicorn.conf.py` 强制 `workers=1, max_requests=0`。横向加 worker 会导致重复调度和 Token 互抢，扩容前必须先把任务执行拆成独立 worker。

## 双前端并存

- **Vue 新前端**（frontend/）：覆盖任务管理、admin 面板、回测列表等主要路由，构建产物 dist 由 Nginx 托管，API 经 Nginx 反代到 Flask:5000。
- **Jinja 旧前端**（templates/ + static/）：仍由 Flask 直接渲染，承载登录页、backtest_training / backtest_multi_product / google_sheet 各 create+detail 页、xpl、admin 部分页面、yule 等。

两套前端调用同一批后端 API。修改后端接口时必须同时确认两侧页面的影响。
