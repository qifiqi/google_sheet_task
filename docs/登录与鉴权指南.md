# 登录与鉴权指南

实现位于 `app/utils/auth.py`，模型与初始化在 `app/models.py` / `app/startup.py::init_rbac`（`PERMISSIONS` 定义在 `app/config.py`）。

## JWT 双 Token

- `create_access_token`：2 小时；`create_refresh_token`：7 天。HS256，secret 优先取环境变量 `JWT_SECRET_KEY`（与启动校验同源），未配置时回退 SystemConfig（缺省 `DEFAULT_JWT_SECRET`）。
- payload 含 `user_id`、`token_version`、`type`。

## 接口（auth_api_bp，前缀 /api）

| 端点 | 说明 |
|---|---|
| `POST /api/auth/login` | 登录，返回 access/refresh token |
| `POST /api/auth/refresh` | 滑动续期：同时轮换返回新 access_token 与新 refresh_token |
| `GET /api/auth/me` | 当前用户信息 |
| `POST /api/auth/logout` | 登出 |
| `PUT /api/auth/password` | 改密码 |
| `/api/admin/users` `/roles` `/permissions` | 用户/角色/权限管理 |

## 会话吊销（token_version）

**登录不递增版本号**——同一账号多端登录互不影响。`User.token_version` 仅在改密码、管理员重置密码或登出时递增，使该用户**所有已签发 token 立即失效**。活跃用户经 refresh 滑动续期，不会被 7 天硬上限强制下线。`login_required` 解析 Bearer token → 校验类型/过期 → 加载 User（必须 `is_active`）→ 校验版本 → 写入 `g.current_user`。

## AUTH_ENABLED 开关

- `AUTH_ENABLED=false` 仅允许 development 环境，运行期注入拥有全部权限的 `_MockUser`。
- 生产/测试环境校验在 `create_app()` 的 `validate_auth_runtime_settings()`：`JWT_SECRET_KEY` 用默认值或关闭鉴权直接 RuntimeError（fail fast）。

## RBAC 模型

`User` M2M `Role` M2M `Permission`（code 形如 `资源:操作`）。`PERMISSIONS`（app/config.py）现仅含页面权限 `page:admin:*` 等条目；接口级权限码（task:view、backtest:view 等）已从代码中移除，历史库中的行由 `init_rbac()` 幂等清理。`init_rbac()` 幂等同步内置权限、admin/developer 角色、默认账号 `admin/admin123`。

## 当前鉴权现状（重要）

- **接口级细粒度权限已整体移除**：`permission_required` 装饰器与 `app/utils/task_authorization.py` 均已删除，`PERMISSIONS` 只保留页面权限（`page:*`）。接口统一只受 `login_required` 保护，实际访问控制依赖页面/导航权限：
  - 后端导航菜单按 `permission` 字段过滤（`NavigationMenuItem`，见 `app/navigation.py`）
  - `init_rbac()` 启动时幂等清理历史遗留的非 `page:*` 权限行及其角色关联
  - Vue 前端路由守卫按 `meta.permission` 校验，无权限跳 `/403`（见 [前端Vue工程.md](前端Vue工程.md)）

## 默认账号与安全提醒

- 默认账号 `admin/admin123`，首次部署后**必须改密**。
- 生产环境务必设置强随机 `JWT_SECRET_KEY` 与 `SECRET_KEY`（否则启动直接失败）。
- token 通过 `Authorization: Bearer <access_token>` 头传递；前端 401 时自动用 refresh token 刷新并重放请求。
