# 任务系统与调度

## 任务门面（app/services/task/）

对外入口仍是 `TaskManager` / `task_manager`，真实实现在 `app/services/task/facade.py`，由 7 个 Mixin 组合：

| 模块 | 职责 | 关键函数 |
|---|---|---|
| creation.py | 建任务、C31 批量拆分、配置规范化 | `create_task` / `create_and_start_task` / `batch_create_and_start_task` / `create_restart_task` |
| runtime.py | 启动线程与执行壳（825 行核心） | `start_task` / `_execute_service_task` / `_finalize_task_execution` |
| restart.py | 取消、重启（断点续跑）、删除 | `cancel_task` / `restart_task` / `delete_task` |
| occupancy.py | Sheet/Token 占用与校验 | `ensure_google_sheet_occupancy` / `release_google_sheet_occupancy` / `validate_backtest_training_sheet` |
| query.py | DB 状态与本地线程协调 | `TaskQueryService.check_local_task_status` |
| logs.py / results.py | 任务日志与结果查询 | `add_task_log` / `get_task_results` |
| dashboard_query.py / runtime_view.py / data_cleanup.py / error_handling.py | 仪表盘、运行态视图、结果清理、错误记录 | — |

`tests/archive/legacy_services/task_manager.py` 只是历史兼容层，不是生产实现。

### 进程内运行态（TaskManager.__init__）

- `running_tasks: dict[task_id, threading.Thread]`
- `task_stop_events: dict[task_id, threading.Event]`（取消信号）
- `start_errors: dict[task_id, str]`
- `task_token_occupancy: dict[task_id, token_id]`
- `backtest_sheet_start_lock: threading.RLock`（回测 Sheet 锁的进程内互斥）

`get_runtime_snapshot()` 输出以上快照，管理后台用于排障。

### 任务类型（TaskType）

`google_sheet`（C3，c31 归一为它）、`google_sheet_C4`、`google_sheet_C5`、`google_sheet_C7`、`backtest_training`、`backtest_multi_product`、`model_summary_rebuild`（系统类型）。

## 任务状态机

```
pending ──start_task──▶ running ──▶ completed
   ▲                      │ ├──▶ error
   │                      │ └──▶ cancelled（cancel_task 或 stop_event）
   └── dead task 清理 / restart 回滚 / watchdog 强制重启前置
error ──watchdog restart(resume)──▶ running
```

- 可编辑状态：pending / completed / cancelled / error（不含 running）。
- `error_message` 同时承担"用户可见错误摘要"与"看门狗自动恢复信号"（`[NETWORK_RETRYABLE]` 等前缀），不要覆盖成无结构 traceback。统一错误工具在 `app/utils/task_error_utils.py`。

### start_task 关键约束（runtime.py）

1. 仅 `status=='pending'` 可启动，拒绝重复启动。
2. 回测类型在 `backtest_sheet_start_lock` 内检查同 Sheet 是否有任务在跑，抢占 `BacktestSheetRunLock`（DB 表，spreadsheet_id 唯一，IntegrityError 兜底）。
3. 受 `max_concurrent_tasks` 限制；占用 Google Sheet 注册表（`google_sheet_registry_service.acquire_for_task`）。
4. Token 校验 + 占用计数（`google_sheet_token_service.validate_task_start` / `increment_usage`）。
5. 按 task_type 建线程执行对应服务；失败回滚全部占用与状态。

### 执行壳与"代际保护"

`_execute_service_task` 统一：标记 running（非 C3 用原子 UPDATE 防并发）→ 实例化 `service(task.config, task_id, app, stop_event)` → `execute_task()` → `_finalize_task_execution`（**取消信号优先于返回值**，决定 cancelled/completed/error）→ finally 中释放 Token/Sheet 占用与回测锁。

**代际保护**：收尾前比较 `running_tasks[task_id] is current_thread`。被看门狗替换掉的老线程不再写任务状态、不释放新一代的占用，避免状态互踩。

### 回测任务串行接力

同 Sheet 的回测任务冲突时新任务保持 pending 排队；前一个任务 finally 中调用 `_start_next_pending_backtest_task` 自动接力启动下一个。

## 断点恢复与重启（restart.py）

- `cancel_task`：set stop_event；pending 任务直接释放占用。
- `restart_task(resume_from_checkpoint=True)`：保留 `current_step` / `start_time` 断点续跑；非断点模式先 `clear_task_execution_data` 清历史结果。回测类型如同 Sheet 有任务在跑则置回 pending 排队。
- `check_and_cleanup_dead_tasks`（startup.py）：DB=running 但本进程无线程的任务重置为 pending。
- `check_local_task_status`：DB=running 且内存无线程 → 可重启（原因：内存无线程）；有线程时日志静默超过 `task_status_check_timeout`（默认 600s）才允许重启。

## 看门狗（task_watchdog.py）

独立 daemon 线程，专属日志 `logs/task_watchdog.log`。每次循环从 config_manager 读运行参数：`watchdog_enabled`、`watchdog_interval_seconds`（默认 1800）、`watchdog_log_timeout_minutes`（默认 30）、`watchdog_force_restart_wait_seconds`（45）、`watchdog_max_restart_attempts`（3）。

### 扫描范围与目标

只处理**最近 5 天创建**的任务（`WATCHED_TASK_CREATED_WITHIN_DAYS`），三类：

1. `running` 且日志静默超阈值（或从未写过日志且 start_time 已超时）；
2. `error` 任务按 error_message 前缀分类：`[NETWORK_RETRYABLE]` → 网络重启；`[GOOGLE_SHEET_RETRYABLE]` → Sheet 执行重启；其余普通 error；
3. `cancelled` 且带 `[WATCHDOG_FORCE_RESTART]` 前缀（上次强制重启失败的兜底）。

### 强制重启与防无限重启

- attempt 计数 = max(内存缓存, error_message 中 `attempt=N/M` 解析值)。
- 超过 `watchdog_max_restart_attempts` → `_abandon_task`（置 error，前缀"watchdog 已放弃自动重启"）。
- 强制重启流程：set stop_event → 最多等 45s join 线程（超时 detach）→ 释放回测锁/Token/Sheet 占用 → 置 pending → `start_task`；启动失败标 cancelled 带 `[WATCHDOG_FORCE_RESTART] attempt=N/M` 供下轮兜底。
- error 任务走 `restart_task(resume_from_checkpoint=True)`。

修改看门狗时：筛选条件压到 SQL 层、不要扫全表、不要触发无限重启循环、不要把所有失败任务都交给自动重启。

## 定时任务（scheduler_service.py）

- APScheduler BackgroundScheduler + croniter；`start(delay_seconds=30)` 延迟启动避免与应用启动争抢。
- 任务定义存 `ScheduledTask` 表（name、cron_expression、task_function、task_params、is_active、is_running + running_instance_id 防并发）。
- 内置 job：`_cleanup_old_logs` / `_cleanup_old_results` / `_cleanup_old_data`（按 task_function 名分发，支持独立进程执行 `scheduled_task_worker.py`）。
- 默认任务："每日数据清理" cron `0 0 * * *`，清理 10 天前任务日志（结果清理 `_cleanup_old_results` 当前在 `_cleanup_old_data` 中注释停用）。
- 管理 API：`/api/admin/scheduler/*`（stats / tasks CRUD / toggle / run / status）。

## 修改检查清单

改任务参数/执行逻辑时至少过四层：页面字段 → 页面回填（localStorage/模板/restart 回填）→ `task_manager` 透传（C31 到 `batch_create_and_start_task` 的 child_config）→ 最终执行 service 消费。异常处理用 `raise` 保留原链，禁止 `raise e`；失败必须写 `Task.error_message`。
