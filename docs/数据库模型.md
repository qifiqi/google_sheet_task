# 数据库模型与维护

模型全部在 `app/models.py`，表名统一 `t_param_` 前缀。部分字段由 SQLAlchemy event 自动规范化（如 stock_code 大写、market_type 小写）。

## 数据库选择

- 默认 SQLite：`sqlite:///{项目根}/instance/app.db`（app/config.py::DEFAULT_DATABASE_URL）。
- `DATABASE_URL` 切换；生产 MySQL（PyMySQL），兼容 PostgreSQL（psycopg2-binary）。ensure_* 修补兼容三种方言。
- 引擎：`pool_pre_ping=True, pool_recycle=3600`。

## 建库与迁移（重要）

本项目**不完全依赖标准迁移流**，三条路径并存：

1. **Alembic**：`flask db migrate` / `flask db upgrade`（migrations/）。
2. **CLI**：`flask --app run.py init-db` → `db.create_all()` + `normalize_boolean_columns()` + 13 个幂等 `ensure_*` 修补（app/startup.py）：google_sheet_token / google_sheet_registry（registry_scope）/ user / task / task_result / scheduled_task / task_result_return / task_log / task_result_payload / task_result_summary_index / stock_metadata / backtest_runtime / navigation_menu。`flask --app run.py init-default-config` 仅写入默认 SystemConfig；init_rbac 与导航菜单由每次启动的 `_initialize_system_metadata()` 幂等完成。
3. **常规启动**：`bootstrap_app()` 中建表与初始化**当前被注释**，只做占用恢复和死任务清理——线上脏库问题先看 `app/startup.py`。

注意：部分 ensure_* 检查的是历史表名（`user`/`tasks`/`google_sheet`），而模型实际表名带 `t_param_` 前缀，只有部分函数同时兼容——改动 schema 时先确认修补函数命中的真实表名。

## 历史修复记录（原 docs/sql 脚本内容存档）

以下修复已在线上执行过，脚本随 docs/sql 删除，内容保留于此备查：

### 2026-08-24 · task_log.message 改 TEXT（MySQL）

现象：插入超长日志报 MySQL 1406 "Data too long"。

```sql
ALTER TABLE t_param_task_logs
    MODIFY COLUMN message TEXT NOT NULL COMMENT '日志内容';
-- 验证
SELECT COLUMN_NAME, DATA_TYPE, CHARACTER_MAXIMUM_LENGTH, IS_NULLABLE
FROM information_schema.columns
WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 't_param_task_logs' AND COLUMN_NAME = 'message';
```

### 2026-08-24 · task_results 大字段扩容（MySQL）

现象：C7 结果 JSON 超过 MySQL TEXT 约 64KiB 上限。

```sql
ALTER TABLE t_param_task_results
    MODIFY COLUMN result MEDIUMTEXT NULL,
    MODIFY COLUMN parameters MEDIUMTEXT NULL,
    MODIFY COLUMN error_message TEXT NULL;
```

### 2026-08-24 · task_results_return 拆列（PostgreSQL，事务内）

把原 JSON 大字段 `returns_json` 拆为结构化列：

- 新增：`stock_code varchar(20)`、`stock_name varchar(20)`、`start_return_date date`、`end_return_date date`、`return_length integer`
- 类型转换：`stock_date`、`index_return`、`start_return` 改 text，从 `returns_json::jsonb` 的 dates / index_returns / start_returns 提取回填
- 回填规则：stock_code 空则 'UNKNOWN'，stock_name 空则 '未知股票'；start/end_return_date 取 dates 数组首/末元素（空回退 `DATE '1970-01-01'`）；`return_length = jsonb_array_length(dates)`
- 回填后置 NOT NULL、`DROP COLUMN returns_json`，并建索引 `ix_task_results_return_stock_code` / `ix_task_results_return_stock_name`

## 维护建议

- `Task.config` 是任务恢复、重启、前端回填的核心，改模型时保持其 JSON 兼容。
- `Task.error_message` 承担用户摘要 + 看门狗信号双重职责，勿写无结构 traceback。
- 大字段（result/parameters/returns）注意 MySQL TEXT 上限教训，新增大 JSON 字段考虑 MEDIUMTEXT/JSONB。
- 定期清理靠默认定时任务（每日 0 点清 10 天前任务日志，结果清理当前停用）；手工维护可用 `/api/database/vacuum`。
