# 策略回测报告模板使用说明

本文说明如何通过 Word 回测报告接口生成策略回测报告，以及模板文件的结构。

## 入口

- 接口：`POST /api/exports/backtest-reports/word`（app/routes/export_api.py）
- 服务链：`StrategyBacktestReportRequestDTO.from_payload` → `StrategyBacktestReportService.generate_word()` → Pillow 图表 → `generate_strategy_backtest_report()` 渲染 python-docx 文档
- 模板文件：`app/services/report_templates/strategy_backtest_report.json`

## 请求体要点（app/dto/strategy_backtest_report.py）

| 字段 | 说明 |
|---|---|
| `report_type` | `RPT-S` 单品 / `RPT-M` 多品 |
| `title` / `filename` | 报告标题与下载文件名 |
| 收益来源（三选一） | ① `returns` 直接传收益序列；② `task_id`（可选 `return_series_id`）从任务结果取；③ Google Sheet（`spreadsheet_id` / `sheet_name` / `google_sheet_url` 任一） |
| `products` | 仅 RPT-M：各产品各自选收益来源并指定权重，服务端按权重合成组合收益 |
| `metadata` / `runtime_params` | 报告元数据与运行参数透传 |

多品报告会把累计收益换算为日收益、加权合成后再还原为累计收益（`_cumulative_to_daily` / `_daily_to_cumulative`）。

## 模板结构（strategy_backtest_report.json）

### validation

- 必填顶层字段：`report_type`、`title`、`metadata`、`sections`、`charts`、`calculation_notes`、`conclusion`。
- `metadata` 必填：`report_id`、`model_version`、`price_type`、`generated_at`、`date_range`、`total_trading_days`、`risk_free_rate`。
- 条件校验：`RPT-M` 必须有 `weight_allocation`；`RPT-S` 也带 `weight_allocation` 但表格行数必须为 1。

### styles

- 页面：Letter 8.5×11 英寸，左右边距 1.25 英寸；正文字体 Microsoft YaHei 10.5pt，行距 1.25。
- 标题色：Title 22pt / H1 15pt / H2 12pt，主色 `1F4E79`、二级 `2F5597`。
- 表格：Table Grid，表头底色 `1F4E79` 白字，隔行底色 `F3F6FA`，**表头跨页重复、行内容禁止跨页拆分**。
- 图表：宽 6 英寸，题注 9pt 居中；页脚居中显示 `{title}`。

### blocks（渲染顺序）

1. `title` → 2. `metadata`（报告编号/模型版本/价格类型/生成日期/数据区间/总交易日/无风险利率）→ 3. `weight_allocation` 权重分配表 → 4. `sections`（正文各章节，由 service 的 `_sections` 生成）→ 5. 「九、分析图表」+ `charts` → 6. 「十、指标计算说明」+ `calculation_notes` → 7. 「十一、结论」+ `conclusion`。

章节编号（一~十一）由模板中的 `heading` 文本固定，新增章节需同步改模板 JSON 与 service 的 `_sections` 输出。

## 报告内容

`_build_report_data` / `_sections` 生成的数据表覆盖：净值与收益走势、月度/日度汇总、盈亏分布、超额收益（对比基准）、滚动收益、市场阶段、极端日、资金曲线等；图表由 `generate_report_charts` 用 Pillow 绘制（折线、分组柱状、直方图、双直方图、回撤曲线），全部指标计算复用 `XPLAnalyzer`（app/services/performance_analysis/）。

## 修改模板的注意事项

1. 改 `blocks` / `styles` 只动 JSON；但 `_render_blocks` 只支持既有 block 类型（title/metadata/text/table/sections/heading/charts/notes/paragraphs），新增类型要改 `strategy_backtest_report_template.py`。
2. `validation.required_fields` 与 service 的 `_validate_report_data` 是两道校验，缺字段会直接报错不出报告。
3. 表格宽度以 6 英寸版心估算列数，列过多的表先在 service 侧精简。
