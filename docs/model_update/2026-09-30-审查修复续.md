## 本轮修复

### 安全类

1. **P0 后端 NameError**（`app/routes/export_api.py`）：`export_model_summary`（model-summary 导出）使用 `g.current_user` 但 flask import 缺 `g`，命中该端点即 500。修复：import 行补 `g`。
2. **越权：定时任务 API 全端点仅 login_required**（`app/routes/scheduler_api.py`）：7 个端点挂在 `/api/admin/scheduler/*` 下，任何登录用户可创建/改删/立即执行定时任务（`task_function`+`task_params` 可选任意任务与参数），与同目录 `admin_api.py`/`auth_api.py` 的 `admin_required` 惯例不一致。修复：全部改 `@admin_required`（页面级仍 `page_login_required`，与其他 admin 页一致）。前端调用方仅 `admin_scheduler.js`（admin 页）与 Vue SPA `Scheduler.vue`（路由带 permission meta），无误伤；测试无直接命中该端点的用例。
3. **XSS：任务日志 message 未转义**（`static/js/common/business/task-polling.js`）：`log.message` 含任务参数/Sheet 标题等外部输入，直接拼 innerHTML（C4/C5/C7 三个详情页共用）。修复：过 `escapeHtml`（utils.js 加载顺序在前已保证）；`level` 走固定映射、`formatTime` 输出为本地化日期串，均安全。
4. **XSS：通知 message 未转义**（`static/js/template-auth.js` `showNotification`）：调用方约 30 处，大量传入 `error.message`/`data.message` 等服务端回显文本（可含用户可控的任务名/Sheet 标题），直接进 innerHTML。所有调用方均为纯文本（无故意传 HTML），修复：函数内统一过本地 `escapeHtml`，一处覆盖全部调用点。
5. **XSS：导航菜单 label/path 未转义**（`static/js/template-auth.js` `renderSidebarMenu`/`renderTopMenu`）：`/api/meta/nav` 返回的 label/path（DB 管理）直接拼 innerHTML 与 href。修复：插值处全部过 `escapeHtml`；`filterTemplateNav` 新增 `isSafeNavPath`（仅允许单个 `/` 开头的站内路径，同 `sanitizeNextUrl` 策略），拦截 `javascript:` 等协议——path 字段契约为"前端路由路径"（`app/models.py` NavigationMenuItem），无绝对 URL 合法场景。`isItemActive` 仍用原始 path 比较，不受转义影响。

### 功能类（复核确认后修复）

6. **C4 重启回填缺 5 字段 + date_range_mode 选择器永失效**（`static/js/pages/google_sheet_c4_create.js` `loadRestartConfig`）：重启路径只回填了 market_type；`count_mode`/`kline_adjustment`/`kline_data_source`/`start_date`/`end_date` 全部丢失，日期还会被 `initDefaultDatesIfEmpty` 的默认区间（近 5 年）静默替换——重启后的任务与原任务参数不一致。`date_range_mode` 旧代码按 `input[name="date_range_mode"][value=...]` 查找，但复选框只有 id 无 name，且 config 里是数组，选择器永远匹配不到。修复：对齐模板回填路径 `fillFormWithTemplate` 的写法，date_range_mode 改走共享助手 `Biz.formState.applyDateRangeModes`。
7. **多品全局预览 XLSX 导出缺脏拦截**（`static/js/pages/backtest_multi_product_global_preview.js` `exportPreview`）：比例/无风险利率修改后未点"计算预览"时，Word 路径（`openExportWordModal`）有 `ratioInputsDirty` 守卫，XLSX 路径没有——ratios 被静默丢弃、按已存储旧值导出，且无风险利率带的是新值，口径自相矛盾。修复：补同款守卫（提示改为"再导出 Excel"）。
8. **admin 配置校验弹窗不出现且异常被吞**（`static/js/pages/admin_config.js` `validateConfig`）：`ajaxRequest` 返回完整信封，校验体应为 `data.data.validation`，原代码漏拆一层读 `data.validation` → undefined → 模板串取属性抛 TypeError，发生在 promise 回调里被吞，用户点"校验配置"无任何反馈。修复：改为 `data.data.validation`，空对象兜底。
9. **C31 部分子任务启动失败仍提示无条件成功**（`static/js/pages/google_sheet_c31_create.js`）：后端 `batch_create_and_start_task()` 只要 ≥1 个子任务启动成功就返回成功信封，data 里的 `failed_to_start/total_created/total_started` 被前端全部丢弃，toast 写死"任务创建成功"。修复：按计数区分——有失败时 warning 提示"成功启动 M/N，请到任务列表查看"。
10. **admin 结果页分页可键盘越界**（`static/js/pages/admin_results.js`）：prev/next 只加 Bootstrap disabled class（`pointer-events:none` 仅挡鼠标），键盘 Tab+Enter 仍触发 `loadResults(0)`/`loadResults(pages+1)`，且越界后 next 判据失真可无限继续。修复：`loadResults` 入口拒绝越界页码（新增 `lastTotalPages` 在 `updatePagination` 里维护）。

### 上一批遗留（本轮一并提交）

11. **基准比例裸数字陷阱**（`static/js/pages/backtest_multi_product_global_preview.js` ~841）：弹窗导出 Word 的 ratio 显式带 `%` 提交——裸数字 ≤1 会被后端 `_normalize_index_benchmarks` 判为小数比例 ×100（0.5 → 50%）。
12. **V2 无风险利率无边界钳制**（`static/js/pages/performance_analysis_v2.js` `collectV2RuntimeParams`）：HTML min/max 不拦手输越界值，负数/超 100 直达夏普计算；钳到 [0,100] 再 /100，与弹窗导出侧口径一致。

## 复核为误报、不修（登记）

- **编辑配置"整页提交覆盖"**：`saveEditedConfig` 只提交单条配置的 value/description（PUT `/api/system-configs/<key>`），后端单行增量字段更新，不存在跨行丢失更新；仅同 key last-write-wins，属常规取舍。
- **sheets 编辑回填被远端覆盖**：编辑模态框回填是纯同步本地操作，远端刷新只重绘表格不触碰表单，且无轮询，时序不成立。
- **其余手写分页 prev/next**：除 admin_results.js（已修）外，admin_tasks/backtest 四页/google_sheet 三页均有 disabled 属性或 JS guard，双重防护完备。

## mimosa 深度扫描分诊（31 项，全部闭环）

扫描：`scan-2026-09-29T20-12-28.928Z-04e1c30737e5`（deep，seal `sha256:302ee9ea…`，run status inconclusive/静态边界）。分诊结论：

- **13 项 LOW"不安全的随机数"**：全部为重试退避抖动（`db_retry`/`qq_api` 的 `random.uniform`）、UA 轮换（`random.choice(_USER_AGENTS)`）、爬虫接口 nonce（`dfcf_api` 的 `get_ut`/jQuery 回调名），无安全敏感随机用途（无令牌/密码派生）。接受。
- **16 项"SSRF"（HIGH/MEDIUM）**：两类。① 前端 api.js 的 post/put/del/envelope 被建模为 ssrf sink——实际是浏览器端同源固定路径请求（`/api/exports/...` 等常量模板 + 任务 ID 插值），攻击者无法控制 host/scheme，浏览器前端不构成 SSRF；② `ding_talk_notifier.py:216` 动态 URL——`base_url` 为硬编码 `https://oapi.dingtalk.com/robot/send`（:30），仅查询串拼接。均误报。
- **2 类 XSS 入口（showNotification/renderSidebarMenu）**：即本轮第 4、5 项已修点，扫描器不识别 `escapeHtml` 净化器，修复后污点链已在 sink 处断开。
- 扫描器自述覆盖缺口（"部分分析阶段未能完整覆盖"），本报告不构成全面安全结论。
