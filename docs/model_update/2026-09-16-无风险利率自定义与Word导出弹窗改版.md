# 修改文档：无风险利率自定义 + Word 导出弹窗改版

- 日期：2026-09-16
- 分支：dev_vue
- 范围：绩效分析（performance_analysis）V1 指标引擎、Word 报告导出弹窗
- 性质：新增可配参数 + 前端弹窗重排，**不修改数据库 schema/迁移/数据**

## 背景

夏普比率的无风险利率此前硬编码为 0（`metrics.py` 计算注释自述"假设无风险利率为0"），Word 报告元数据表的"无风险利率"行因前端从不传值恒显示 `0.00%`。本次在导出 Word 弹窗增加自定义无风险利率输入，后端重算与报告展示同时生效；弹窗借机重排解决拥挤问题。

## 口径决策（按确认执行）

1. **生效范围**：弹窗值随导出请求进入 Word 报告的指标重算链路（`generate_word → _build_benchmark_runs → V1 引擎`）；页面 `/performance_analysis/analyze` 等分析接口保持默认 rf=0（DTO 已支持该字段，未来前端传值即可生效，无需再改后端）。
2. **单位**：弹窗按百分比填写（3 = 3%），payload 内统一转小数（0.03），与现有 runtime_params 阈值口径一致；报告元数据以百分号文本（`3.00%`）展示。
3. **其他 Word 导出入口**（回测训练结果页 / 多品结果页 / 全局预览页，均无弹窗直连下载）维持 rf=0 默认；RPT-M 请求在 `export_backtest_word` 内按任务重建 payload，行为不变。

## 代码改动

### 后端

| 文件 | 改动 |
|---|---|
| `app/services/performance_analysis/request_dto.py` | `MetricsRuntimeParamsDTO` 新增 `risk_free_rate: float = 0.0`；`from_raw` 支持数字/字符串解析，非数字与非有限值分别报错（"无风险利率必须是数字/有限数字"） |
| `app/services/performance_analysis/metrics.py` | `calculate_sharpe_for_period` 增加第 4 参 `risk_free_rate=0.0`，公式改为 `(平均月收益 − rf/年化因子) × 年化因子 / 年化波动率`（即 `(年化收益 − rf) / 年化波动率`）；`calculate_sharpe_ratios_by_periods` 同名透传至全部/分年/滚动年三处调用；`_calculate_metrics_v1` 从 `runtime_params.risk_free_rate` 取值传入指数、策略两列夏普计算 |

- `text_analysis.py`（粘贴文本 analyze 链路）不传 rf，走默认 0，历史行为不变。
- `strategy_backtest_report_service.py` 无需改动：`_runtime_params` 本就走 `MetricsRuntimeParamsDTO.from_raw`，rf 自动随 `request.runtime_params` 进入重算；元数据展示行本就读 `metadata.risk_free_rate`（缺省回退 `0.00%`）。

### 前端

| 文件 | 改动 |
|---|---|
| `templates/performance_analysis/v2.html` | `word-export-options-modal` 重排：标题改"导出 Word 报告"、弹窗垂直居中（`modal-dialog-centered`）；价格类型与无风险利率并排一行（`row g-3`，sm 断点以下自动堆叠）；新增 `#word-export-risk-free-rate` 数字输入（0～100，step 0.01，带 `%` 后缀，默认 0） |
| `static/js/pages/performance_analysis_v2.js` | 新增 `readWordExportRiskFreeRate()`（百分比输入校验：有限数字且 0～100，非法弹警告并中止）；`confirmWordExport()` 双通道注入——`metadata.risk_free_rate = "X.XX%"`（报告展示）+ `runtime_params.risk_free_rate = 小数`（后端重算） |

### 数据流（导出一次的完整路径）

```
弹窗输入 3% → confirmWordExport
  payload.metadata.risk_free_rate = "3.00%"      ── 报告"无风险利率"行展示
  payload.runtime_params.risk_free_rate = 0.03   ── _runtime_params → DTO → V1 引擎夏普分子
→ POST /api/exports/backtest-reports/word（RPT-S 不重建 payload，双通道直通）
→ generate_word → _build_benchmark_runs → calculate_v1_metrics(runtime_params)
→ metrics.calculate_sharpe_ratios_by_periods(..., risk_free_rate=0.03)
```

## 兼容性与影响面

- **默认行为完全不变**：`risk_free_rate` 缺省 0.0，公式 `avg − 0/12` 在浮点上与原式逐位一致，存量报告/测试的夏普值不受影响。
- **Word 导出缓存无需处理**：缓存键为整个 payload 的规范化 JSON 哈希（`app/utils/ttl_cache.py`），rf 变化自动产生新键。
- **不涉及**：数据库、C 系任务执行链路、看门狗、token 占用。

## 测试

- 扩展 `test_runtime_params_from_raw_parses_and_validates`：rf 字符串解析（`"0.03"`）、非法值（`"abc"`、`NaN`）报错。
- 新增 `test_calculate_sharpe_for_period_subtracts_monthly_risk_free_rate`：锁定公式（rf=0 时退化为历史口径；rf=3% 时严格下降 `rf/年化波动`）。
- 新增 `test_v1_metrics_applies_risk_free_rate_to_sharpe`：端到端验证 `runtime_params.risk_free_rate` 进入 V1 引擎指数/策略两列夏普（近似断言 rel=1e-4，吸收结果投影 6 位小数舍入）。
