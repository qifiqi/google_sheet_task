# 修改文档：多品全局预览「计算预览」接入无风险利率 + 比例工具栏对齐修复

- 日期：2026-09-18
- 分支：dev_vue
- 范围：多品全局预览页（比例设置面板 / Excel 导出 / Word 弹窗默认值 / GET 预览）、绩效分析 V2「参数配置」页签、预览指标口径后端链路
- 性质：口径打通 + 布局修复，**不修改数据库 schema/迁移/数据**

## 背景

无风险利率此前只在三个 Word 导出弹窗里生效（9-16 夏普、9-17 索提诺 + 单产品/多品入口）：
页面上看到的「比例计算-指数 / 比例计算-结果」两列与组合指标恒为回测执行时的口径（rf=0），
用户改了无风险利率，只有从导出的报告里才能看到差异。

本次把无风险利率提升为**预览口径**的一部分：与比例同级，随「计算预览 / 保存比例 / GET 预览 /
Excel 预览导出」一起传给后端并据此重算；后端在开始计算（或命中缓存）时各打一条 INFO 日志，
便于对账"页面看到的指标是按哪个口径算的"。

同时修复比例设置工具栏的布局缺陷：新加的无风险利率输入框在常见宽度下与「参数方案」下拉、
「计算预览」按钮不在同一行/同高（实测数据见「布局修复」节）。

## 口径决策

1. **rf 与比例同级**：计算预览（`POST .../calculate-ratios`）、保存比例（`PUT .../ratios`）、
   GET 预览（`GET .../global-preview/<task_id>?risk_free_rate=`）、Excel 预览导出
   （`GET /api/exports/global-preview/<task_id>?risk_free_rate=`）都携带；导出的 Excel 与页面
   看到的「比例计算」两列同源。
2. **rf=0 不带参数**：前端 `riskFreeQuerySuffix()` 在 0 时返回空串，缺省请求与历史逐字一致
   （URL、响应体、缓存键、日志值都不变）。
3. **生效范围**：比例后单产品指标（「模型结果（x%）」列）与组合指标（「比例计算」两列）。
   单品「指数 / 模型结果」是回测执行快照，不随此处变化——页面提示文案已写明这一边界。
4. **存档快照不得混用**：rf≠0 时即便比例未变，也按收益序列重算比例后指标；缺收益序列的旧结果
   仍回退存档值（否则同一行会同时出现 rf=0 与 rf≠0 两套口径）。
5. **缓存隔离**：预览缓存键加入运行参数签名 `_preview_runtime_signature()`；新增参与预览计算的
   运行参数必须同步加进该元组，否则不同口径会命中同一份缓存。
6. **显示值 = 计算值**：载荷回显 `runtime_params.risk_free_rate`，页面按它回填输入框，
   避免"界面显示 3% 而指标按 0 算"。
7. **单位**：页面按百分比填写（3 = 3%），请求统一转小数（0.03），与绩效分析 V2 的阈值口径一致；
   非法输入（非数字 / 超出 0～100）前端 alert 中止，后端 400（与绩效分析同一套报错文案）。
8. **日志**：`多品全局预览开始计算/Global preview compute start` 与
   `多品全局预览命中缓存/Global preview cache hit` 各一条 INFO，字段含 task_id、产品数、
   成功结果数、权重数组、加权方式、risk_free_rate（小数点后 4 位）。

### 布局修复（「没对齐」）

根因：`.ratio-toolbar` 是单行 flex（`align-items: center; flex-wrap: wrap`），提示文案
`.ratio-formula-hint` 也在同一行且 `flex: 1`。提示文案随本次新增 rf 说明行变成 4 行后：

- 宽度不足时按钮被挤到下一行——实测 1200px 视口：`计算预览` 落到下拉框下方并左对齐；
- 更常见的是提示文案折行变高（1280px 视口下高 198px），成为行内最高元素，
  `align-items: center` 把下拉 / 输入框 / 按钮按该高度垂直居中，控件上下留下大片空白。

修复：工具栏拆两行——`.ratio-toolbar-controls`（方案下拉 / 无风险利率 / 计算预览，按钮 `ms-auto`
右贴边）+ 独占一行的提示文案；`≤991.98px` 断点仍按列堆叠（媒体查询改指向 `.ratio-toolbar-controls`）。

验证方式：Chrome headless 渲染**真实模板片段 + 真实 CSS**（`bootstrap.min.css` / `theme.css` /
`backtest_multi_product_global_preview.css`），脚本量取 `getBoundingClientRect`：

| 视口宽度 | 修复前 | 修复后 |
|---|---|---|
| 1600 / 1440 / 1366 | 同行、但被高提示块垂直居中 | 同行同高 ✓ |
| 1280 | 提示块高 198px，控件被居中拉偏 | 同行同高 ✓ |
| 1200 | 按钮换行到下拉下方 | 同行同高 ✓ |
| 1100 | 按钮换行（第三行） | 同行同高 ✓ |
| ≤991.98 | 按列堆叠（设计如此） | 按列堆叠（不变） |

修复后 1600/1440/1366/1280/1200/1100 六档下 `#groupSelect`、`.risk-free-field`、
`#calculateRatiosBtn` 的 `top` 与 `height` 完全一致（`top=24.0 h=38.0`），
标签与输入框中线均为 43.0。

## 影响面与兼容性

- **默认行为零变化**：不带 `risk_free_rate` / `runtime_params` 的请求与历史逐字段一致
  （rf=0 时 `(avg − 0/N) × N` 在浮点上与原式逐位相同），存量页面、脚本、测试不受影响。
- 不涉及数据库、C 系任务执行链路、看门狗、token 占用；提示文案与输入框为新增 DOM，
  原有 `data-index`、`.ratio-input` 结构与交互未动。
