# 2026-09-30 单产品全局预览导出 Word（弹窗选择参数结果）

## 需求

对齐多产品全局预览页的「导出 Word」能力：单产品回测（backtest_training / C 系列）
自己的全局预览页 `/backtest-training/global-preview/<task_id>` 此前只有 XLSX 与收益序列
导出，本次新增「导出 Word」。单产品任务一个股票下有多个参数方案（每条成功结果一列），
导出时弹窗列出参数、由用户**选择导出哪个参数的结果**，输出单个 RPT-S 文档。

不新增接口——复用多产品页同一个 Word 回测报告端点 `POST /api/exports/backtest-reports/word`
（RPT-S + `task_id` + `return_series_id`，`StrategyBacktestReportService._returns_from_task`
对多条序列要求必须传 `return_series_id`，本弹窗恰好逐结果精确指定）。

> 同日的 `/global-preview/single-product`（预览中心）已有一版「导出 Word」：
> 循环导出**全部**成功结果、逐个下载、无弹窗。该行为保持不变；本页是按参数
> 单选导出的平行入口，二者互不影响。

## 后端（无新端点）

- `app/services/backtest_report_query_service.py`：
  - 新增公开构建器 `build_single_product_word_report_payload(task_id, task_config, return_series_id, return_series)`：
    按任务配置（sheet 标题 → 模型版本、price_mode → 价格类型文案）与结果收益序列
    构造 RPT-S 请求载荷，结构与 `/backtest-training/api/task-result/<id>` 下发的
    `word_report_payload` 完全一致；
  - `_build_global_preview_payload_from_results` 的每个结果列（column）新增
    `return_series_id` 与 `word_report_payload`（仅 `success && return_series_id` 的列
    附带，其余置 None），预览页前端因此拿到与结果详情页同源的导出载荷；
  - 消费方（Excel 导出、按股票拆分 ZIP）忽略多余键，行为不变。
- `app/routes/backtest_api.py`：`get_task_result_detail` 的内联 `word_report_payload`
  构建改为调用上述共享构建器（字段逐值等价，消除两处漂移），并移除随之不再使用的
  `get_backtest_model_version` / `get_price_type` 局部导入。

## 前端（老模板）

- `templates/backtest_training/global_preview.html`：
  - 工具栏在「导出收益序列」旁新增「导出 Word」按钮（`btn-outline-info`，与多产品页同款图标）；
  - 新增 `#exportWordModal` 弹窗：参数单选列表（`#wordExportParamList`，仅当前分组下
    带收益序列的成功结果）+ 价格类型下拉（跟随任务/五种取值，同训练结果页）+
    无风险利率输入（百分比，默认 0，用于夏普重算，仅影响本次导出）。
- `static/js/pages/backtest_training_global_preview.js`：
  - `openExportWordModal`：当前分组无可导出列（成功且带 `word_report_payload`）时
    alert 提示；否则渲染参数单选列表（默认选中第一条）后弹出；
  - `confirmExportWord`：取选中列的 `word_report_payload` 深拷贝，按训练结果页同款
    双通道合并弹窗选项（`metadata.risk_free_rate` 展示文案 + `metadata.price_type`
    覆盖展示行 + `runtime_params.risk_free_rate` 小数重算），POST
    `Api.endpoints.export.wordReport` 后按 Content-Disposition 触发下载，导出中
    按钮转 spinner、成功后收起弹窗；
  - 价格类型取值 ↔ 文案映射 `WORD_PRICE_TYPE_LABELS` 与后端 `get_price_type` 一致。

## 测试

`tests/integration/test_global_preview.py` 新增两例：

- `test_global_preview_columns_carry_word_report_payload`：成功+收益序列列携带
  RPT-S 载荷（return_series_id / products（序列自身代码名）/ model_version /
  price_type），失败列置 None；
- `test_single_product_word_export_uses_selected_return_series`：POST Word 报告端点
  （RPT-S + task_id + return_series_id + 弹窗覆盖项），断言 200、DOCX MIME、
  generate_word 收到精确指定的收益序列与合并后的 metadata/runtime_params。

全量回归 `tests/unit tests/integration`：与改动前基线对比无新增失败
（既有失败均为联网 K 线/图表渲染等环境类问题，含
`test_global_preview_recalculates_missing_legacy_metrics_from_return_series`
这一经验证的本机既有失败）。
