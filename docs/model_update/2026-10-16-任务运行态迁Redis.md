# 任务运行期中间态迁 Redis（db-to-http 方案 B）

- 日期：2026-10-16
- 分支：`dev_db_to_http`
- 设计登记：`docs/design/db-to-http-migration/README.md` §3 / §6.2 / §8.1.1、`02-remote-incremental-endpoints.md` E9

## 1. 背景与目标架构

迁移前，任务执行链的中间态全部经仓储落库（db 模式直写本地库、http 模式走远程
CRUD 仍落主站库），其中两类是高频写放大源：

- **每组合进度写**：`task.current_step/total_steps` + `commit_with_retry()`，C3/C4/C5/C7/回测
  每个参数组合一次；http 模式下实际是"读全行-合并-写回"的远程 ModifyOrAdd（带 config 大字段），
  且此前因 `RemoteRecord` 内存改 + 空 commit 而**静默失效**。
- **每条业务日志实时写 TaskLog**：`base._save_to_database` / `add_task_log`，运行期逐条 commit。

**方案 B 目标形态**：数据库在任务执行期只保留三个**瞬时里程碑**——创建 pending、
启动 running（一次写）、结束终态快照；**持续中间态**（每组合进度、业务日志、取消标志、
心跳）全部落 Redis；任务结束时一次性回灌数据库并清键。保留的 DB 触点仅：

| 触点 | 位置 | 说明 |
|---|---|---|
| 任务创建 | `creation.py` | pending 行 |
| 启动 running 标记 | `runtime._mark_task_running` / `mark_running_if_pending` | 每任务一次（任务列表/统计/钉钉查询面零改动的前提） |
| 结果保存 | `_save_task_result → create_with_return` | 每组合一次（业务数据，非中间态） |
| 终态快照 | `_finalize_task_execution → sync_snapshot` | status/end_time + Redis 进度回灌 + 日志批量回灌 |
| 占用/锁释放 | occupancy / registry / 回测锁 | 既有收尾链不变 |

## 2. 新增核心模块

**`app/services/task/runtime_state.py`**（零 Flask 依赖，与 `app/adjudication.py` 同级）：

- 键布局（命名空间沿用 `REDIS_NAMESPACE`，默认 `arb:gstask`）：
  - `{ns}:rt:{task_id}:state` Hash：`status / current_step / total_steps / error_message / start_time / heartbeat_at`
  - `{ns}:rt:{task_id}:logs` List：JSON 日志行，LPUSH 最新在前 + LTRIM 截断（`TASK_RUNTIME_LOG_MAX`，默认 1000）
- 生命周期：线程启动 `mark_running` 建态（**进度以任务行当前值播种**，断点恢复窗口崩溃对账不回退）
  → 运行期 `update_progress / append_log / request_cancel`（每次写续期 TTL 7 天兜底）
  → 结束 `sync_snapshot`（进度+日志回灌 DB、drop）；异常收尾 `sync_snapshot`（不带终态，
  终态已由 `record_task_exception` 直写）；进程崩溃残留由启动对账 `reconcile_all_runtime_states` 回灌。
- 降级：`REDIS_URL` 未配置 / redis 缺失 / 连接异常 → 进程内存 dict（单 worker 语义完整；
  多副本跨进程视图失效，与裁决层降级口径一致，warn 一次）。
- 单测：`tests/unit/test_runtime_state_store.py`（FakeRedis 替身 + 内存后端 + 回灌 monkeypatch，14 例）。

## 4. 行为变化（对外可感知）

1. 运行中任务的日志/进度在轮询接口视角不变（查询面已叠加运行态）；**日志历史截断**：
   结束后 TaskLog 保留最近 `TASK_RUNTIME_LOG_MAX`（默认 1000）条运行期日志 + 编排日志，
   超出部分不再落库（原先全量落库）。
2. 取消响应路径：`cancel_task` 仍即时写 DB 终态行；执行链停止信号从"逐组合查库"变为
   "读运行态取消标志"，取消后运行态由收尾快照清理。
3. 断点恢复数值更可靠：结束快照/启动对账会把最终进度回灌任务行，重启恢复读到的是
   上次真实断点（此前 http 模式进度从未落盘）。
4. 进度条实时性：心跳（`heartbeat_at`）随每次进度/日志写更新，`status-check` 的
   "N 分钟无更新判挂死"比原"最新日志时间"更准确。

## 5. 例外与边界登记

- **model_summary 索引重建任务**不接入运行态存储（批量粒度进度、自带终态收尾、
  不走任务运行时），保持落库；其 http 模式缺口随 §6 登记。
- **看门狗仍停用**；恢复启用前需把"最新日志时间"心跳改为读运行态 `heartbeat_at`
  （`task_watchdog.py` 现逻辑在方案 B 下判活会失真）。
- 多副本部署（同namespace 多进程同时跑任务）为**未支持场景**（与裁决层一致）：
  运行态内存降级或 Redis 共享均可读，但任务线程本身是进程内的，勿多副本同时服务任务。
