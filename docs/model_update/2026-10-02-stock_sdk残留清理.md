# 2026-10-02 stock_sdk 残留清理（目录缓存 / 构建引用 / 安装轮子）

## 背景

用户要求核查 stock_sdk 是否还有使用方、是否已全部迁移到 `app/remote_api`。核查结论：

- **代码零引用**：`app/` `tests/` `ding_stream_service/` `frontend/` `scripts/` 全量扫描无任何
  `import stock_sdk`（源码早在 `a2c54da`「refactor(remote-api): 移除 stock_sdk 依赖」删除，
  dev_vue 合并后亦无新增引用）；
- 但仍有三处残留：
  1. 磁盘 `stock_sdk/` 目录剩 98 个 `__pycache__/*.pyc` 编译缓存（源码删除后的本地垃圾）；
  2. `Dockerfile:17` 仍 `COPY stock_sdk ./stock_sdk`——全新 clone 上该目录不存在，
     **docker build 会直接失败**（本地能过仅因 pyc 缓存还在）；
  3. git 仍跟踪安装轮子 `migrations/stock_sdk-0.1.0-py3-none-any.whl`（全库零引用）。

## 变更内容

- 删除磁盘 `stock_sdk/` 目录（纯 .pyc，git 未跟踪）；
- `Dockerfile` 移除 `COPY stock_sdk ./stock_sdk` 行；
- `git rm migrations/stock_sdk-0.1.0-py3-none-any.whl`；
- `docs/部署运维.md` Dockerfile 复制清单同步勘误。

## 影响面

- 不涉及运行代码（零引用物）；修复的是全新 clone 的 docker 构建失败隐患；
- 历史文档（model_update/审计报告）中对 stock_sdk 的提及为时点记录，保留不动；
  `docs/架构总览.md` 的「（已移除）见 app/remote_api/」墓碑注记保留作指引。
