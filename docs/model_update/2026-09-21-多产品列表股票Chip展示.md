# 多产品列表股票 Chip 展示（2026-09-21）

## 背景

多产品回测列表页的任务名称列副行原本以纯文本 `产品: A / B / C`（`product_name || stock_code` 用 " / " 连接）展示跑过哪些股票。静态版受 `.task-name-cell` 360px + ellipsis 限制，产品一多只能看到前两三只，且无任何交互查看全量，也不显示 `stock_code`。

数据无需后端改动：列表接口 `GET /api/tasks?task_type=backtest_multi_product` 经 `Task.to_dict()` 已整包返回 `task.config.products[]`（含 `product_name / stock_code / market_type / sheet.title / parameters / ratio`）。

## 方案

产品行升级为 chip（徽章）+ 折叠：

- 前 `PRODUCT_CHIPS_MAX_VISIBLE = 3` 个产品直显为小徽章，主文本 `product_name || name || stock_code`；
- 超出部分收敛为 `+N` 徽章，悬停 title 列出剩余全部产品明细；
- 每个徽章悬停 title 展示 `名称（stock_code · market_type）`，口径与详情页产品卡一致（`backtest_multi_product_detail.js` 产品卡：`product_name || name`、`stock_code / market_type`）；
- `config.products` 缺失或为空时维持 `-` 兜底；
- chip 区域局部恢复 `white-space: normal` 换行（父级 `.task-meta` 仍为 nowrap+ellipsis），单徽章超长自带 ellipsis（max-width 140px）；
- 批量导出弹窗卡片的任务副行保留纯文本，但补充 title 悬停展示全量产品明细，信息不缩水。

## 迭代（2026-09-22）：+N 与 chip 点击改为产品清单表格弹窗

`+N` 原生 title 悬停为一整段连排长文本，产品多时可读性差（无控件样式、宽度不可控、出现延迟）。改为：

- **任一产品 chip / `+N` 可点击**（`role="button"` + `tabindex="0"`，支持 Enter/Space），打开"产品清单"弹窗；
- 弹窗内为 名称 / 股票代码 / 市场 三列小表格（静态版 Bootstrap modal 复用 `batchExportModal` 结构；Vue 版 `el-dialog` + `el-table`），标题带任务名，头部显示产品总数；
- `+N` 上的连排 title 移除（由弹窗承载全量信息），可见 chip 保留单个产品的快捷 title；
- 批量导出弹窗卡片的 title 悬停保持不变（次级入口，避免嵌套弹窗）。

改动文件：`static/js/pages/backtest_multi_product_list.js`（`buildProductListRows / openProductListModal` + 点击/键盘委托）、`templates/backtest_multi_product/list.html`（`productListModal`）、`static/css/pages/backtest_multi_product_list.css`（`.product-chip--toggle`）、`frontend/src/views/backtest-multi/List.vue`（`productListVisible/productListTask/productListRows` + 弹窗；移除仅服务 +N title 的 `productRestText`）。

## 迭代（2026-09-22）：股票代码检索（看哪些任务跑过某只股票）

列表为服务端分页（每页上限 100），纯前端只能筛当前页，无法回答"哪些任务跑过这只股票"，因此在列表接口增加 `stock_code` 查询参数，SQL 层过滤，两版列表页各加筛选输入框。

### 后端（filter 全链透传，分层路线 schema → route → service → repository）

- `app/schemas/task.py`：`TaskListQuery` 新增 `stock_code: str = ""`；
- `app/routes/task_api.py`：`tasks()` GET 分支透传 `stock_code`；
- `app/services/task/query.py`：`TaskQueryService.get_tasks_paginated` 与 `TaskQueryMixin` 签名透传；
- `app/repositories/task_repository.py`：`list_paginated_with_statistics` 新增过滤——锚定 config JSON 文本中 `"stock_code"` 键值**前缀匹配**（保留尾部引号会漏掉"输 AAPL 命中 AAPL.US"的子串场景，故不封尾引号；锚定键名避免误中 product_name/sheet 字段）；兼容 `json.dumps`（`": "`）与 `JSON.stringify`（`":"`）两种分隔符；输入剔除 `"` 与 `%`，空串跳过。分页与统计共用同一 query，计数口径一致。

### 前端

- 静态版：`templates/backtest_multi_product/list.html` 卡头下新增筛选行（输入框 + 查询/清除），`backtest_multi_product_list.js` 以模块变量保存筛选值并随每次轮询请求带上，查询/清除均回到第 1 页；CSS 约束输入框宽度；
- Vue 版：`List.vue` 的 `filterDefs` 新增 `stock_code` 输入项，`loadTasks` 带参、`clearFilters` 一并清空（FilterToolbar 通用渲染，无组件改动）。
