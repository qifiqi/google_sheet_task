# 任务管理 / 任务结果页体验优化

日期：2026-09-18　分支：dev_vue　范围：`/admin/tasks`（任务管理）、`/admin/results`（任务结果）两页及其接口。

## 背景与问题

对管理后台「任务管理」「任务结果」两页做体验走查，主要问题：

任务管理页（`frontend/src/views/admin/Tasks.vue`）：

1. 无统计概览（`GET /api/tasks` 已返回 `statistics`，前端弃用）；
2. 类型列直接显示原始 `task_type`（`google_sheet_C4` 等），不可读；
3. 失败任务在列表看不到失败原因，必须逐个点进详情；
4. 创建/开始/结束三个 160px 时间列信息密度低，无耗时列；
5. 「停止确认」列是纯前端按状态猜的伪状态（"线程已结束"），有误导性；
6. 筛选/页码不进 URL，刷新后丢失；轮询固定 30s 不读系统配置；
7. 停止任务无 loading 反馈；摘要抽屉不显示 `error_message`。

任务结果页（`frontend/src/views/admin/Results.vue` + `GET /api/results`）：

1. 列表只有 `id/task_id/step_index/success/timestamp` 五个裸字段，无任务名/类型，无法辨认结果归属；
2. 仅支持 `task_id` 精确过滤（要求复制完整 36 位 UUID），不支持成功/失败筛选与关键字；
3. 失败结果在列表看不到失败原因；无成功/失败计数；
4. 抽屉里「执行结果」标题与参数/结果两个 pre 布局错位，复制按钮只有整条 JSON 一颗。

## 接口改动

### `GET /api/results`（`app/routes/result_api.py` → `app/services/task/results.py` → `app/repositories/task_result_repository.py`）

- 新增查询参数（`app/schemas/task.py::TaskResultListQuery`）：
  - `success: bool | None`——按成功/失败过滤；
  - `keyword: str`——模糊匹配任务名称（join Task `name ilike`）或结果 `task_id`（`ilike`），输入部分 ID 即可筛选。
- 投影扩展（**原键不变**，静态版 `admin_results.js` 只消费原键，不受影响）：
  - `task_name` / `task_type`：join Task 取任务名与类型；
  - `parameters_preview` / `error_preview`：SQL 层 `func.substr(col, 1, 200)` 截断预览，
    避免把 TEXT/LONGTEXT 整值拉进列表页（`_RESULT_PREVIEW_LENGTH = 200`）。
- 响应新增同过滤条件的 `total_success` / `total_failed` 计数；
  响应形状对齐单任务 results 分页分支（`{items,total,pages,current_page,per_page,total_success,total_failed}`）。
- `task_id` 精确参数与「任务不存在返回空页」语义保留（兼容 ModelSummary 深链与既有调用方）。

`GET /api/tasks`、任务域其余接口无改动（`statistics` 原本就返回）。

## 前端改动

### 新增 `frontend/src/utils/task_meta.js`

任务类型元信息共享工具，收编此前散在 `admin/Tasks.vue` 与 `admin/ModelSummary.vue` 的重复实现：

- `normalizeTaskType` / `getTaskVersionFromType` / `isGoogleSheetTask` / `taskDetailRoute`（自 admin/Tasks.vue 迁出，补 `c7` 分支）；
- `taskTypeLabel`：可读短标签（C3/C4/C5/C7/单品回测/多品回测）。

admin/Tasks.vue 删除本地副本改为 import；ModelSummary.vue 的本地实现保持不动（未在本轮收编范围内，避免扩大影响面）。

### 任务管理页 `admin/Tasks.vue`

- 统计卡（StatCardGrid）：总任务/已完成/运行中/错误 + 子指标（今日新增/成功率/平均时长/错误率），
  **点击卡片按状态筛选，再次点击取消**（选中卡高亮 accent 边框）；
- 表格列重构：类型列用 `taskTypeLabel` 徽标；失败任务状态徽标 hover tooltip 展示 `error_message`；
  开始/结束合并为一列双行 + 新增「耗时」列（优先后端 `duration_seconds`，缺失时按开始/结束补算）；
  移除「停止确认」伪状态列与创建时间列（创建时间保留在摘要抽屉）；
- 停止按钮 loading（`stoppingTaskId`），停止后沿用 stop-confirmation 轮询确认；
- URL 状态同步：`status/task_type/keyword/page` 写 query，`watch(route.query)` 支持前进/后退
  （自 replace 引起的变化用等值守卫跳过，同任务列表页模式）；
- 轮询间隔读 `SystemConfig.frontend_polling_interval`（默认 30s，读不到沿用默认；
  与任务列表页相同的「停内置定时器 + 按配置自建」模式）；
- 摘要抽屉新增「错误信息」行（runtime-detail 的 `task.to_dict()` 自带该键，接口无改动）。

### 任务结果页 `admin/Results.vue`

- 筛选区（FilterToolbar）：状态（成功/失败）下拉 + 关键字输入（任务名称/任务 ID，部分匹配，
  替代原「输入完整任务 ID」输入框）；FilterToolbar 输入自带 300ms 防抖；
- 表格头右侧显示 `共 N 条 · 成功 X · 失败 Y`（随筛选联动）；
- 表格列：任务（名称 + 类型徽标 + 短 ID hover 看全 ID）、步骤、状态、参数预览（等宽字体溢出提示）、
  失败原因（仅失败行显示）、时间；操作列「查看 / 任务 / 删除」；
- URL 状态同步：`success/keyword/page`；兼容旧深链 `?task_id=xxx`（ModelSummary 跳转链接）——
  归一为 keyword 预填（模糊匹配覆盖原精确语义）；
- 抽屉重构：描述区（含「跳转任务详情」按钮，按 `task_type` 经 `taskDetailRoute` 分流到
  `/task/:id`、`/backtest/:id`、`/backtest-multi/:id`）；参数信息/执行结果各自成节、
  分别提供「复制参数 / 复制结果」；错误信息独立节；
  `prettyJson` 对字符串形态 JSON 先 parse 再美化。

## 风险与备注

- `/api/results` 为加字段 + 加可选参数的非破坏性扩展；静态版 `admin_results.js`、`/api/results?task_id=` 既有调用方不受影响；
- keyword 模糊匹配为 leading-wildcard `ilike`，无法走索引；仅管理员结果查询页使用、默认不带 keyword 的查询路径不变，量级可接受；
- 未修改任何数据库 schema / 迁移；
- 注意：工作区另有他人并行修改的 `backtest-multi` 相关文件（Detail.vue/静态模板等），不在本轮改动内，未触碰。
