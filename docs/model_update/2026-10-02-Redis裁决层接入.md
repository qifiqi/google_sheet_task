# 2026-10-02 Redis 裁决层接入（db-to-http §8.1 落地）

## 背景

db→http 迁移的 33 处 `TODO(db-to-http)` 中，§6.1 结构性缺口（状态机 CAS / Sheet 占用 /
token 计数回写 / 回测锁 / 调度锁的读-改-写竞态）按既定路线以 Redis 裁决层收口。
用户确认方案后实施：redis 服务进 docker-compose、配置走 env、降级直通不阻断业务。

## 设计要点（与原 §8.1 设想的差异）

- **只串行化秒级读-改-写临界区**：持久状态仍在远端行，Redis 锁不承载业务语义；
  TTL 到期自动放行、持有者崩溃不留死锁——因此**不需要长持锁与续期**（`renew()`
  保留为 API 备用）；
- **降级直通**：`REDIS_URL` 未配置 / redis-py 缺失 / 连接异常时锁恒成功（等价接入前
  的读-改-写语义，单 worker 部署本就安全），首次降级打一条 warning；
- 竞争等待预算（默认 5s，0.2s 重试）耗尽后**降级直行**而非报错：业务路径不因锁竞争中断；
- 锁值含持有者 token，释放/续期经 `register_script` Lua 在服务端原子校验，防 TTL 过期后
  误删他人锁；
- 命名空间 `{REDIS_NAMESPACE}:*`（默认 `arb:gstask`），多副本共库可隔离。

## 部署升级步骤

```bash
cd dockers && cp .env.example .env   # 已有则补一行 REDIS_URL=redis://redis:6379/0
pip install -r ../requirements.txt  # 或重建镜像
docker compose up -d                # redis 服务随起，app 依赖启动
```

## 影响面与验证

- db 模式（`DATA_ACCESS_MODE=db`）零改动路径——仲裁器只在 http_backend 仓储消费；
- 回归：全量 `pytest tests/unit tests/integration` **10 failed / 749 passed / 57 skipped**，
  失败集与接入前基线完全一致（+9 为新增仲裁器用例），零新增失败；
- 未消掉的缺口：§6.1 的事务类（22 处 `commit=False` 组合）与 `create_with_return`
  跨表写入不在 Redis 职责内，仍等远端端点（见
  [02-remote-incremental-endpoints.md](../design/db-to-http-migration/02-remote-incremental-endpoints.md) E1/E4）。
