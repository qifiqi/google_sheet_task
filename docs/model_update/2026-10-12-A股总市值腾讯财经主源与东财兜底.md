# A股总市值（ETF资产总数）取数：腾讯财经主源 + 东方财富兜底

日期：2026-10-12　分支：dev_vue

## 背景

策略回测 Word 报告的权重表「ETF资产总数 / 净资产」列，A 股取数原为 `etf_total_assets → DFCJStockApi.get_total_assets_with_source`，唯一数据源为东方财富延迟行情 `push2delay.eastmoney.com/api/qt/stock/get` 的 f116 总市值。线上持续出现 `502 Server Error: Bad Gateway`（push2 系主机 WAF/网关抖动，2026-10-12 当日复现），失败时返回 `(None, None)`，报告资产列整体渲染 "-"，且 `strategy_backtest_report_service._build_report_data` 的列头判断因 `asset_texts` 为空失真（纯个股报告也显示「ETF资产总数」）。

## 方案演进

第一版做「东财优先 → 腾讯兜底」，但东财挂掉时每个代码首次取数仍需吃 `__get` 的 5 次指数退避重试（约 17-40s）才轮到腾讯，Word 导出为同步请求，延迟不可接受；且 push2delay 502 并非瞬时抖动。最终定为**腾讯主源、东财兜底**：

```
etf_total_assets.get_etf_total_assets_detail (cn)
  ├─ 1) TencentStockApi（qt.gtimg.cn，直连无 WAF）→ 命中即返回
  └─ 2) DFCJStockApi（push2delay f116）→ 腾讯契约不符/异常时兜底
```

TTL 缓存（成功 6h / 失败 10min）与 (None, None) 降级语义不变，对报告层透明。

## 腾讯行情字段契约（qt.gtimg.cn，GBK、~ 分隔，实测 2026-10-12）

| 字段下标 | 含义 | 说明 |
| --- | --- | --- |
| 2 / 3 | 代码 / 最新价 | 代码回读校验（== 请求代码）作错位护栏 |
| 44 | 流通市值（亿元） | 未使用 |
| **45** | **总市值（亿元）** | 个股=总市值；场内基金=最新价×总份额（基金规模），与东财 f116 同口径；`×1e8` 转元 |
| 61 | 类型标记 | `GP-A` / `GP-A-KCB` / `GP` / `ETF` / `LOF`（本次未采用，ETF 判定仍走代码前缀） |

要点：

- **symbol 映射**：沪 5/6/9（含 900 沪B）→ `sh`，北交 4/8/920 → `bj`，其余 → `sz`（北交所实测可用；东财侧无此区分）。
- **位置字段的护栏**：`价格×总股本` 交叉校验不可行——流通≠总市值（万科偏差 18.6%）或 A+H（中芯国际偏差 76.6%）的个股上恒等式不成立；故仅做代码回读校验 + 正值校验，契约不符一律 `(None, None)` 降级东财，不做静默猜测。
- **适配层契约**：任何失败（网络/解析/契约/非正值）一律返回 `(None, None)`，永不外抛；适配层若漏抛异常由 `etf_total_assets` 入口安全网吸收（与 yf_api 同约定，不承诺二级兜底）。
- 是否 ETF 判定不变：代码前缀（沪 5 / 深 15-16 开头），两源同规则、与数据源解耦。

## 注意

- 东财兜底路径保留原有 tenacity 重试与 `dfcf_kline_proxy_enabled` 代理开关语义不变；仅当腾讯失败时才发生，正常路径不付该延迟。
- 腾讯请求不走代理，直连 + `Referer: https://gu.qq.com/`，`trust_env=False` 与 DFCJ 会话策略一致。
- 若腾讯未来变更字段布局：代码回读校验会使其整体降级到东财（可观测的 warning 日志 `腾讯财经行情契约不符`），不会静默出错值。
