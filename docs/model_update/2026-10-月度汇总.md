### 2026-10-08 登录302循环修复与移动端缺口收尾
- P0 根因：登录态双通道分歧——localStorage `access_token` 持久（页面 JS 通道，登录页自动跳转判据）与 cookie `gsc_access_token` 会话级（服务端 `page_login_required` 通道）生命周期不一致，浏览器重启后 localStorage token 仍在有效期内时，登录页自动跳转被服务端 302 弹回，无限刷新无法登录。
- 修复两层：`setTokens` 客户端解码 JWT exp 给 cookie 写 Max-Age 对齐两通道生命周期（解析失败保持会话 cookie，绝不写 `Max-Age=0` 误删）；登录页 10 秒防弹跳护栏（`leaveLoginForNext` 打标 + `canAutoLeaveLogin` 检查，弹回后展示表单+提示；表单手动提交不受门禁）。未触碰 SSO 换票逻辑本身。
- 移动端收尾：navbar.js 族前缀补 `/backtest`、`/backtest-multi` 恢复 11 个 legacy 页面（桌面+手机）侧栏导航；weight_combination 筛选弹窗窄屏宽度 `min(calc(100vw - 1.5rem), 20rem)`、grid 断单列、label 允许换行。纯前端 3 个静态文件，0 后端改动，revert 即回滚。

### 2026-10-24 随机价任务内存驻留治理：快照惰性物化替代全量预计算
- 背景：`get_bdl` 对全部股票一次性预展开并全程持有 `kline_data_map`（base.py precomputed_params 模式），random_price 持久路径下每(窗口×随机组)物化一份 `merge_rows` 合并行（7键 dict ≈0.6KB/行），驻留内存 ≈ Σ股票(Σ窗口bar数×组数)×0.6KB：30股×20组×10年区间 ≈5GB 量级，且从任务启动持到结束，多任务并发再叠加——内存随规模线性放大（非泄漏，是预计算设计问题）。
- 方案：持久路径展开期不再物化合并行。`_expand_random_price_groups` 落库时返回值从普通 dict 换为新增 `SnapshotLazyKlineMap`（task_kline_snapshot_service）：展开期只登记每组 series id 与窗口签名(首日/末日/行数)；执行期消费方（c5/c7/c1_1 的 `kline_data_map.get(kline_key)` 与 base.py `combination['kline']`）按需触发 `materialize_series_rows`（get_series_by_id + get_source_by_id + merge_rows，2 个主键查询 + JSON 解码，千行窗口毫秒级），带 LRU(8) 复用相邻组合（组数≤8 时同窗口一轮后全命中）。外部K线取数每股票仍只一次，随机值仍展开期一次生成落快照，快照缺失物化抛 NotFoundError 走组合失败、不会静默重拉重算；非持久路径（组合数精算 / 无上下文单测）保持原内存 dict 行为零变化。
- 去重适配：`_deduplicate_parameter_combinations` 改走 `_resolve_kline_signature`（惰性映射读登记元数据、普通映射物化行），签名 (首日/末日/行数) 与旧行为逐值等价，去重结果不变。
- 效果：随机价任务全程驻留从 O(股票×窗口×组×bar) 降到 O(组合小 dict)+O(单窗口物化行×8)，上述 5GB 场景降至几十 MB + 执行期单窗口瞬态；代价为执行期每组至多 2 次本地库主键读（组数>8 时每组合一次，相对每组合必发的 Google Sheet 网络写入可忽略）。
