> 设计文档：`docs/design/performance-analysis-v3/01-设计方案.md`（含三项已确认决策：
> 红涨绿跌、净值序列走后端导出、v3 新开 JS/CSS；四个补充问题的结论见设计文档 §0）。
>
> **同日补记（浏览器实测修复轮）**：真实数据联调发现并修复六处渲染缺陷（见文末
> "补记：浏览器实测修复轮"），并补齐 Word 报告同款"累计超额收益曲线"与
> "日收益分布直方图"两张交互图，全部图表坐标轴/刻度线/网格显式化。

## 需求

V3 页（`/performance-analysis/v3`）原为 V2 的直接复制。本次按量化分析视角重构：

1. 更丰富的图表化：补齐净值/水下回撤/月度热力图等核心图，新增指标（滚动、分布、
   资金曲线特征、极端行情）全部图形化；
2. 排版重构：从"表格优先"改为"分区仪表盘 + sticky 锚点导航"，明细折叠为数字支撑区；
3. 多数据对比接入口：前端 Dataset Registry，任意新数据源登记即可对比。

## 后端（唯一行为变更：analyze 可选导出净值序列）

不新增端点。`POST /api/performance-analysis/analyze` 载荷新增可选 `include_series`
（经 `coerce_bool` 解析，缺省关闭，老调用方响应零变化）：

- `app/services/performance_analysis/facade.py`：新增 `build_series_payload(result)`——
  从 `MetricsV1Result` 的 `index_df/start_df/excess_df`（同源 `base_df`，日期轴一致）
  导出 `{dates, index_nav, start_nav, excess_nav}`；净值 6 位小数、非有限值置 None；
  无帧（single 模式）返回 None。
- `app/services/performance_analysis/text_analysis.py`：`analyze()` 增加 `include_series`
  形参；dual 分支改持 `MetricsV1Result` 再取 `.metrics`（行为不变），按需挂 `payload['series']`。
- `app/services/performance_analysis/sheet_reader.py`：`analyze_v1()` 同步；`include_series`
  时走既有 `get_calculate_metrics_v1_with_dataframes`（同门面），`sheet_result` 挂载不变。
- `app/services/performance_analysis/service.py`：`analyze(payload)` 解析 `include_series`，
  三个 `_analyze_*` 分支透传；`_normalize_result` 仅在请求导出时附 `data.series` 键。
- 请求 Schema（RootModel 自由字典）无需修改；来源分流仍在 service。

## 前端（老模板，V2 零影响）

- `templates/performance_analysis/v3.html`（重写）：分区仪表盘——来源四 Tab（Sheet/粘贴/
  Excel/结果分析）+ 参数配置 → 数据集栏 → 锚点导航（核心指标/净值与回撤/年度绩效/月度透视/
  收益分布/风险与极端行情/数据明细）→ 口径 chips（四阈值 + 无风险利率 + 区间，含颜色约定图例）→
  各分区图表 → 八章明细折叠区（与 RPT-S 报告章节一一对应）→ Excel/Word 导出与 Word 弹窗。
- `static/js/pages/performance_analysis_v3.js`（新建，v3 专属）：
  - **Dataset Registry**（多数据对比接入口）：来源适配（`analyzeGoogleSheet/analyzePaste/
    analyzeResult` 统一构造 `{key,label,source,metrics,series,meta,wordPayload}`）→
    `addDataset()` 登记（同 key 覆盖）→ 芯片栏勾选参与对比、点击设为当前、×移除；
    新数据源只需构造条目调 `addDataset`，图表层不改。
  - 对比模式（>1 勾选）：KPI 转多列表格（行最优绿描边）、净值/水下/年度/雷达/分布按数据集
    多系列（首数据集基准作灰色虚线公共基准）；超额/散点/热力图/极端/明细等单视图图表展示
    当前选中数据集。
  - 图表：净值曲线（可切对数轴）、水下回撤、年度收益/回撤/超额柱、风险调整雷达（归一化）、
    月度热力图（自绘色块表，基准/策略/超额切换，全年复利合计列）、滚动收益组合图
    （均值柱+胜率线）、月度散点（45°线）、三张分布直方图、极端阶段/极端单日/修复天数柱、
    资金曲线特征表；柱状图带自写柱顶数值标注插件。
  - 明细区按 RPT-S 八章组织 11 个 tab（含 Sheet 结果条件显示、全量指标中文化总表、全量 JSON）。
  - URL 参数直达：`?task_id=`（自动拉结果下拉）/ `?result_id=`（直接分析），支持 C 系列/
    回测页跳转接入。
  - 颜色约定落地：红涨绿跌（`.v3-up/.v3-down`），系列色（基准蓝/策略绿/超额橙）与涨跌色分离。
- `static/js/common/metric-names.js`（新建）：前端唯一指标词表（键 → 中文名/八章分组/格式），
  行名与 RPT-S 报告对齐，"模型"统一叫"策略"；V3 全部展示名经 `window.MetricNames` 取得；
  `sheet_result` 键不做映射（键来自模板 Sheet 本身）。
- `static/js/chart.umd.min.js`（新增 vendor，Chart.js 4.4.9）：v3 不再依赖 CDN 图表库
  （xlsx-js-style 仍为 CDN，与 V2 一致）。
- `static/css/pages/performance_analysis_v3.css`（新建）：涨跌色工具类、分区导航、数据集芯片、
  热力图色块、明细最优值描边等。
- **V2 缺陷顺手修复**（一行）：`performance_analysis_v2.js` 直接输结果 ID 路径的

## 补记：浏览器实测修复轮（同日）

以真实指标管线 + 浏览器自动化（粘贴数据→分析→逐区截图）联调，定位并修复：

1. **夏普比率/年化波动率整行空**：`index/start_sharpe_ratios` 是**字典**
   `{'all': {...}, 'year_*': {...}}`，原按列表（`year==='all'`）取值恒空。
   新增 `periodEntry()` 统一兼容字典/列表两种形状（KPI、雷达、明细表同步修正）。
2. **分布类图表全空**：metrics 里分布经序列化后是**纯数组**（7 档顺序，键丢失），
   原按字典键取值恒空。新增 `distValue()`（数组按下标/字典按键双兼容）与改造
   `distLabels()`，三张分布图 + 三张分布明细表 + 全量指标总表同步修正。
3. **假 delta"（0.00%）"**：`Number(null)===0` 使空值参与差值计算。新增
   `isFiniteNum()` 严格判定，KPI 单/对比模式与雷达归一化同步修正。
4. **修复天数图 0 点并中断渲染**：整体修复天数是**标量**、分年度是字典，原按字典
   读标量得到空 labels，Chart.js 绘制时抛"Cannot convert object to primitive value"。
   已改为"各年 + 全部"合并轴（基准/策略/超额）。
5. **多图空白的关键根因（format 递归）**：柱顶数值标注的 format 回调原先放在
   `plugins.v3ValueLabels.format`——Chart.js v4 的 options 代理会把**函数值选项当作
   可脚本化回调在解析期调用**，触发 `format->format` 递归异常，中断整个动画帧绘制
   （同一帧的多张图连带空白，控制台表现为 Cannot convert object to primitive value）。
   已改为 format 挂在 chart 实例（`$v3ValueLabelFormat`），不进 options 树。
6. **分布占比二次缩放**：`*_distribution_pct` 服务端已是百分数（8.33 表示 8.33%），
   页面原再 ×100（显示 833%）。新增 `fmtPctRaw()/numOrNull()` 原值直出。

另按需求补齐 Word 报告（RPT-S）同款静态图的两张**交互版**（Chart.js，带坐标轴/
刻度线/网格，刻度只显数值、单位由轴标题说明，与报告口径一致）：

- **累计超额收益曲线**（净值与回撤区）：`series.excess_nav - 1` 逐点累计超额，单模式
  红色单线、对比模式按数据集多线；
- **日收益率分布直方图**（收益分布区）：从净值序列还原日收益，按报告算法实现
  对称分箱（0.5%/99.5% 分位 ×1.05、最小 1%；Freedman–Diaconis 与 span/60 取大后
  向 1-2-2.5-5 网格取整，12~60 箱），基准/策略双系列频数，0 轴参照线（自写
  v3ZeroLine 插件），卡片头显示"超出 ±X% 并入两端"。

坐标轴样式显式化：新增 `v3YScale()/v3XScale()`（浅色横向网格 #E1E6EC、灰蓝轴线
#9EADBD、深色刻度），柱状/折线图统一套用；KPI 与明细表数值列表头右对齐
（`th.num`），消除"表头在左、数值在右"的视觉错位。

验证方式：临时预览服务（真实 analyze 管线 + 最小 auth stub）+ 浏览器自动化逐区
截图核对——17 张图全部有像素、零控制台报错、柱顶标注/双轴/热力图/直方图正常
（验证后已删除临时服务脚本）。

> 注意：联调中同步确认——若页面图表容器塌陷（面板仅百余像素高、锚点导航无
> 蓝色胶囊高亮），是浏览器未加载到 `static/css/pages/performance_analysis_v3.css`
> （旧缓存或部署未同步静态文件），强刷（Ctrl+F5）或重新同步静态资源即可。
