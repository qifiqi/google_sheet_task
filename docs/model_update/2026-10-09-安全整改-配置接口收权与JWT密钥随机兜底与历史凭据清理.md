## 2. 堵住的攻击链（审计严重项）

1. **配置投毒 → JWT 密钥接管**：`POST /api/config` 原先任意登录用户可写任意键，且 `_get_secret` 在环境变量缺省时回退数据库配置——低权限用户写入 `JWT_SECRET_KEY=<已知值>` 后可自签 admin JWT 完全接管平台。现两层封堵：写端点 admin_required + 受保护键服务层拒绝（即使管理员账号被盗也无法经 API 改密钥，须登服务器/改环境变量）。
2. **公开默认密钥 fail-open**：启动校验原先只检查环境变量是否等于默认值，env 未设置时放行，运行期却回退公开常量 `'change-me-in-production-secure-key'`——任何人都可离线伪造任意用户令牌。现公开常量在任何解析路径都不可用。
3. **配置明文泄露**：`GET /api/system-configs` 原先未脱敏，任意登录用户可读全库配置明文。现仅管理员可读且值全部打码。

## 3. 行为变化与部署注意

- **`/api/config` 写、`/api/system-configs` 读写从此仅限 admin 角色**（前端消费方仅 `admin_config.js` 与 Vue 管理端 Config.vue，均属管理页，无破坏面）。非 admin 调用返回 403 信封。
- **`JWT_SECRET_KEY`/`SECRET_KEY`/`proxy_url`/`token_file` 四个键经任何 HTTP 配置接口不可写**，写入返回 400 并提示走环境变量/服务端脚本。运维如需设置数据库侧 `JWT_SECRET_KEY`（可跨重启保持令牌有效），用 `flask shell` 调 `config_manager.set_config()`。
- **未设置 `JWT_SECRET_KEY` 环境变量的部署**：启动多一条 warning 日志；进程重启后所有已签发令牌失效（用户需重新登录，SSO 用户重新走换票）。生产环境强烈建议显式设置强随机 `JWT_SECRET_KEY`（`python -c "import secrets; print(secrets.token_hex(32))"`）。
- 已核实 `update_configs`/`update_config_row` 无 HTTP 之外的调用方（全库仅 `config_api.py` 两端点消费），白名单不影响启动期或任务链路写入。
