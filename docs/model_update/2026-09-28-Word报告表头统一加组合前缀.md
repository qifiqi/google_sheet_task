# Word 报告表头统一加"组合"前缀（2026-09-28）

## 背景与需求

导出 Word 报告中，默认组合基准列的表头此前固定显示为"指数"，策略列显示为"策略"，与报告语境（多产品按比例组合的回测）不符。需求：

1. 原指数表头改为**组合指数**；
2. 策略表头及其派生表头**统一添加"组合"二字**（组合策略）；
3. 基准归属的派生表头（指数月数/占比/天数、平均超额、正超额概率等）同样**统一带"组合指数"**；
4. 把散落在报告服务各处的表头文案**抽成函数**统一管理，派生表头一律由其派生；
5. 图表图例与图表标题同步。

范围仅限 Word 报告（`/api/exports/backtest-reports/word`）内的表头/图例/结论文字；前端页面表格、CSV 导出、权重表标题、`(指数)` 后缀标记均不动。

## 改动内容

### 1. 表头词汇抽成函数（`strategy_backtest_report_service.py`）

新增两个无参静态方法，作为报告表头词汇的唯一出口：

- `StrategyBacktestReportService._composite_benchmark_label()` → `"组合指数"`
- `StrategyBacktestReportService._strategy_label()` → `"组合策略"`

### 2. 默认组合基准列头

- `_build_benchmark_runs`：默认组合基准 run 的 `label` 由字面量 `"指数"` 改为 `_composite_benchmark_label()`。
- `_benchmark_tag`：组合基准的判定由 `label.startswith("指数")` 改为 **`code is None`**（`_BenchmarkRun` 的既有契约）。原字符串前缀判定在 label 变为"组合指数"后会误判（`"组合指数".startswith("指数")` 为 False，会落到 `代码 权重%` 分支产出 `None 100%`），必须同步修正。
- 自定义满配基准与组合基准共存时，仍按原规则消歧为 `指数(代码)`，保证多基准场景下超额/胜率等派生列头的区分标记不撞车（组合基准 tag 为空串、自定义满配 tag 也为空串，若不消歧会出现两列同名"超额"）。

### 3. 派生表头全部经函数取值（消除单/多基准双份字面量）

| 位置 | 旧 | 新（默认组合场景） |
| --- | --- | --- |
| 1.1 核心收益 / 1.2 分年度 | `策略` | `组合策略` |
| 1.1 单基准超额列 | `超额(策略-指数)` | `超额(组合策略-组合指数)`（按 `策略列头-runs[0].label` 拼装） |
| 1.3 滚动收益 | `指数平均收益` / `策略平均收益` / `策略胜率(跑赢指数)` | `组合指数平均收益` / `组合策略平均收益` / `组合策略胜率(跑赢组合指数)` |
| 2.1 回撤指标 | `策略` | `组合策略` |
| 2.2 分年度回撤 | `指数回撤` / `策略回撤` / `超额回撤(策略-指数)` | `组合指数回撤` / `组合策略回撤` / `超额回撤(组合策略-组合指数)` |
| 3 风险调整 / 5.1 / 5.2 / 7.x / 8 | `策略` | `组合策略` |
| 4.2 月度分布 | `指数月数` `指数占比` `策略月数` `策略占比` | `组合指数月数` `组合指数占比` `组合策略月数` `组合策略占比` |
| 5.3 日度分布 | `指数天数` `指数占比` `策略天数` `策略占比` | `组合指数天数` `组合指数占比` `组合策略天数` `组合策略占比` |
| 6.1 超额行标签 | `累计超额(策略-指数)` | `累计超额(组合策略-指数)`（基准侧保持泛指，兼容自定义指数列） |
| 6.2 超额区间分布列 | 单基准 `月数` `占比`；多基准组合列裸 `月数` `占比` | `组合指数月数` `组合指数占比`（自定义列保持 `月数(代码 比例%)`） |
| 6.3 滚动超额列 | 单基准 `平均超额` `正超额概率`；多基准组合列裸同前 | `组合指数平均超额` `组合指数正超额概率`（自定义列保持 `平均超额(代码 比例%)`） |
| 3 超额行（多基准组合列） | `超额夏普比率` / `超额索提诺比率` | `超额夏普比率(组合指数)` / `超额索提诺比率(组合指数)` |
| 7.1/7.2 行标签 | `策略跑赢次数` | `组合策略跑赢次数` |
| 十、结论 | `指数累计回报率…策略累计回报率…` | `组合指数累计回报率…组合策略累计回报率…` |

单基准分支（月数/天数/平均收益）此前是独立字面量，本次统一改为与多基准同规则（`f"{run.label}…"` / 策略列头拼装），消除双份文案来源；多基准模式下组合基准列的派生列头随之自动变为"组合指数…"。

### 4. 图表图例与标题（`strategy_backtest_report_charts.py` + `_build_chart_data`）

基准图例消费 `run.label`，自动跟随"组合指数"；策略图例（净值曲线、回撤曲线、分年度收益、日收益分布四处）此前硬编码"策略"/"策略回撤"，改为从 `_build_chart_data` 注入的 `strategy_label` 读取，缺省回落"策略"（保持该模块可独立测试）。

超额相关图表标签由 `_build_chart_data` 统一生成：

- 超额收益曲线图例：组合基准 `超额` / 单基准 `累计超额收益` → 统一 `超额(组合指数)`（自定义列保持 `超额(代码 比例%)`）；
- 月度超额分布标题：组合基准裸 `月度超额分布` → `月度超额分布（组合指数）`（自定义列保持 `月度超额分布（代码 比例%）`）。

### 5. 文案同步

- `app/schemas/backtest.py`：`include_composite_benchmark` 注释"列头固定为'指数'" → "组合指数"。
- `templates/backtest_multi_product/global_preview.html`：导出弹窗开关提示"列头显示'指数'" → "组合指数"。
- `static/js/pages/backtest_multi_product_global_preview.js`：同上注释。

## 保持不变（明确不改）

- 自定义指数基准列头 `指数` / `指数(比例%)` / `指数(代码 比例%)`（它们是真实指数基准，非组合）。
- 权重表标题 `策略权重` / `指数权重` 及行标签 `代码 (指数)`、相关系数热力图标签（`(指数)` 是"被选为基准"的标记，非列头）。
- 7.1/7.2 章节标题中的"指数月收益"（描述阈值规则，泛指任一基准）。
- 前端页面表格、Excel/CSV 导出、`performance_analysis/exporter.py` 的 CSV 表头。

## 注意

- Word 导出带 TTL 缓存（`word_export_cache_ttl_minutes`）：部署本改动后，缓存中的旧报告在 TTL 内仍会回放缓存文件；如需立即生效可管理端清理 Word 导出缓存或重启后清空 `data/word_export_cache/`。
