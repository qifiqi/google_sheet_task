# db-to-http 架构对齐与审查问题收敛（2026-10-17）

依据用户明确的目标架构做现状对照与增量实现。目标架构：

> 1. 所有数据库操作改为 HTTP 直连（主站接口）；user/路由统一迁移主站。
> 2. 用户在本服务登录页经主站登录接口拿 Token 交给 web，之后统一携带 Token
>    访问 task 与业务数据（主站按 Token 角色鉴权，实测非授权端点 403）。
> 3. 任务/长任务的停止与启动经 Redis 处理；初始化与最终落盘统一走 HTTP 落远程；
>    中间产出的结果实时落盘。

## 二、审查问题收敛（P0/P1）

1. **服务级凭据生命周期（P0）**：远端 Token 为登录颁发的会话票据，后台任务线程无人工重登能力。
   - `app/remote_api/client.py`：服务级调用（token=None 且无请求域 Token）收到 401 时，用 `STOCK_API_USERNAME/PASSWORD`（环境变量，红线：不入源码/日志/测试）自动经 `SysUser/Login` 重登换新，锁+代数计数合并并发、thread-local 防递归，换新后仅重试一次；
   - `app/config.py`、`.env.example`：补 `STOCK_API_TOKEN`（必配）与 `STOCK_API_USERNAME/PASSWORD`（可选兜底）条目与说明。
2. **启动期占用恢复断链（P0）**：`startup.py` 三个 reset 与死任务清理原直写本地 ORM 表，http 模式下真实占用态在远端且 acquire 端无自愈——崩溃一次远端占用永久卡死。
   - 仓储两侧新增同签名方法：`google_sheet_token_repository.reset_all_usage_counts` / `google_sheet_repository.clear_all_occupancy` / `backtest_repository.delete_stale_run_locks(is_task_running)` / `task_repository.list_running_task_entities`；
   - `startup.py` 四函数改经仓储调用，db/http 模式统一写"真实库"。
3. **http 孪生 AttributeError 缺口（P1）**：
   - `task_result_repository.list_by_task_fields`：http 版整行拉取后本地投影（fields 白名单、parameters/result 解 dict、return_date_range 计算字段含 stock_date 回退），TODO 标注等 E7 列投影收敛网络放大；
   - `task/task_log/backtest.add_entity`：http 版经 `orm_entity_payload`（`__table__` 元数据取列、不 import models）落远端，None 自增主键剔除、远端回显 id 回写实体；TaskLog 消息过 `normalize_message` 截断。
4. **网关身份校验缓存（P1）**：`sys_user_repository.get_user_info` 加 30s 正缓存 + 5s 瞬时失败负缓存（401 登录失效不缓存实时抛出），消除"每请求一次远程 RTT、远端抖动全站雪崩"。
5. **顺带修复**：`sys_user_repository.get_user_role_list` 的 `SdkProtocolError` 未导入（真触发 NameError）；`client.py` 的 `except RemoteApiError` 未导入（任何传输错误路径 NameError）——两处均为存量潜伏 bug，本次测试覆盖错误路径时暴露。

## 三、架构对齐增量（统一携带 Token + 安全加固）

1. **请求域用户 Token 透传**（`app/remote_api/client.py` + `app/utils/auth.py` + `app/__init__.py`）：
   - 网关 `authenticate_current_request` 校验通过后 `set_request_user_token(token)` 写入 ContextVar；`teardown_request` 统一清除（线程复用防串号）；
   - 统一调用器凭据解析顺序：显式 token > 请求域用户 Token > 服务级 `STOCK_API_TOKEN`（+自动重登）。**行为变化**：请求线程内的业务数据调用从"服务账号角色"改为"实际用户角色"过主站鉴权——远端 403 会如实透传到页面（这正是主站权限体系的预期语义）；AUTH_ENABLED=false 的免鉴权开发模式不受影响；
   - 重登路径（thread-local 标志内）不采用请求域 Token，登录调用恒为服务级形态。
2. **任务线程隔离**（`app/services/task/facade.py`）：`ThreadPoolExecutor.submit` 会复制提交者 contextvars——任务 worker 改为 `pool.submit(contextvars.Context().run, _wrapped)` 空上下文执行，长任务不继承用户 Token（会话过期不会打断任务，权限语义以服务账号评估），数据访问回退服务级凭据 + 自动重登。
3. **SSRF 加固**（Mimosa 验收约束）：`_validate_remote_host` 在传输构造期解析 DNS 并拒绝环回/私有/链路本地/保留/多播/未指定地址，`STOCK_BASE_URL` 误配直接 `RemoteApiConfigError` 失败而非静默外发凭据。

### 6.3 远端/环境问题（需主站团队处理）

1. **P0：`POST /api/ParamTasks/ModifyOrAdd` 插入分支服务端失败**——任意新 id（含完整合法行、
   补齐时间戳、created_by 置空、steps=0 等全部变体）一律"操作失败/内部请求出错"；更新分支正常。
   纯 http 模式下任务无法新建，当前只能改写存量行。请远端排查插入路径（疑似库约束/实体配置）。
2. **主站为单会话账号模型**（新登录踢旧会话，被踢 token 返回"您的账号已在其他设备登录"）：
   服务级 `STOCK_API_TOKEN` 必须使用**专用服务账号**，否则与人工登录互踢（自动重登会
   周期性踢掉人工会话）。
3. **DNS 双 A 记录**：stockapi.jaspil.cn 同时解析到内网 `172.18.20.20`（443/7070 均不可达）
   与公网 `118.178.136.251`——内网记录已死，建议 DNS 侧摘除；`.env.development` 的
   `STOCK_BASE_URL=http://172.18.20.20:7070` 指向死地址，本地联调需显式覆盖。
4. 远端偶发 502（nginx upstream）+ `GetUserInfo` 等接口短暂挂起：参数回推遇 502 风暴时
   worker 线程会长时间阻塞（本此实测 ~16 分钟，取消标志置位后仍未自愈）——看门狗恢复
   （判活改读 Redis heartbeat_at）的优先级应提升。
5. venv 需确保 `redis` 包安装（requirements.txt 已列，陈旧环境会静默降级内存运行态）。
