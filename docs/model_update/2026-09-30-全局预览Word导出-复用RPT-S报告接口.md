# 2026-09-30 全局预览 Word 导出（复用 RPT-S 报告接口，前端循环调用）

## 需求与约束

单品全局预览（`/global-preview/single-product`）新增 Word 导出：按"股票代码 × 年份"组合，
**每个结果（股票×年份×参数方案）一个 RPT-S 文档**，由前端逐个调用、逐个下载。
**不新增任何接口**——复用多产品全局预览页已在用的 Word 回测报告接口
`POST /api/exports/backtest-reports/word`。

> 同日早些时候实现过一版专用方案（`GET /global-previews/<task_id>/word` 端点 +
> 预览 Word 文档构建器 + 批量导出 format 字段），按"不要过多接口"要求已全部撤销。

## 后端（仅一处限流调整，无新端点）

- `app/routes/export_api.py`：`/backtest-reports/word` 端点从通用 `_export_limit`
  （rate_limit_export，10/min）改为独立 `_word_report_limit`
  （`rate_limit_word_report`，默认 **60/min**，仍按用户键，可经系统配置调整）。
  原因：前端循环调用该端点，10/min 会误伤；其余导出端点限流不变。

## 前端（老模板：global_preview_index.js + index.html）

- 工具栏恢复「导出Word」按钮（与「导出」Excel 并列，查询成功后可用）。
- 查询任务后首次点击 Word 导出时，调既有 `GET /api/tasks/<task_id>/results` 建立
  结果索引（result_id → return_series_id / stock_code / year / success），按任务缓存。
- 点「导出Word」弹出**选择弹窗**（`#wordExportModal`，交互对齐列表页批量导出弹窗）：
  - 列出任务下全部结果卡片（股票_年份_结果ID）；默认**全选可导出**结果，
    取消勾选即"只导出部分"；支持"全选可导出 / 清空"快捷操作；
  - 不可导出结果（失败或无收益序列）置灰禁选并标注原因；
  - 汇总行与确认按钮实时显示已选数量，未选时确认按钮禁用。
- 确认后按所选结果逐个导出：
  1. 逐个 `POST /api/exports/backtest-reports/word`，载荷
     `{report_type:'RPT-S', task_id, return_series_id}`，**不传 filename**，
     文件名走服务端标准命名（见下节）；
  2. 每个文档按响应 Content-Disposition 触发浏览器下载；
  3. 前端限速：相邻调用间隔 **2 秒**（`WORD_EXPORT_INTERVAL_MS`），叠加后端 60/min
     双重限速；
  4. 进度实时显示（"正在导出 Word 3/12：AAPL_2024_结果17"，股票/年份/结果仅作
     进度展示）；单个失败不中断，结束后汇总"成功 X 个，失败 Y 个"及原因。

## 数据可行性依据

- RPT-S 收益来源三选一（returns / task_id / Google Sheet），单品走
  `task_id + return_series_id`；任务多条收益序列时 return_series_id 必传
  （`StrategyBacktestReportService._returns_from_task`）。
- 结果列表接口每条自带 `return_series_id` 与 `parameters`（stock_code/year），
  预览载荷无需扩展。
- 每个结果的收益序列覆盖该结果自身的年份周期，逐结果出 RPT-S 即得到按年的
  单品绩效报告（与多产品页 RPT-M 的 group 形态互不影响）。

## 默认文件名升级（RPT-S / RPT-M 统一规范）

循环导出不传 `filename`，走服务端 `_default_filename` 标准命名。本次按"段间 `-`、段内 `_`"
规范升级（`strategy_backtest_report_service.py`）：

```
RPT-S  →  RPT-S-159682.SZ-20260106_20260706-20260930120000.docx
           └类型 └股票代码     └k线范围(起_止)   └时间戳

RPT-M  →  RPT-M-159682.SZ_40-000001.SZ_30-600519.SZ_30-G1-20260106_20260706-20260930120000.docx
           └类型 └组合段(代码_权重，现状保留)        └方案组 └k线范围      └时间戳
```

- **RPT-S**：task 来源无 products，组合段用收益序列的股票代码补位
  （`_returns_from_task` 现返回 `(收益行, 股票代码)`，`_resolve_source_returns` /
  `_build_benchmark_runs` 同步透传到 `generate_word`）；
- **RPT-M**：组合段（代码_权重）现状保留；新增方案组段 `G<group_key>`
  （`export_backtest_word` 按 RPT-M 重建载荷后回填 `payload.group_key`）与周期段；
- **周期段**：取组合收益首末交易日（报告真实 K 线范围），`yyyymmdd_yyyymmdd`；
- **回落链**：加权组合超长 → 纯代码（现状保留）；缺股票代码/周期/组号 → 对应段省略；
  最差退回 `RPT-<类型>-<时间戳>`；时间戳到秒，同组合多次导出不互相覆盖。
- 数据多时的定位递进：按文件名排序 → 股票聚堆 → 周期排列 → 时间戳区分重复导出；
  RPT-M 先按组合构成、再方案组、再周期。

## task 来源 RPT-S 权重表补位（修复"股票代码/成交额/ETF 资产"为空）

RPT-S 走 `task_id + return_series_id` 时载荷没有 `products`，权重表
（股票代码/股票名/权重/平均成交额/ETF 资产总数）全部渲染为单品空值。修复
（`strategy_backtest_report_service.py`）：

- `_returns_from_task` 增返回收益序列上的股票名称（3 元组：行/代码/名称），
  `_resolve_source_returns` / `_build_benchmark_runs` / `generate_word` 同步透传；
- `generate_word` 对 task 来源 RPT-S 且无 products 的请求，用
  `_task_source_product` 补位：股票代码/名称取自收益序列，`market_type` /
  `exchange_market` 取自任务 config（与 RPT-M 透传口径一致，避免纯数字港股
  代码被误判 A 股）；序列上无代码时不补位维持原状；
- 补位后权重表拿到标的身份，平均成交额走既有 K 线近半年窗口取数、ETF 资产
  总数走既有 `etf_total_assets`（东方财富源 + TTL 缓存）链路，无需新查询接口。

## /results 字段白名单投影（fields 查询参数）

不新增接口：现有 `GET /api/tasks/<task_id>/results` 增加通用 `fields` 投影参数，
**缺省（不带 fields）= 历史全量 to_dict**（CSV/详情消费方零影响）。

```
?fields=id,task_id,parameters,return_series_id,success,return_date_range
```

- 白名单常量 `TASK_RESULT_FIELD_WHITELIST`（`app/schemas/task.py`），未知字段直接 400
  （支持列表随消息下发）；`return_date_range` 为**计算字段**：批量取收益序列
  `stock_date` 首末日期 `{"start","end"}`；
- 实现：仓储 `list_by_task_fields`（`load_only` 让 result 大 JSON 不进内存 +
  `_return_date_ranges` 批量序列查询）→ 门面 `get_task_results_fields` → 路由
  fields 分支（`parse_query(TaskResultsQuerySchema)`）；
- 消费方：v2 结果分析下拉（展示 股票/名称/年份/参数/K线范围，失败附截断原因）与
  全局预览 Word 导出索引/弹窗卡片（可导出行带周期）——均不再拉 result 大 JSON；
- 设计口径：不做 `projection=light` 之类的魔法开关（会随消费方口味腐化），通用性
  落在显式字段选择上；派生数据以计算字段身份进白名单。
