# 2026-09-30 V2 绩效分析页新增「结果分析」Tab 与分析接口合并

> 同日曾实现过一版"全局预览专用 Word 导出"（专用端点 + 预览 Word 文档构建器 + 批量格式字段），
> 按需求收敛已全部撤销；全局预览的 Word 导出改由前端循环调用既有 Word 报告接口实现，方案另行记录。

## 需求

`/performance-analysis/v2` 新增一个数据来源 Tab：输入任务 ID 拉取结果 ID 下拉选择后直接分析；
也允许直接输入结果 ID（纯数字），此时不展示下拉框。
**约束：不新增接口；老的 analyze / analyze-sheet 两个端点合并为单一入口。**

## 后端（接口合并：analyze + analyze-sheet → 单一 /analyze）

- `app/routes/performance_analysis_api.py`：
  - 删除 `/analyze-sheet`，只保留 `POST /api/performance-analysis/analyze` 作为统一分析入口
    （登录 + `rate_limit_analyze` 限流，信封与原 analyze 一致）；
  - `_run_analyze` 助手随合并内联进唯一视图函数。
- `app/services/performance_analysis/service.py`：
  - 新增公开入口 `analyze(payload)`：按载荷携带的数据来源分流，
    `result_id`（结果分析）/ `spreadsheet_id`（Google Sheet）/ `data`（粘贴文本）
    三种来源互斥且必须恰好一种，否则 ValidationError(400)；
  - 原 `analyze_text` / `analyze_sheet` 收编为私有 `_analyze_text` / `_analyze_sheet`，
    新增 `_analyze_result`：经 `task_result_repository.get_export_entity` 取结果实体，
    复用 `_product_data` 提取收益序列（优先 return_series，回退结果 JSON 内嵌 `_return_date` 行），
    再走与粘贴数据完全相同的 `performance_analyzer.analyze` + `_normalize_result` 管线；
    无收益数据 → ValidationError(400)，结果不存在 → NotFoundError(404)。
- `app/schemas/performance_analysis.py`：`PerformanceAnalysisPayloadSchema`（RootModel 自由字典）
  继续作为唯一请求 Schema；来源分流与深度校验留在 service。

## 前端（老模板）

- `static/js/common/api.js`：`performanceAnalysis` 只保留 `analyze` 一个函数（`analyzeSheet` 删除），
  URL 由 api.js 唯一持有。
- `templates/performance_analysis/v2.html`：新增「结果分析」Tab（导入 Excel 之后、参数配置之前），
  含任务 ID/结果 ID 输入框与结果下拉框（默认隐藏）。
- `static/js/pages/performance_analysis_v2.js`：
  - `requestV2Analysis` 去掉 endpoint 直传参数，固定走
    `Api.endpoints.performanceAnalysis.analyze`（envelope + abort signal 语义不变）；
    Google Sheet / 粘贴数据 / 结果分析三个 Tab 的调用点同步收敛；
  - 纯数字输入视为结果 ID → 隐藏下拉、直接分析；其余视为任务 ID → 回车/失焦触发
    `Api.endpoints.tasks.results` 拉取结果列表（失败结果在下拉中禁用并标注）；
  - 分析按钮可用性与 `runActiveV2Analysis` 分发接入 result-tab；
  - 渲染复用既有 renderSummary/renderTables/renderCharts 管线，runtime_params 与其它 Tab 同源；
  - Word 报告导出已接入：分析成功后 `state.wordReportPayload` 带上
    `{report_type:'RPT-S', task_id, return_series_id, runtime_params}`（下拉路径取自
    结果列表、直接输 ID 路径经 `/api/results/<id>` 详情补齐），导出弹窗的股票预填为
    被分析结果自身的股票（`wordExportStockPreset`，打开时可改）。
  - 下拉选项展示富信息：`结果 id · 股票代码 · 股票名称 · 年份 · 参数 a/b · K线范围起 ~ 止`，
    失败结果禁选并附截断原因；数据走 `/api/tasks/<id>/results?fields=...` 白名单投影
    （不含 result 大 JSON，见《全局预览Word导出》文档）。
- V1 首页（performance_analysis_index.js）本就调用 `analyze`（data 来源），零改动。

## 接口收敛前后对照

| 旧 | 新 |
|---|---|
| `POST /api/performance-analysis/analyze`（data） | `POST /api/performance-analysis/analyze`（统一入口） |
| `POST /api/performance-analysis/analyze-sheet`（spreadsheet_id） | 并入统一入口（载荷带 `spreadsheet_id`） |
| 结果分析（曾考虑新增 `/analyze-result`） | 并入统一入口（载荷带 `result_id`），**不新增端点** |

## 测试

`tests/integration/test_xpl_v2_page.py`：扩展页面 DOM 断言（result-tab / 输入框 / 下拉框），
新增 3 例接口测试——均打合并后的 `/analyze`（result_id 来源）：成功分析带序列结果、
无收益数据 400、结果不存在 404；原粘贴文本用例不变，天然覆盖同一入口的 data 分支。
