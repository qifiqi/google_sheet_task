# 2026-10-01 MySQL 密码出库与 nb3 导入工具移除

## 背景

安全审查（`fc44c28..533c2b1` 全量审查）发现两处问题：

1. **高危**：MySQL root 密码明文入库——`dockers/docker-compose.yml`（environment +
   healthcheck）、`dockers/nb3-import/import-nb3.sh` 默认值、`dockers/构建.md` 示例、
   `docs/model_update/2026-09-29-*` 文档共 6 处同一明文。该库仅绑 `127.0.0.1` 内网使用，
   实际暴露面小（用户评估），但违反仓库"凭据不入源码/日志/测试"红线，按最小成本改为
   env 注入。
2. **决策变更**：nb3 备份导入工具（`dockers/nb3-import/` 四件套：01_schema.sql /
   data_order.txt / import-nb3.sh / table_headers.tsv）废弃，存量数据改用 SQL 文件导入，
   整目录移除（git 历史可找回）。

## 变更内容

### MySQL 密码改 env 注入

- `dockers/docker-compose.yml`：
  - `MYSQL_ROOT_PASSWORD: "${MYSQL_ROOT_PASSWORD:?请在 dockers/.env 设置 MYSQL_ROOT_PASSWORD}"`
    ——缺失时 compose 直接报错（fail-fast），不落明文；注释掉的 postgres 块同步改为
    `${POSTGRES_PASSWORD:?}` 占位；
  - healthcheck 改 `CMD-SHELL` + `$$MYSQL_ROOT_PASSWORD`（`$$` 转义后由容器内 shell
    读自身环境变量），compose 文件不再出现密码。
- 新增 `dockers/.env.example`（入库的样例）：服务器上 `cp .env.example .env` 后填真实
  密码；`dockers/.env` 被 `.gitignore` 的 `.env` 规则覆盖，不会入库。docker compose 以
  compose 文件所在目录为项目目录，自动加载该 `.env` 做变量替换。
- `dockers/构建.md` 的 `docker run` 示例改引用环境变量。
- `docs/model_update/2026-09-29-*` 中两处明文密码改为变量引用（历史文档同步勘误）。

### nb3 导入工具移除

- `git rm -r dockers/nb3-import/`（脚本上的 MYSQL_PWD 加固随目录一并废弃）；
- `docker-compose.yml` mysql 服务注释同步：数据来源描述改为"SQL 文件导入"；
  **mysql 服务本身保留**（存量数据仍在该库中）。

## 注意事项

- **git 历史仍留有该密码**（fc44c28..533c2b1 多个提交）。内网回环 + 迁移期数据库，
  经评估不做强制轮换；若后续放开网络暴露面，需先轮换密码。
- 服务器升级步骤：`cd dockers && cp .env.example .env`，填入现用密码后
  `docker compose up -d`；`.env` 不入 git，需自行备份。
- 仓库内另有两处**存量**明文（本轮未动，属历史遗留）：`README.md:152,254` 的
  `Hello12345*`（PG 连接串，密码不同）与 `tests/archive/legacy_drawer/`（已被
  norecursedirs 排除）。建议后续顺手清理。

## 影响面

- 不涉及应用代码、数据库 schema 与数据；
- 服务器上重新 `docker compose up` 前必须先放置 `dockers/.env`，否则 mysql 服务
  启动即报错（这是有意的 fail-fast）。
