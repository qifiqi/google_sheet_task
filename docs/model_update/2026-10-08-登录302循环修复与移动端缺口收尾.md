# 登录 302 无限刷新循环修复 + 移动端适配缺口收尾

- 日期：2026-10-08
- 分支：dev_vue
- 触发：①用户实测登录时页面无限刷新、无法登录，手动清空浏览器缓存后恢复；②移动端适配复核（对照 `docs/design/mobile-adaptation-audit-2026-09/`）发现两个收尾缺口
- 改动面：纯前端 3 个静态文件（`static/js/template-auth.js`、`static/js/common/components/navbar.js`、`static/css/pages/weight_combination.css`），0 个 `app/` 后端文件

## 1. P0：登录页 ↔ 目标页 302 无限刷新循环

### 1.1 根因（双通道登录态分歧）

页面鉴权有两条互不知情的通道：

| 通道 | 使用方 | 生命周期 | 修复前的问题 |
| --- | --- | --- | --- |
| localStorage `access_token` | 页面 JS（`/api/auth/me` 带 Authorization 头；登录页自动跳转的判据） | 持久，access token 有效期 2h（`app/utils/auth.py:71`） | 浏览器重启后仍在 |
| cookie `gsc_access_token` | 服务端 `page_login_required`（页面导航带不了自定义头，只能回退读 cookie，`app/utils/auth.py:179-188`） | **会话级**（`setTokens` 写 cookie 未带 Max-Age） | 浏览器一关就没 |

浏览器重启（或任何 cookie 丢失/被顶场景）后 localStorage 里的 token 仍在有效期内时：

1. 打开任意受保护页 → 服务端守卫：无 cookie → 302 `/login?next=...`；
2. 登录页 `bindLoginPage`：`getToken()` 为真 → `/api/auth/me`（走 Authorization 头）成功 → `location.replace(next)`；
3. 目标页导航仍无 cookie → 守卫 302 弹回 `/login` → 回到第 2 步，**无限刷新**，登录表单永远被自动跳转顶掉，无法输入。

清空站点数据清掉了 localStorage → `getToken()` 为假 → 表单得以驻留 → 重新登录重写两条通道 → 恢复。与用户实测现象完全吻合。

### 1.2 修复（`static/js/template-auth.js`，两层）

1. **cookie 生命周期与 token 对齐**：新增 `getAccessTokenMaxAgeSeconds()`（客户端解码 JWT payload 取 `exp`，base64url + UTF-8 解码），`setTokens` 写 cookie 时带上 `; Max-Age=<exp-now>`。此后两条通道同生命周期，浏览器重启后一起消失/一起有效，分歧来源消除。解析失败（`null`/`exp<=0`）保持原会话 cookie 行为，**绝不写 `Max-Age=0`（会误删 cookie）**。登录、refresh 轮换、SSO 换票三个入口都经 `setTokens`，无需逐点改。
2. **登录页防弹跳护栏**（对"cookie 被本机其他服务同名 HttpOnly cookie 顶死"这类通道性故障兜底，见 `app/utils/auth.py:18-20` 前科）：登录页发起的所有"跳往 next"统一收敛到 `leaveLoginForNext()`（打标 `sessionStorage.templateLoginBounceAt`）；`bindLoginPage` 入口 `canAutoLeaveLogin()` 检查——**10 秒内刚发生过跳转-弹回，则不再自动跳转**，展示登录表单并提示"登录跳转被页面鉴权拦回（浏览器 Cookie 与本地登录状态不一致），请重新登录；若反复出现，请清理浏览器缓存后重试"。表单手动提交不受门禁（用户显式动作），但其跳转同样打标——若 cookie 通道仍不通，弹回后护栏生效，循环变为"可见的表单 + 提示"。sessionStorage 不可用（隐私模式）时护栏退化为不生效，不劣于现状。

### 1.3 行为变化说明

- 正常登录/已登录访问 `/login` 自动跳转的行为不变（单次跳转不打扰）。
- 登录后 10 秒内手动回退到 `/login` 会看到表单而非自动跳走（护栏窗口内），重新提交即可，属可接受的鲁棒性代价。
- 未触碰 SSO 换票逻辑本身（`consumeSsoTokenFromHash`/`performSsoExchange` 原样），仅其成功跳转改走打标出口。

## 2. 移动端适配收尾（对照 2026-09 审计报告的遗留复核）

### 2.1 legacy 书签路径整页无导航

`/backtest/*`、`/backtest-multi/*`（`app/routes/pages/backtest_training.py:12`、`backtest_multi_product.py:12` 的 legacy 蓝图）与正式路径渲染同一组模板，但 `navbar.js` 族前缀表只有 `/backtest-training`、`/backtest-multi-product`——legacy 路径匹配不到族，`[data-navbar]` 挂载点被移除，**桌面和手机都没有侧栏**（手机端意味着无法跳转、无法退出登录）。修复：admin 族前缀补 `/backtest`、`/backtest-multi`（navbar.js 头部注释登记为 D8 修订）。11 个 legacy 页面（training 6 + multi 5）自动恢复导航。

### 2.2 weight_combination 筛选弹窗窄屏断列

`.wc-filter-popup` 固定 236px + `__body` 双列 grid + label `white-space: nowrap`，≤575.98px 时"单股下限(%)"等标签处于溢出临界（2026-09 修复批只处理了选品表格部分，弹窗未动）。修复：在既有 `@media (max-width: 575.98px)` 块内补弹窗宽度 `min(calc(100vw - 1.5rem), 20rem)`、grid 断单列、label 允许换行；横向越界由 `positionFilterPopup` 既有的视口收口（`Math.max(8, Math.min(left, innerWidth - pw - 8))`）兜底。
