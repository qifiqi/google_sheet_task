# 2026-10-02 钉钉告警移除本地手机号取数

## 背景

db→http 迁移完成度检查登记的 P1 待办（`docs/design/db-to-http-migration/` §6.3 ⚠️）：
`utils/ding_talk_notifier.py` 的 @ 手机号机制读本地 User 表（值班开发者 + 任务创建人手机号），
纯 http 部署下本地用户表不再维护，收件人恒失效。用户裁决：**直接移除手机号机制**
（不接主 Web 接口，后续有需要再立项）。

排查中还发现同类隐患：http 后端 `RemoteRecord` 无 `created_by` ORM 关系，
`send_task_notification` 里 `task.created_by.username` 在 http 模式会直接 `AttributeError`
（不止手机号，创建人显示同样依赖本地表）——本次一并处理。

## 变更内容（`app/utils/ding_talk_notifier.py`）

- 删除 `_collect_oncall_developer_mobiles` / `_collect_at_mobiles` /
  `_normalize_mobile` / `_mask_mobile` / `DEV_ROLE_CODES` 与 `auth_repository` import：
  告警不再 @ 任何手机号，`payload["at"]` 仅保留 `isAtAll: False`；
- `_build_markdown_text` 去掉 `at_mobiles` 参数与 @ 行拼装；
- 新增 `_creator_display_name(task)`：db 后端保持本地用户名；http 后端经
  `getattr(task, "created_by", None)` 兼容 RemoteRecord 缺关系键（AttributeError → None），
  退化为 `created_by_user_id`，两者皆无则 `系统/未知`；
- 发送日志去掉手机号字段（顺带消除一处敏感信息打码需求）。

`auth_repository.list_alert_oncall_active_entities` 方法保留（db 回退模式的本地能力，
test_repositories 仍覆盖）；仅通知器不再消费。

## 影响面

- 钉钉告警消息格式：不再有 "@手机号" 尾行；db 模式创建人显示不变，http 模式由报错变为显示用户 ID；
- 不涉及接口、任务执行链与数据库；
- 回归：全量 `pytest tests/unit tests/integration` 与基线一致（失败集仍为 db_to_http
  既有基线的子集，零新增）。

## 关联
