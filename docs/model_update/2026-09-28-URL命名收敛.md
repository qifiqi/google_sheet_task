# URL 命名收敛（2026-09-28）

## 背景

[2026-09-28-接口规范审计与修复.md](2026-09-28-接口规范审计与修复.md) 将"URL 前缀存在多套约定"登记为已知债务（当时评估收敛成本高收益低）。本次审计确认了五处命名不一致并全部修复，收敛后全库 URL 遵循单一约定：

- 路径段一律 **kebab-case**（snake_case URL 清零）；
- 管理 API 统一 **`/api/admin/*`**；
- JSON API 一律含 `/api` 段（页面除外），`errors.py` 信封判定不再依赖 Accept 兜底管理端；
- 批量动作统一 **`batch-<动词>`**（`batch-create` / `batch-export`）；
- 蓝图前缀定义位置统一：**页面蓝图在定义处，API 蓝图在 `app/routes/__init__.py` 注册处**（不再两处重复声明）。

## URL 变更明细

| 旧 URL | 新 URL | 文件 |
|---|---|---|
| `/admin/api/dashboard/overview`、`/admin/api/model-summary*`、`/admin/api/word-export-cache*`、`/admin/api/tasks/<id>/runtime-detail` | `/api/admin/...`（同尾段） | `admin_api.py`（前缀 `/admin`→`/api/admin`，路由去 `/api/` 前导） |
| `/performance_analysis/analyze` | `/api/performance-analysis/analyze`（粘贴文本） | `performance_analysis_api.py` |
| `/performance_analysis/v1/analyze` | `/api/performance-analysis/analyze-sheet`（Sheet 链接） | 同上 |
| `/performance_analysis/v1/weight_combination(/products)` | `/api/performance-analysis/weight-combination(/products)` | 同上 |
| 页面 `/performance_analysis`、`/performance_analysis/v2`、`/performance_analysis/weight_combination` | `/performance-analysis`、`/v2`、`/weight-combination` | `pages/performance_analysis.py` |
| 页面 `/global-preview/single_product` | `/global-preview/single-product` | `pages/global_preview.py` |
| `/api/exports/tasks/batch`、`/api/exports/global-previews/batch` | `.../batch-export` | `export_api.py` |
| `/api/exports/performance_analysis` | `/api/exports/performance-analysis` | `export_api.py` |
| `/api/google-sheet/worksheets` | `/api/google-sheets/worksheets`（与资源 CRUD 复数对齐） | `google_sheet_api.py` |

说明：`/analyze` 与 `/v1/analyze` 并非重复实现（`analyze_text` vs `analyze_sheet` 两个动作），修复方式是去掉版本段并按动作命名（`analyze` / `analyze-sheet`），端点语义不变。全库无 URL 版本段。

## 补记：回测子域并入 /api（同日第二轮）

部署排查发现 nginx 模式 A（`docs/design/frontend-refactor/05-deployment.md`）只反代 `location /api/`，三个业务域 API 前缀（`/backtest-training/api/*`、`/backtest-multi-product/api/*`、`/global-preview/api/*`）会掉进页面 try_files 规则被当页面 404。根因是页面与 API 共用前缀，网关必须逐条区分——与管理端 `/admin/api/*` 问题同构，随即按同一逻辑收敛：

| 旧 URL | 新 URL |
|---|---|
| `/backtest-training/api/**` | `/api/backtest-training/**` |
| `/backtest-multi-product/api/**` | `/api/backtest-multi-product/**` |
| `/global-preview/api/**` | `/api/global-preview/**` |

- 实现：三个蓝图前缀在注册处改为 `/api/<域>`，`backtest_api.py`（10 处）与 `global_preview_api.py`（2 处）路由去掉 `/api/` 前导；endpoint 名与 wire 格式不变。
- 调用方同步：`api.js` 15 处、`app/schemas/backtest.py` docstring 3 处、活测试 8 个文件 21 处、`tests/scripts/` 两个下载脚本。
- 收益：全部注册 JSON API 统一 `/api/<域>/**` 单命名空间；nginx / Vite proxy 各只需一条 `/api` 规则；`errors.py` 的 `startswith("/api")` 即覆盖全部注册路由（`"/api/" in path` 与 Accept 启发式降级为非注册路径兜底，注释已更新）；`05-deployment.md` nginx 示例在 API 反代处注明子域已并入。
- 验证：url_map dump 15 条新路由就位、无冲突；受影响 8 个测试文件 81 passed（1 个失败为本文上节已确认的基线既有失败，与本轮无关）。
