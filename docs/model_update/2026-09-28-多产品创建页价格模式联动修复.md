# 多产品创建页价格模式联动修复（2026-09-28）

## 背景

用户反馈：多产品（backtest_multi_product）创建页"价格模式没有联动"——顶部全局
Google Sheet 链接指向 C7.0.3 模板时，全局价格模式仍显示"收盘价"，只有部分产品卡片
在各自识别后被切到 OHLC，且该值随后可能被全局设置变化覆盖回收盘价。

后端事实：`app/services/backtest_multi_product_service.py::_build_product_kline`
对 C7.0.3 模板**无条件强制 `ohlc_price`**（与单品回测 `get_bdl` 行为一致），前端传
什么都不影响执行结果。因此本次是纯前端修复，目标是**界面显示与实际生效一致**，
后端零改动。

## 原问题链路（修复前）

1. C7.0.3 检测只存在于产品卡片级 `applyPriceModeDefault(card, title)`，由卡片自身
   Sheet 识别成功后触发；顶部全局价格模式下拉从不参与检测。
2. 卡片被自动切到 OHLC 后**未加锁**（不设 `priceTouched`），此后用户改全局市场/
   复权/数据源等任意字段都会触发 `applyGlobalSettingsToCards()`，把未手动改过价格
   的卡片统一覆盖回全局值（收盘价），C7.0.3 默认值被静默冲掉。
3. `analyzeSheet` 对同一 spreadsheetId 有成功即跳过的早退，被冲掉的值不会因重新
   分析而恢复。

## 修复内容

改动文件：

- `static/js/pages/backtest_multi_product_create.js`
- `templates/backtest_multi_product/create.html`

### 1. 全局链接单独识别，驱动全局价格模式默认值

新增 `analyzeGlobalSheet()`（500ms 防抖，随全局链接 input 触发）：

- 复用 `Api.endpoints.googleSheet.worksheets` 识别全局链接标题；
- 识别成功后调用 `applyGlobalPriceModeDefault(title)`：标题含 `C7.0.3` →
  全局价格模式自动切 `ohlc_price`，否则回 `sp_price`；随后经既有的
  `applyGlobalSettingsToCards()` 下发到所有未自定义的产品卡片；
- 全局价格模式**手动改过即锁定**（`dataset.touched`，程序赋值不触发 change），
  之后不再跟随 C7.0.3 自动切换；
- 顶部新增 `#globalSheetInfo` 状态行（识别中/成功/失败），成功时显示
  `标题 / sheet`，与卡片级 `sheet-info` 行为对齐。

产品卡片继承同一全局链接时仍各自识别——卡片还需标题推断模型版本（C3/C5/C7
参数表结构），该链路不变。

### 2. 卡片级检测的锁定语义

`applyPriceModeDefault(card, title)` 重写：

| 场景 | 行为 |
|---|---|
| 用户手动改过卡片价格模式（`priceModeTouched`） | 不再自动切换（原行为不变） |
| 卡片**自有链接**识别为 C7.0.3 | 切 OHLC 并锁定（`priceTouched` + `priceModeAuto`），不再被全局价格模式下发覆盖 |
| 卡片**继承全局链接**识别为 C7.0.3 | 只切值不锁定，跟随全局（全局此时已自动切 OHLC，两值收敛） |
| 自有链接从 C7.0.3 换成其他模板 | 自动解锁并回到全局当前值 |
| 普通非 C7.0.3 识别（未锁定过） | 不动值（卡片创建时已继承全局默认，后续跟随全局变化） |

修复前"非 C7.0.3 一律强制 `sp_price`"的行为移除，避免覆盖全局非默认值。

### 3. 提示补齐

全局与卡片的价格模式下拉均加 `title`：识别到 C7.0.3 Sheet 时自动切换为 OHLC，
手动修改后不再自动切换。

## 联动效果（修复后）

- 全局链接指向 C7.0.3 → 全局价格模式自动变 OHLC → 所有未自定义卡片同步 OHLC；
- 某产品自有 C7.0.3 链接 → 该卡片自动 OHLC 并锁定，改全局价格模式不影响它；
- 用户手动选择（全局或卡片级）永远优先，自动切换不再打扰；
- 后续新增产品卡片在创建时即继承全局当前值（含自动切换后的 OHLC）。

## 后端校验（2026-09-29 补充）

前端联动修复后，后端在创建期增加按产品的 C7.0.3 价格模式校验
（`app/services/backtest_multi_product_service.py::normalize_multi_product_config`，
仅创建链路调用，`task/creation.py`）：

- **显式指定非 OHLC** 的 C7.0.3 产品 → `ValidationError`：
  `产品 N（产品名）使用 C7.0.3 模板，价格模式必须为 OHLC（开高低收）`；
- **未显式指定**价格模式的 C7.0.3 产品 → 直接归一为 `ohlc_price`（不再回退
  全局默认 `vwap_price`）；
- 混排的非 C7.0.3 产品不受影响（`_is_c7_0_3` 按产品自己的 `sheet.title` 判断，
  C3/C5 子产品既不被强制也不被拒）；
- 存量任务**重启不受影响**：`task/restart.py` 不重跑 normalize，执行期
  `_build_product_kline` 的 OHLC 强制继续兜底。

模板版本混排说明：多品回测按"行号对齐"组合方案，每个产品独立 Sheet、独立参数
格式（参数行 2 列按 C5/C7 的 `xm:/ml:` 单元格写入，其他按 C3 位置写入），因此
C3 与 C7/C7.0.3 产品**允许混排**，前后端均不限制，已固化测试
`test_normalize_multi_product_config_allows_mixed_c3_and_c7_0_3_products`。

## 全局参数表（2026-09-29 补充实现）

按此前设计分析落地"顶部设一遍、产品卡片跟随、改动即脱钩"的全局参数基线。
改动文件仍为 `create.html` / `backtest_multi_product_create.js` /
`backtest_multi_product_create.css`，**提交 payload 结构不变，后端零改动**。

### 交互结构

- 顶部工具卡新增可折叠"全局参数"区（默认展开）：模型徽章 + 工具栏
  （添加行/粘贴追加/复制参数/帮助）+ 参数表，列结构与产品卡片参数表完全一致
  （同一 `FIELD_MAP`，同列对齐）。
- 该区实现为"伪卡片"（`data-is-global-param="1"`）：直接复用卡片参数表的全部
  工具函数（加行/粘贴/复制/帮助弹层/行收集）；`getCardMarketType` 对伪卡片改读
  全局市场下拉，全局市场决定全局表 C3 手续费默认值。
- 全局 Sheet 识别状态行（`#globalSheetInfo`）放在全局设置行下方、说明文字上方
  （`col-12` 内正常文档流），不参与链接列高度，保证全局链接输入框底边与
  "市场"等下拉框对齐（该列内放状态行会把输入框顶高 20px）。

### 下发与脱钩规则

| 场景 | 行为 |
|---|---|
| 全局表任意编辑（输入/加行/删行/粘贴） | 250ms 防抖后整表下发到所有"未自定义参数 且 模板版本一致"的产品卡片 |
| 卡片参数表手动编辑（输入/加行/删行/粘贴） | 立即脱钩（`paramTouched`）：显示"参数已自定义"徽标 + "重置为全局参数"按钮 |
| 全局后续变化 | 只影响未脱钩卡片；脱钩卡片保持不动 |
| 点击"重置为全局参数" | 清除脱钩标记并整表重新拉取全局参数；版本不一致时提示未跟随 |
| 新增产品卡片 | 创建时继承全局参数行（版本一致且有内容时） |
| 全局 Sheet 识别切换模板版本 | 全局表重置为对应版本空表并下发；卡片版本由各自 Sheet 识别，随后自动重新对齐 |
| 全局市场切换 | 全局表空行手续费默认值刷新，并按各卡片市场重新换算下发 |

- C3 手续费列按市场换默认：下发时命中"全局市场默认值"的单元格替换为目标
  卡片市场默认值（A股 0.035% ↔ 美股 0.002%），自定义手续费原样透传。
- 版本不同的卡片（如全局 C7、卡片自有 C3 Sheet）跳过继承——参数列结构不同，
  无法直接复制，需自行填写；后端行号对齐校验保持不变。
- 行数对齐由下发机制保证：跟随卡片的行数恒等于全局表行数。

### 验证

浏览器实测（admin 登录后）全链路通过：下发、脱钩徽标、脱钩隔离（全局改值时
脱钩卡片不动、未脱钩卡片跟随）、重置回全局、美股卡片手续费自动换 0.002%、
市场联动数据源 Yahoo。`tests/integration/test_static_pages.py` 除既有 `/admin/`
302 存量失败外全部通过。

## 数据源联动股票（2026-09-29 补充）

规则：**非 A股产品一律使用 Yahoo 数据源**，联动入口从"市场下拉/搜索建议点选"
扩展到"手动输入股票代码"。

- **手输代码推断市场**（`applyStockMarketInference`，600ms 防抖）：与后端
  `infer_market_type` 同规则——标准后缀（`.SH/.SZ/.BJ/.SS→cn`、`.US→en`、
  `.HK→hk` 等）优先，无后缀纯数字 → cn，其余 → en；含中文等非代码字符
  （股票名称）不推断。推断切换市场后同步刷新手续费默认值与数据源。
- **以用户选择为准**：点过搜索建议或手动选过市场（`marketManual` 标记）后
  不再自动推断。
- **数据源双向联动**（`syncCardDataSourceWithMarket`）：非 A股 → Yahoo；
  切回 A股时，仅当 Yahoo 是联动自动切的（`sourceAuto` 标记）才恢复默认
  AKShare。用户手动选的数据源（卡片级/全局级）任何市场切换都不覆盖。
- **全局市场对称联动**：非 A股 → 全局数据源 Yahoo；切回 A股恢复 AKShare
  （同样只恢复自动切换的值）。
- 顺手修复：产品摘要市场标签原来只有"A股 cn/美股 en"两种，香港等市场误显示
  为"A股 cn"，现按全局市场下拉的选项文案展示（如"香港 hk"）。

浏览器实测通过：`AAPL→en/yahoo/0.002%`、`600519→cn/akshare/0.0350%`（自动恢复）、
`0700.HK→hk/yahoo`、中文名不误判、全局 en↔cn 对称、卡片与全局的手动数据源
均不被自动逻辑覆盖。
