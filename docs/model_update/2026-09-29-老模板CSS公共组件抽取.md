# 老模板 CSS 公共组件抽取

- 日期：2026-09-29
- 分支：dev_vue
- 前置：`docs/design/mobile-adaptation-audit-2026-09/`（移动端审查）与同日移动端修复
- 目标（用户验收点）：拆分后样式不乱、颜色规范、布局规整对齐、主题切换顺畅
- 验证：浏览器实测（1280/375 × 明暗主题，覆盖 C3 详情、回测列表/详情、全局预览、admin/logs）+ `test_static_pages.py` 42 项全绿 + 全量回归无新增失败

## 1. 背景

静态化迁移时各模板内联 `<style>` 按"原样抽离"红线搬入 `static/css/pages/*.css`，迁移期禁止顺手去重，重复成为遗留。本次为收尾性独立重构，与移动端修复分属两批改动。

重复盘点（按定义出现文件数）：`.log-container` ×8（含 theme.css 一处死代码）；`backtest_training_detail.css` 是 `backtest_multi_product_detail.css` 的逐字子集；`backtest_training_list.css` 与 multi 版前 208 行逐字相同；两个回测 global_preview CSS 共享壳层逐字相同（存在一处漂移：`.header-toolbar` 阴影 training 有、multi 无）；C 系列四个详情 CSS 中 c4≡c5≡c7，与 C3 共享 `#results-table`/`.result-content`/`.log-container` 等块。

| 动作 | 文件 | 说明 |

## 3. 颜色规范（验收点：颜色规范、主题切换顺畅）

1. **变量化**：抽取时把仅适配亮色的硬编码统一替换为主题变量，暗色自动跟随——
   - `.result-content pre`：`#f8f9fa/#e9ecef` → `var(--bs-tertiary-bg)/var(--bs-border-color)`；
   - `.detail-sheet-item`/`.detail-config-item`：`#e9ecef/#f8f9fa/#fff` → `var(--bs-border-color)/var(--bs-tertiary-bg)/var(--bs-body-bg)`；
   - `.detail-config-label/#6c757d` → `var(--bs-secondary-color)`，`.detail-config-value/#212529` → `var(--bs-body-color)`；
   - `#results-table tr:hover` `rgba(0,123,255,.05)` → `rgba(var(--bs-primary-rgb), .05)`；
   - C3 专有 `.result-summary-*` 同步变量化（留在页面文件）。
2. **双声明兜底**：`.summary-parameter-cell` 的 `color-mix()` 前置 `background: var(--bs-tertiary-bg)` 回退（实测发现部分内核 color-mix 解析失败导致冻结列透底，双声明根治）。
3. **明暗成对保留**：终端日志配色（`#0b1220/#dbeafe`）与 metric-card 石板色板为刻意主题无关/成对设计，保留定值并加注释说明。
4. **滚动条暗色补齐**：`.result-content` 细滚动条增加 dark 覆盖。

## 4. 主题切换修复（本轮实测发现并修复）

实测发现 **google_sheet 族 9 页不加载 `theme.css`**，全部主题变量（`--bs-tertiary-bg` 等）在该族未定义——变量化后组件会丢边框/底色，且该族页面原本完全不支持暗色。已为 4 个 C 系列详情页补挂 `theme.css`：

- 变量在亮色下解析回原值（`--bs-tertiary-bg=#f8f9fa` 与原硬编码一致），亮色零漂移（截图比对确认）；
- 暗色下正文/卡片/表格/摘要格完整生效——C 系列详情页首次获得可用的暗色模式（此前亮色锁定）。

## 5. 布局规整（验收点：布局规整对齐）

统一了孪生文件间的一处真实漂移：multi 全局预览 `.header-toolbar` 缺失阴影（training 有），抽取后统一为 training 版本；其余孪生块逐字相同，无行为差异。页面级覆盖（如 multi 两行式表头预览表、admin/logs 600px 日志区）经级联顺序验证保持原样。

## 6. 级联与加载顺序保证（验收点：样式不乱）

- 加载顺序：bootstrap → template-auth → theme（→ sidebar）→ **components** → pages/*.css；components 永远先于页面 CSS，页面覆盖能力不变。
- 全作用域敏感规则（`.badge`/`.pagination`）不抽取，避免波及未使用页面。
- 宽选择器 `.col-4 + .col-8` 抽取前已 grep 确认 11 个加载页模板无 `col-4` 结构冲突。
- theme.css 中删除的仅是旧版 `.log-container`（400px 绿字死代码）；另有两条与暗色覆盖冗余的规则（`.param-card .card` 暗色、`#taskNameText` 暗色）是在**页面 CSS**（`backtest_training_detail.css` / `backtest_multi_product_detail.css`）抽取时删除的，行为无变化（theme.css 全局暗色同值覆盖）。

## 7. 测试与验证

- **浏览器实测**（预览环境 + mock 数据）：1280×900 / 375×812 × 明暗主题，覆盖 C3 详情（结果摘要格/日志区/表格）、回测列表（指标卡四态暗色）、回测详情、全局预览（工具栏阴影/空态）、admin/logs（600px 日志区与级别配色）；布局与抽取前一致，颜色存在向主题变量统一的微小变化（pre 边框 `#e9ecef`→`#dee2e6`、hover 蓝、滚动条、muted 文本色等，属 §3 变量化的预期结果，非回归）。
- **静态页测试**：42 项全绿（模板仅加 link 行，零 Jinja 残留）。
- **全量回归**：743 通过、16 失败与抽取前完全一致（均为 stock_sdk/dfcf 等外部行情 API 网络超时的存量环境性失败），无新增失败。

## 8. 后续约定

- 新页面样式：共享组件写进 `components.css` 对应分节；页面私有写 `pages/<页>.css`；禁止再复制组件定义。
- 三份"注释占位"空文件（training 的 detail/list/global_preview css）保留以维持模板 link 有效，可作页面级覆盖入口。
