# 2026-09-21 Word 导出文件名携带每股权重

## 需求

策略回测 Word 报告（RPT-S/RPT-M）导出文件名原来只含产品代码与时间戳（`RPT-M-600519-SCHD.US-20260921103456.docx`），同一任务用不同权重配置多次导出时无法从文件名区分。需要在文件名中体现每股的权重。

## 最终格式

```
RPT-M-600519_50-SCHD.US_50-20260921103456.docx
RPT-M-510300_33.33-510500_66.5-510800-20260921103456.docx
```

多产品按 `代码_权重` 拼接（`-` 分隔产品对，`_` 连接代码与权重）；权重为百分比数字，不带 `%`、不带括号。

## 方案与取舍

- **改动位置**：只改 `_default_filename`（`app/services/strategy_backtest_report_service.py`）。文件名是服务端唯一生成点，经 Content-Disposition 下发，前端（静态页与 Vue）从响应头取名保存，无需任何前端改动。
- **权重口径**：与报告内"策略权重"表**同源**：`normalize_weight` + `_weight_percent_text`（百分比数字去尾零）。接受 `30`、`30%`、`0.3` 三种写法，统一折算为百分比数字（`0.665` → `66.5`）。比例缺失/非法的产品只拼代码（与 `_is_zero_weight_product` 的容错口径一致）；比例为 0 的产品本就不参与命名。
- **权重不带 `%` 后缀（踩坑记录）**：第一版用了 `50%`，导出报 `URI malformed`。原因：纯 ASCII 文件名 Flask/Werkzeug 不做百分号编码，`Content-Disposition` 头原样携带 `50%`，前端 `decodeURIComponent` 把 `%)-` 当作非法转义序列直接抛 URIError。因此文件名中禁用裸 `%`。
- **不用括号**：`代码(权重)` 可行但徒增符号长度，按需求简化为 `代码_权重`。
- **单品不拼权重**：单产品（RPT-M 降级 RPT-S 或单品报告）权重恒为 100%，文件名保持 `RPT-S-CODE-` 形式。
- **超长回落**：加权形式总长超过 180 字符时回落纯代码形式，保护 Windows 路径长度限制。
- **缓存版本**：`app/utils/ttl_cache.py` 的缓存键版本 `word-export:v2:` → `v5:`（每轮格式调整递增一次）。缓存 sidecar 存有首次生成的下载文件名，不递增版本会让旧格式文件名在 TTL 内继续下发。

## 影响

- 纯文件名展示变化，报告内容、指标计算、缓存命中逻辑均不变。
- 附带对齐了同文件并发的 `平均成交额 (半年)` 表头改名对应的 3 个测试断言。
- 测试：更新 `test_default_filename_keeps_rpt_m_with_multiple_active_products`，新增百分比/小数比例折算、超长回落两个用例（`tests/unit/test_strategy_backtest_report_service.py`）。
- 已知残留风险（未处理）：前端各页面 `decodeURIComponent(Content-Disposition)` 的解析是散落的重复代码，任务名等用户输入含 `%` 时其他导出（如 xlsx）也会报同样错误；如需根治应抽公共解析函数并加 try/catch 回退。
