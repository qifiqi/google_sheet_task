# 修改文档：登录会话优先级（本地已有会话优先，SSO 换票兜底）

- 日期：2026-09-18
- 分支：dev_vue
- 范围：登录页会话判定（`/login` 落地时的本地会话复用与 `#sso_token` 换票顺序）
- 性质：行为修正 + 口径确认（不涉及后端接口、不涉及数据库 schema/迁移/数据）

## 背景

登录页此前把「URL 携带 `sso_token`」当作最高优先级：只要 fragment 里有 token 就先换票，
换票失败（如主服务 token 已过期/被回收）才报错。副作用是——用户在本服务已有可用会话
（localStorage 里的 access/refresh token 仍有效），仅因从主服务二次点击链接进来且带的
是过期 token，就会被打断甚至顶掉会话。

同时本服务是长时运行任务平台，本地会话承载"正在看的任务、页面权限"，其价值高于
入口身份断言。

## 口径（已确认）

**本地已有可用会话 → 复用并跳转；本地无会话或会话彻底失效 → 才用 sso_token 换票。**

判定顺序（`static/js/template-auth.js::bindLoginPage`）：

1. `getToken()` 存在 → `fetchCurrentUser()`（内含 401 自动 refresh 续期）：
   - 成功 → `location.replace(next)`，fragment 中的 sso_token 读完即弃（`consumeSsoTokenFromHash`
     仍会立即 `replaceState` 清掉 fragment，不留在地址栏与历史里）。
   - 失败 → `clearAuthState()` 清本地会话；此时若带到 sso_token，继续走换票。
2. `getToken()` 不存在，但带到 sso_token → 换票 `POST /api/auth/sso/exchange`；
   失败展示错误并保留账号密码登录兜底。
3. 两者都没有 → 保持账号密码登录表单。

## 已知后果（已接受，登记备查）

同一浏览器先后被**不同主服务账号**使用时（换账号、共用终端），第 1 步会沿用上一次
换票得到的本地身份，子服务会以旧身份展示数据。需要切换身份时必须先在子服务退出登录
（清 localStorage + `gsc_access_token` cookie）再进入。

若后续要求"入口身份必须实时生效"，改法是让 sso_token 优先、换票失败再回退本地会话
（而不是像现在这样先判本地会话），改动点同样只在这一处。

## 代码改动

| 文件 | 改动 |
|---|---|
| `static/js/template-auth.js` | `bindLoginPage()`：SSO 分支与本地会话分支调换顺序，本地 `fetchCurrentUser()` 失败时清会话并回退换票；补注释说明优先级与已知后果 |

## 不涉及

- 后端 `app/routes/sso.py`、`app/services/sso_service.py`、`sso_service` 的校验/映射逻辑零改动；
  `tests/integration/test_sso_exchange.py`（12 例）不受影响。
- `SSO_ENABLED=false` 时换票端点不可用，第 2 步会失败并落回账号密码登录，行为不变。
- 其他登录相关口径（`authExemptPaths`、fragment 而非 query 传 token、退出登录清态）不变。

## 测试

前端该分支无自动化用例（登录页会话判定依赖真实 localStorage/fragment，仓库既有
测试也只覆盖后端换票端点）。手工验证清单：

1. 本地有有效会话 + 带过期 sso_token 进 `/login` → 直接跳 `next`，地址栏 fragment 已清。
2. 本地有有效会话 + 不带 sso_token → 直接跳 `next`（与旧行为一致）。
3. 无本地会话 + 带有效 sso_token → 换票成功跳 `next`（与旧行为一致）。
4. 无本地会话 + 带无效 sso_token → 页面显示换票错误，账号密码登录可用。
5. 本地会话彻底失效（清 refresh）+ 带有效 sso_token → 清态后换票成功。

后端回归：`.venv\Scripts\python.exe -m pytest tests/unit tests/integration` 中
`test_sso_exchange.py`、`test_auth_token_lifecycle.py` 全通过。
