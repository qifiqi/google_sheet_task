# 修改文档：Word 导出弹窗配置推广（单产品结果页 + 多品全局预览）

- 日期：2026-09-17
- 分支：dev_vue
- 范围：回测域 Word 报告导出（`/api/exports/backtest-reports/word`）的 RPT-M 透传与两个前端入口
- 性质：前端弹窗补齐 + 后端 RPT-M 合并透传，**不修改数据库 schema/迁移/数据**

## 背景

2026-09-16 的无风险利率改造只覆盖了绩效分析 V2 页（RPT-S 弹窗）。其余 Word 导出入口的差距：

| 入口 | 改造前状态 |
|---|---|
| 回测训练结果页（单产品） | 按钮直连下载，零配置（价格类型随任务、rf 恒 0） |
| 多产品全局预览页 | 有「导出 Word · 选择股票」弹窗，但只有选股/比例/组合指数开关，无价格类型、无 rf |
| 多产品结果页 | 直连下载，零配置（本次未动，用户未要求） |
| 回测训练全局预览页 | 无 Word 导出（本次未动） |

本次把 V2 弹窗的两项传入配置（价格类型 + 无风险利率）推广到前两个入口。

## 口径决策

1. **价格类型仅为报告展示行**（`metadata.price_type`），不参与任何计算—— Word 报告的收益序列来自任务本身的收益结果，价格类型无法也不应重算。两个新弹窗都提供「跟随任务（默认）」选项：不选具体类型时保留 payload 原值（多品任务的任务侧元数据是各产品价格类型的拼接，如「收盘价、开盘价」，单一选择不应默认覆盖它）。
2. **无风险利率双通道**（与 V2 一致）：`metadata.risk_free_rate = "X.XX%"`（报告元数据行展示）+ `runtime_params.risk_free_rate = 小数`（`MetricsRuntimeParamsDTO.from_raw` → V1 引擎夏普分子重算）。输入 0～100 百分比，非法值弹提示中止导出。
3. **RPT-S 不需要后端改动**：payload 即请求本身，双通道字段随请求直通（2026-09-16 已打通）。
4. **RPT-M 需要后端补透传**：`export_backtest_word` 此前按任务重建 payload 后只回填 `index_benchmarks` 和 `include_composite_benchmark`，请求携带的 `metadata`/`runtime_params` 被丢弃（重建载荷的 metadata 来自任务配置、runtime_params 缺省即 rf=0）。

## 代码改动

### 后端

| 文件 | 改动 |
|---|---|
| `app/services/export_service.py` | `export_backtest_word`：RPT-M 重建载荷后，`payload.metadata = {**payload.metadata, **report_request.metadata}`、`payload.runtime_params = {**payload.runtime_params, **report_request.runtime_params}`（请求值优先覆盖任务默认值；RPT-S 路径 payload 即请求，合并为恒等操作）。缓存键为整个 payload 的规范化 JSON 哈希，rf/价格类型变化自动产生新键，无需处理缓存 |

### 前端

| 文件 | 改动 |
|---|---|

### 数据流（多品导出一次的完整路径）

```
弹窗选股 + 输入 rf=3% → confirmExportWordBtn → exportWordDirectly
  payload.index_benchmarks = [{stock_code, ratio}]
  payload.metadata = {risk_free_rate: "3.00%"（, price_type: 选中时）}
  payload.runtime_params = {risk_free_rate: 0.03}
→ POST /api/exports/backtest-reports/word
→ export_backtest_word：build_multi_product_global_preview_word_payload 按任务重建
  → 合并请求 metadata/runtime_params（请求优先）+ index_benchmarks/include_composite 回填
→ generate_word → _build_benchmark_runs → _runtime_params(request.runtime_params)
  → calculate_v1_metrics(rf=0.03)；报告元数据行显示 3.00%
```

单品结果页路径：payload（RPT-S，task_id + return_series_id 来源）在前端直接合并双通道字段 → 同一端点直通（不重建）。

## 兼容性与影响面

- **默认行为完全不变**：两个弹窗默认值（跟随任务 + rf=0）下，合并后 payload 与历史 payload 逐字段一致；多品「未选具体价格类型」时任务侧拼接文案保留。
- **RPT-M 重建路径的老调用**（多品结果页 `word_report_payload` 直传、脚本调用）：不传 metadata/runtime_params 即 `{}`，合并后不变。
- **不涉及**：数据库、C 系任务执行链路、看门狗、token 占用、V2 页（未改动）。
